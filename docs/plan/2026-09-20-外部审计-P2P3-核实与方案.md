## 3. P2「数据没跟盘走」—— 核实结果与三个选项（**要你拍板，我故意没动代码**）

### 3.1 先看交付包自己怎么说的（原文）

`Partner-WU盘交付-0.0.24\使用说明.txt`：

- 第 11 行：**"数据跟盘走：在 U 盘上运行时，工作区自动落在 U 盘根目录的「Partner-W工作区」文件夹"**
  ⇒ 承诺的是**工作区**（这条是好的：`packages/desktop/src/main/workspace/portable.ts` + 换盘符自愈都在）。
- 第 63 行：**"跟账号绑定，不跟 U 盘绑定 —— 换一台机器需要重新登录（不需要重新激活）"**
  ⇒ **凭据/登录态本来就不打算跟盘走**，而且是文档里明说的。

`①双击这里启动.bat`（0.0.24）里的注释：

- "便携版和「装到电脑」版**共用同一个程序目录**，Windows 只允许跑一份"——启动器靠 `tasklist` 检测，
  说明**两份共用同一个 appId ⇒ 共用同一个 `%APPDATA%\@clawwork\desktop`**，也共用单实例锁。
  使用说明第 18–19 行同样写了"两份会抢同一个实例"。

### 3.2 审计说的 ~180MB 是什么

- 本机实测 `%APPDATA%\@clawwork\desktop`（**开发机**，含开发期产物）：`runtime` **587MB**、
  `runtime-cache` 326MB、`logs` **297MB**、`Code Cache` 250MB、`Cache` 118MB、
  `openclaw-state` 73MB、`skills-remote` 57MB。
- 其中"换一台机器都要重来一遍"的是**运行时**：部署目标写死在 userData 下
  （`packages/desktop/src/main/runtime/deploy.ts:96-113` → `userData/runtime/deployed/<key>`），
  调用方 `packages/desktop/src/main/index.ts:337`。使用说明第 7 行自己写着首启"约 2–3 分钟"。
- 所以审计看到的残留 = **便携版与"装到电脑"版共用 appId** 造成的那一份，加上 Chromium 缓存与日志。

### 3.3 三个选项

| 选项                                     | 做法                                                                                                    | 代价 / 风险                                                                                                                                                                                                                                     | 收益                                                            |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| **A（建议）维持现状，只把"日志"跟盘走**  | `initDebugLogger` 在盘上运行时指向 `<盘根>\…\logs`（新日志上盘、旧日志留宿主、**零迁移**）              | 很小：日志是持续写入（50MiB 轮转），U 盘慢/写坏要兜底                                                                                                                                                                                           | 拔盘后宿主少 297MB 级残留；日志跟着人走，换机器能查上一台的故障 |
| **B 便携运行时把整个 userData 指到盘上** | 在盘上运行时 `setPath('userData', <盘根>\…)`（Chromium 缓存一并过去）                                   | ①启动器/说明文档赖以"两份抢一个实例"的机制**失效**（两份能同时跑，可能抢 18789 端口）；②首启往 U 盘写 ~600MB 运行时；③只读盘/拔出盘要有 fail-soft；④迁移难：`openclaw-state` 里含 Windows junction（我们为此删过 `openclaw.mjs`），**不能盲拷** | 真正做到"拔盘不留痕"                                            |
| **C 只把凭据/配置挪到盘上**              | 只挪 `clawwork-config.json` / `device-identity.json` / `device-tokens.json` / `commercial-session.json` | 收益≈0：这三份现在是 **DPAPI（按 Windows 账户）加密**的，挪到盘上换机器也解不开 —— 与文档第 63 行"换机重新登录"一致                                                                                                                             | 让"文件在盘上"看着更整齐                                        |

**我为什么没直接做 B**：这三条都是**产品行为决策**（会不会让两份同时跑、要不要往用户盘里写 600MB、
拔出盘怎么办），而且我**没法打包验证**（本次边界：不打包、不发版）。照纪律不交付"没验证过的行为变更"。

## 7. 顺带查出来的：**同一目录下还有两处明文凭据**（审计没点名）

修 P3 时顺手把 `%APPDATA%\@clawwork\desktop` 整个扫了一遍"字符串里像不像凭据"，除审计列的那几份外还有两处：

| 文件                              | 字段                                                                                         | 实测                                           | 谁写的                                                                                                                                                                                                                                        |
| --------------------------------- | -------------------------------------------------------------------------------------------- | ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `runtime\local-gateway-auth.json` | `token`（43 字符，**不是** `enc:`）                                                          | 本机实测 `keys: formatVersion,token,createdAt` | **我们的代码**：`packages/desktop/src/main/runtime/token-store.ts:76-118`（`writeJsonAtomic` 原样写 token）                                                                                                                                   |
| `openclaw-state\openclaw.json`    | `gateway.auth.token`（43 字符，明文）+ `models.providers.clawrouter.apiKey`（52 字符，明文） | 本机实测（只列字段名与长度，没打印值）         | token 是我们写的（`packages/desktop/src/main/runtime/state-config.ts:83` `minimalGatewayConfig()` + 镜像逻辑）；apiKey 是**网关自己**持久化的（我们只通过 `config.patch` 交给它，`packages/desktop/src/main/commercial/relay-config.ts:102`） |

**为什么这次没顺手改**（两个都写了理由，不是懒）：

1. `local-gateway-auth.json` **改法上可加密**（跟我们刚做的 `secure-field` 同一套），但它有**危险的失败模式**：
   解密失败时若按"当成没有"处理，`ensureLocalGatewayToken` 会**生成一个新 token**，而按 `token-store.ts:12-14`
   的注释，新 token 去认证**还在用旧 token 跑的网关** ⇒ 认证失败 ⇒ 被**误判成 foreign**。
   这条链要连真机一起验（含"换机器后 token 读不出来"的场景），不适合在本次边界（不打包）里动。
2. `openclaw.json` **改不了**：它是**网关的 bootstrap 输入**，网关按明文读；加密它等于让网关起不来
   （要给运行时加"从环境变量读 token"的能力才行 —— 那是运行时契约的改动）。

⇒ 结论：P3 本次修的是**审计点名的两处**（设备私钥、设备令牌）；剩下这两处**仍在明文**，
需要真机验证 + 运行时能力评估，已单列成待办。

### 9.1 为什么"去掉 .bat"必须与构建绑死

`.bat` 唯一在做的事是解释"**已经有一份在跑**"（`tasklist` 查一遍再 echo 一段人话）——
因为老构建抢不到单实例锁时是**裸 `app.quit()`**，用户看到的就是"双击了没反应"。
新构建里这活由 `instance-guard.ts` 的对话框干；**老构建没有它**。

⇒ "这份构建带不带自解释行为"是可以在 asar 里查的：找指纹 `Partner-W已经在运行`
（`bufferHasString`，**原文与 `\uXXXX` 两种形态都试**，因为打包器换 charset 就会变形态）。
实测（正/负对照都跑过）：0.0.24 交付包的 asar（98.0MB）里 `Partner-W` / `工作区` / `本地网关`
**都命中**（说明中文在里面是原文，搜索有效），而 `Partner-W已经在运行` / `本机端口被占用` **0 命中**
⇒ 工具对 0.0.24 的结论正是 **"stale-build：这一版不许去掉 .bat"**。

**口径订正（09-20 晚，见 §10.1）**：这条从 `error` 降成了 **`warn`** —— 判成 error 会把
"给现役版本打压缩包分发"这条正常需求一起堵死，而它要说的只有"**别去掉 .bat**"这一句。
真交付夹现在的体检结论是 **0 error / 3 warn / `exit=0`**（只读、目录 md5 前后一致）。

### 9.2 下一版交付包怎么装（0.0.25 打包后照做）

1. `node scripts/udisk-delivery.mjs "<交付包目录>"` → **0 个 error 才算过**。
   `--fix` 会把该搬走的（那个 `.bat`）搬到交付包**外面**的 `_U盘交付-已移除-<时间戳>\`（**只搬不删**）。

   （同一包裹里放安装包，会让一部分用户装到电脑上，此后 U 盘这份总在"端口被占用"）。
3. 改 `使用说明.txt` 三处（机检会替你盯着，`readme-stale` 会逐条列出来）：
   - 入口改成 **双击 `Partner-W\Partner-W.exe`**（删掉"双击 ①双击这里启动.bat"那一步）；
   - 加一句**数据在盘上**：`<盘根>\Partner-W-运行数据\`（登录态、日志、运行环境、缓存都在里面）；

     —— 新构建里两份**能同时开**，后开的那份会弹框说明；`openclaw-state` 那套 junction 的说法不变。
4. ⚠️ **不要**把 `Partner-W\resources\runtime\openclaw-runtime-manifest.json` 拷到盘根
   （我在第一轮方案里写过这一条，**是错的**，别照做）。原因：`locate.ts` 的 `drive` 候选（盘根）
   优先级**在 `bundled`（`<resources>/runtime`）之前**，而且只看"盘根有没有那个 marker"——
   盘根放了 marker、运行时却还在 `resources\runtime`，部署源就会被判成 `E:\`，
   它会去找 `E:\openclaw-runtime\...` **而那里什么都没有** ⇒ 反而把好好的包弄坏。
5. 便携那份**不自动更新**（程序只提示）：发新版本 = 整目录替换 `Partner-W\`，
   **不要动** `Partner-W-运行数据\` 与 `Partner-W工作区\`。

### 9.3 第二轮带来的新风险（都还没真机验，写下来比藏起来强）

1. **换盘符 / 换机器后插件可能加载失败**：`openclaw-state` 里有一批 junction 记的是**绝对路径**
   （`…\runtime\deployed\<key>\node_modules\openclaw`），而 openclaw **只在插件安装/更新时**修复它们
   （`plugin-peer-link-*.mjs` 的两个调用点），**不会每次启动修**。⇒ 插到别的口变成另一个盘符之后，
   某个插件/技能可能报加载失败。**本轮没做自动修复**（要真机 + 真 U 盘才能验）。
   兜底：把盘符改回原来的字母，或在插件页对它重装一次。
2. **一台机器同时只有一份能用**：本地网关端口固定 18789（`packages/shared/src/constants.ts`）。
   两份并存时后开的那份会弹「本机端口被占用」——这不是 bug，是这份设计要付的代价（比"静默没用"好）。
3. **DriveType≠2 的盘（USB 固态/移动硬盘常报 `DriveType=3`，即"本地固定盘"）或枚举失败**：认盘三条判据
   （盘根 runtime marker / 我们自己的工作区标记 / `DriveType=2`）**都不命中** ⇒ 首启可能仍把数据
   写在 `%APPDATA%\@clawwork\desktop`。而且**不会自愈**：工作区标记只在"工作区确实落在盘上"时才存在。
   ⇒ 这是本轮**已知没解决**的一条（本机没有这种盘可插，`DriveType=3` 的语义是 Windows 的，
   这里**没实测**）。诊断方法见 9.4 第 2 条。
4. **首启慢**：盘上第一次要部署运行环境（0.0.20 实测首次部署 ~160s、网关 ~180s 量级）。
   之后**换机器不用重新部署**（`computeDeploymentKey` 只由 运行时版本/平台/arch/schema/归档 sha/node sha
   决定，与机器无关）—— 但这条**没有第二台机器验过**，只有代码依据。

### 9.4 打包后真机验收（U 盘上跑一遍，6 步）

1. 首启后盘上应出现 `<盘根>\Partner-W-运行数据\`（含 `logs\`、`runtime\deployed\…`）；
   本机 `%APPDATA%\@clawwork\desktop` 应**不再长新文件**（老机器上这个目录本来就有，看 mtime）。
2. 查日志 `…\Partner-W-运行数据\logs\debug-<date>.ndjson` 里的 `app.userData.portable` 一行：
   应带 `target` 与 `reason`（`removable-drive` / `volume-marker` / `workspace-marker`）；
   若是 `app.userData.portable_failed` 就看它的原因（只读盘/没权限/盘满会走这条退路）。
3. 再双击同一个 exe：应弹「**Partner-W已经在运行**」+ 那一份的路径 + 托盘出口（**不再是"没反应"**）。
4. 同时开两份（U 盘那份 + 装到电脑那份）：后开的那份应弹「**本机端口被占用**」（带 18789 与出口）。
5. 托盘退出 → 拔盘 → 本机那份照样能用（两份互不干扰）。
6. 换一台电脑插同一个 U 盘、**盘符相同**：应直接进登录界面（不重新部署、不用重装）——这条是本产品的核心承诺。

## 10. 第三轮：压缩包分发（"分为好多 U 盘，解压"）

（我读了它的中央目录：顶层 4 项 = `Partner-W\` + `使用说明.txt` + `①双击这里启动.bat` +

这一轮补的不是"能不能压"，而是"**下一个人照着做也不会做错**"——因为手工右键压缩最容易压错的
那个东西恰恰最要命：**跑过一次的交付夹**。

### 10.1 为什么必须让工具压（三条闸门）

1. **不许压"跑过"的夹子**：盘上第一次运行会在 `Partner-W-运行数据\` 里生成
   `device-identity.json`（设备私钥）、`device-tokens.json`（operator token）、
   `local-gateway-auth.json`（本机网关 token）、`clawwork-config.json`（中转 token），
   以及含对话的日志。**打包它 = 把同一份凭据发给每一个客户**。
   ⇒ `findSensitiveEntries` 扫这些名字（任意层级），命中就**拒绝打包**并列出命中的路径。
   实测**纯净交付夹 0 命中**（0.0.24，244 条一个没碰到）⇒ 这条不误伤正常包。
2. **不许绕过体检**：包本身有 error（缺随包运行时 / 新构建还留着 `.bat` / 既没 `.bat`
   又不自解释）⇒ 拒绝打包。压缩不能变成"把机检不认的包发出去"的旁路。
3. **封完自己解开对账**：条目集合 + 每个文件的大小都要与源夹一致；不一致就把包改名成
   `.未通过对账-别发`（**只改名不删**）。"创建成功"不等于"客户解得出东西"。

⚠️ 顺带订正一处口径：`stale-build` 这一轮从 `error` 降成 **`warn`**（§9.1 已标注）——
现役 0.0.24（客户手里那版）照样要能压包分发，它要说的只有"**别去掉 .bat**"。

（`7z -x -f …` ⇒ `Too short switch: -x`）；原来测试里还有一模一样的死分支。⇒ 工具名到
命令行的映射收进 `extractArgv` 一份实现，并补了 CLI 端到端测试（真压+真解+真对账）。

### 10.3 铺多个 U 盘（自己复制时）

1. **解压在 U 盘根目录**（`E:\`）：得到 `E:\Partner-W\` + `E:\使用说明.txt`，与老交付包同一形态。
   （解到子目录里也能跑 —— 认盘看的是**卷根**的 marker —— 但说明与话术统一按根目录。）
2. **告诉客户用 7-Zip 解压**（`右键 → 7-Zip → 解压到当前文件夹`）：中文名在包里是 UTF-8，
   Windows 自带解压对老系统会显示成乱码。工具结尾提示里就写了这句。
3. **自己铺盘**：资源管理器整目录复制，或
   `robocopy "E:\" "F:\" /E /XJ /MT:32`（`E:`=已铺好的母盘、`F:`=目标盘）。
   ⚠️ `/XJ` **别省** —— `openclaw-state` 里有 4 个 junction 记的是**绝对路径**
   （`C:\…`），复制过去只会指向错的机器。
4. ⚠️ **别把 `Partner-W-运行数据\` 一起复制**（那是"这台机器跑过"的数据：凭据 + 日志）。
   要"预热"就让每块盘自己跑一次首启（0.0.20 实测首次部署 ~160s 量级），**不要拷数据目录**。
5. **换版本**：便携那份**不自动更新**（程序只提示）⇒ 发新版 = 整目录替换 `Partner-W\`，
   **不要动** `Partner-W-运行数据\` 与 `Partner-W工作区\`。
