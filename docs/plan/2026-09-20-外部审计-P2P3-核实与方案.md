## 3. P2「数据没跟盘走」—— 核实结果与三个选项（**要你拍板，我故意没动代码**）

### 3.1 先看交付包自己怎么说的（原文）

`荣盈魔方U盘交付-0.0.24\使用说明.txt`：

- 第 11 行：**"数据跟盘走：在 U 盘上运行时，工作区自动落在 U 盘根目录的「荣盈魔方工作区」文件夹"**
  ⇒ 承诺的是**工作区**（这条是好的：`packages/desktop/src/main/workspace/portable.ts` + 换盘符自愈都在）。
- 第 63 行：**"跟账号绑定，不跟 U 盘绑定 —— 换一台机器需要重新登录（不需要重新激活）"**
  ⇒ **凭据/登录态本来就不打算跟盘走**，而且是文档里明说的。

`①双击这里启动.bat`（0.0.24）里的注释：

- "便携版和「装到电脑」版**共用同一个程序目录**，Windows 只允许跑一份"——启动器靠 `tasklist` 检测，
  说明**两份共用同一个 appId ⇒ 共用同一个 `%APPDATA%\@clawwork\desktop`**，也共用单实例锁。
  使用说明第 18–19 行同样写了"两份会抢同一个实例"。

### 3.2 审计说的 ~180MB 是什么

- 本机实测 `%APPDATA%\@clawwork\desktop`（**开发机**，含开发期产物）：`runtime` **587MB**、
  `runtime-cache` 326MB、`logs` **297MB**、`Code Cache` 250MB、`Cache` 118MB、
  `openclaw-state` 73MB、`skills-remote` 57MB。
- 其中"换一台机器都要重来一遍"的是**运行时**：部署目标写死在 userData 下
  （`packages/desktop/src/main/runtime/deploy.ts:96-113` → `userData/runtime/deployed/<key>`），
  调用方 `packages/desktop/src/main/index.ts:337`。使用说明第 7 行自己写着首启"约 2–3 分钟"。
- 所以审计看到的残留 = **便携版与"装到电脑"版共用 appId** 造成的那一份，加上 Chromium 缓存与日志。

### 3.3 三个选项

| 选项                                     | 做法                                                                                                    | 代价 / 风险                                                                                                                                                                                                                                     | 收益                                                            |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| **A（建议）维持现状，只把"日志"跟盘走**  | `initDebugLogger` 在盘上运行时指向 `<盘根>\…\logs`（新日志上盘、旧日志留宿主、**零迁移**）              | 很小：日志是持续写入（50MiB 轮转），U 盘慢/写坏要兜底                                                                                                                                                                                           | 拔盘后宿主少 297MB 级残留；日志跟着人走，换机器能查上一台的故障 |
| **B 便携运行时把整个 userData 指到盘上** | 在盘上运行时 `setPath('userData', <盘根>\…)`（Chromium 缓存一并过去）                                   | ①启动器/说明文档赖以"两份抢一个实例"的机制**失效**（两份能同时跑，可能抢 18789 端口）；②首启往 U 盘写 ~600MB 运行时；③只读盘/拔出盘要有 fail-soft；④迁移难：`openclaw-state` 里含 Windows junction（我们为此删过 `openclaw.mjs`），**不能盲拷** | 真正做到"拔盘不留痕"                                            |
| **C 只把凭据/配置挪到盘上**              | 只挪 `clawwork-config.json` / `device-identity.json` / `device-tokens.json` / `commercial-session.json` | 收益≈0：这三份现在是 **DPAPI（按 Windows 账户）加密**的，挪到盘上换机器也解不开 —— 与文档第 63 行"换机重新登录"一致                                                                                                                             | 让"文件在盘上"看着更整齐                                        |

**我为什么没直接做 B**：这三条都是**产品行为决策**（会不会让两份同时跑、要不要往用户盘里写 600MB、
拔出盘怎么办），而且我**没法打包验证**（本次边界：不打包、不发版）。照纪律不交付"没验证过的行为变更"。
你回一句"上 A / 上 B / 都不动"，我下一轮照做（A 大约 1 刀就能落地，B 要先解决 §3.3 的 ①②③④）。

## 4. 来源没找到的两份文件（建议这样排查）

- `jwt-secret.txt`：64 hex 字符；`backend-session.json`：**1,136 字节、单行、非法 JSON**，
  内容是 base64 且**解码后以 `v10` 开头**（`djEw…`）—— `v10` 是 Chromium/OSCrypt 的版本前缀，
  即**某个 Electron 程序用 `safeStorage` 加的密**（而且没加 `enc:` 前缀）。
- 两者 `mtime` 分别是 2026-09-04T14:36Z / 2026-09-07T06:29Z（本机）。
- 代码侧已彻底否证（§1 Q2）。⇒ 最可能是**更早的版本**或**机器上装过的同类程序**写的；
  也可能是"装到电脑"那份留下的（同一 appId）。**需要你确认**：那台机器上是不是装过/跑过旧版或安装版？
- 处置建议：确认来源前**不要删**（`backend-session.json` 若是某处的会话凭据，删了要重新登录），
  但要**当成一次凭据泄露事件**对待：那台机器上换过密码/退出登录一次即可。

1. **明文兜底**：`secure-field.ts:29` —— `safeStorage.isEncryptionAvailable()` 为假时**原样写明文**（老系统/受限环境）。

4. `jwt-secret.txt` / `backend-session.json` 来源未明（§4）。

## 7. 顺带查出来的：**同一目录下还有两处明文凭据**（审计没点名）

修 P3 时顺手把 `%APPDATA%\@clawwork\desktop` 整个扫了一遍"字符串里像不像凭据"，除审计列的那几份外还有两处：

| 文件                              | 字段                                                                                         | 实测                                           | 谁写的                                                                                                                                                                                                                                        |
| --------------------------------- | -------------------------------------------------------------------------------------------- | ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `runtime\local-gateway-auth.json` | `token`（43 字符，**不是** `enc:`）                                                          | 本机实测 `keys: formatVersion,token,createdAt` | **我们的代码**：`packages/desktop/src/main/runtime/token-store.ts:76-118`（`writeJsonAtomic` 原样写 token）                                                                                                                                   |
| `openclaw-state\openclaw.json`    | `gateway.auth.token`（43 字符，明文）+ `models.providers.clawrouter.apiKey`（52 字符，明文） | 本机实测（只列字段名与长度，没打印值）         | token 是我们写的（`packages/desktop/src/main/runtime/state-config.ts:83` `minimalGatewayConfig()` + 镜像逻辑）；apiKey 是**网关自己**持久化的（我们只通过 `config.patch` 交给它，`packages/desktop/src/main/commercial/relay-config.ts:102`） |

**为什么这次没顺手改**（两个都写了理由，不是懒）：

1. `local-gateway-auth.json` **改法上可加密**（跟我们刚做的 `secure-field` 同一套），但它有**危险的失败模式**：
   解密失败时若按"当成没有"处理，`ensureLocalGatewayToken` 会**生成一个新 token**，而按 `token-store.ts:12-14`
   的注释，新 token 去认证**还在用旧 token 跑的网关** ⇒ 认证失败 ⇒ 被**误判成 foreign**。
   这条链要连真机一起验（含"换机器后 token 读不出来"的场景），不适合在本次边界（不打包）里动。
2. `openclaw.json` **改不了**：它是**网关的 bootstrap 输入**，网关按明文读；加密它等于让网关起不来
   （要给运行时加"从环境变量读 token"的能力才行 —— 那是运行时契约的改动）。

⇒ 结论：P3 本次修的是**审计点名的两处**（设备私钥、设备令牌）；剩下这两处**仍在明文**，
需要真机验证 + 运行时能力评估，已单列成待办。
