## A. 网关子进程 stdout/stderr **没人消费**（复核 ③ 剩余；Codex 标"高优先"）

### 现象与证据

- `packages/desktop/src/main/runtime/gateway-process.ts:360`：
  `nodeSpawn(nodeExe, args, { …, stdio: ['ignore', 'pipe', 'pipe'], … })` —— 两条管道**开着**；
- `toGatewayChild()`（同文件 `:338-357`）**只挂 `exit`**，从不 `read()` ⇒ stdout/stderr 无人排空；
- ⇒ 三条后果：①**诊断黑洞**（"网关卡在哪一步"只能猜，生产上也收不到网关日志）；
  ②**理论上的管道写满**（子进程堵在 `write` ⇒ 看起来就是"网关卡死"，与 T-a8 的观察项同形）；
  ③ P0-6 要的"双击 → ready"时间线**缺网关侧那一半**。

### 设计（三层，最小可用；**不新造脱敏/限流轮子**）

1. **消费**：`realSpawn` 接上 drain（`setEncoding('utf8')` + 按行切）。
   `GatewaySpawnFn` 的**必填形状不动**，只加**可选** `onOutput`（既有测试桩不受影响）。
2. **有界 + 脱敏**（新模块 `src/main/runtime/gateway-output.ts`，纯函数为主，好测）：
   - 单行上限（默认 2 KiB）：网关会打整包 JSON，一行几十 KB；
   - 环形尾部缓冲（默认 16 KiB）：内存里留一份，供将来诊断导出；
   - **行级脱敏**：`sanitizeForLog` **只按 key 名**摘（`SECRET_KEY_RE`），而 stdout 是**自由文本**
     ⇒ 必须另按**值**抹：①我们**已知的** token（`ensureGatewayRunning` 手上就有）②`Bearer <x>` /
     `authorization: <x>` ③URL 里的 `user:pass@`。**只抹已知值与固定模式**，不做"长串一律抹"（会毁掉诊断价值）。
3. **落日志 + 不刷屏**：按行写 debug ndjson（`domain:'gateway'`, `event:'gateway.stdio'`，
   带 `stream`/`seq`/`repeat`），并**折叠 + 限速**：同一行连续重复折叠成 `repeat: n`；
   每秒最多 M 行（默认 20），超出**不丢** —— 计成 `dropped`，在下一次可写时补一条
   `gateway.stdio.dropped` 摘要行。⚠️ 日志文件有 50 MB/天的上限（`logger.ts:75`），
   无限速会把当天的诊断证据顶掉。

### A2. `deps.log` 是个**空函数**（同一条线的另一半）

- `src/main/runtime/index.ts:250-252`：`log: () => { /* 默认不落日志；接线时注入 getDebugLogger */ }`；
- 而 `src/main/index.ts:421` 调 `bootstrapLocalGatewayRuntime({ userDataDir })` **没注入** ⇒
  `runtime.deploy.done` / `runtime.links.repaired` / `runtime.links.failed` / `runtime.bootstrap.ok`
  这些事件**在真机日志里一条都不落**（只有失败路径由调用方补了一行 `runtime.bootstrap.failed`）。
- 设计：主进程注入 `log: (event, data) => getDebugLogger().info({ domain: 'gateway', event, data })`
  （域用 `gateway`，与既有的 `runtime.bootstrap.failed` 同一处）；
  **顺带给 `runtime.bootstrap.ok` 加阶段耗时**（现只有 `deploymentKey`/`ownership`/`nodeVersion`）：
  `elapsedMs` + `alignMs` / `deployMs` / `selfCheckMs` / `nodeMs` / `gatewayMs`，
  这样"50 秒到底花在哪"不用再猜（正是 P0-2 / 复核 ③ 要的东西）。

### 测试与变异

- 纯函数（切行 / 环形上限 / 折叠 / 限速 / 脱敏）各一条主用例 + 边界（超长行、无换行结尾、CRLF、二进制垃圾）；
- 集成：假 child（`Readable`）→ 断言 sink 收到的行序/形状；
- 变异：①删 drain（应红：管道无人消费）②去掉单行截断（应红）③去掉折叠（应红）
  ④**去掉值脱敏**（应红 —— 这条最重要）⑤限速阈值改大（应红）。
- SELF-A：把默认阈值从 2 KiB 改 2 MiB（等价，必须存活）；SELF-B：把锚点写成不存在的行（必须报"脚本错"）。

### 风险

- 网关输出**可能含 token / 用户原话**（如果它把参数打出来）⇒ 值脱敏 + 键脱敏**两道都要**；
- 多写日志 ⇒ 磁盘占用（已有限速 + 每天 50 MB 上限 + 默认保留 14 天）；
- 别把 drain 做成"等子进程结束才读"（那正是现在的问题）。

### 切片

- **A1** 纯函数模块 + 单测（TDD）→ **A2** `realSpawn`/`toGatewayChild` 接线 + 假 child 集成测
  → **A3** 主进程注入 `deps.log` + 阶段耗时 + 断言（**三刀各自独立提交**）。
- 暂不做：把尾部缓冲接到界面/诊断工具（先有数据，再决定给谁看）。

## 明确**不做**（写明原因，别当漏了）

- **T-a8 / T-a22 网关"卡死"根因**：Codex 明说"没有复发证据不建议重构网关"—— 复发时按
  `T-a8` 的取证清单留证据再说（探针 `pnpm gateway:probe` 已升级，见 T-a31）。
- **断线横幅的**现场**归因**：仓库与 0.0.24 asar 里根本没有界面上那个 `Local Gateway` 字样
  ⇒ 现场设备日志仍是决定性缺口。
- **同类缝普查**（`login-otp-*` 之外那些"IPC 错误码 → 界面文案"）：Q6 拍板"内测前不做"。
- **`runtime\local-gateway-auth.json` 的 token 加密**：有危险失败模式（解密失败 ⇒ 生成新 token ⇒
  把活着的网关判成 foreign）⇒ 要拍板，不能自己上。
- **`openclaw.json` 里的明文 token/apiKey**：网关按明文读 ⇒ 要运行时支持环境变量，属上游。
