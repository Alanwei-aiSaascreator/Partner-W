      ### 证据（三条都是实测）

      1. `git ls-files --eol`：文本文件 **索引里全是 `i/lf`**，工作区 621 个是 `w/crlf`。
      2. 直接把 blob 抠出来数 CR：`git cat-file blob HEAD:website/tsconfig.json`
         → **CR 0 个、LF 16 个** ⇒ **仓库存的就是纯 LF**。
      3. `git check-attr text eol` → `unspecified` ⇒ **没有 `.gitattributes`**。

      ⇒ 成因链：`core.autocrlf=true`（**本机 git 配置**）在 checkout 时把 LF 转成 CRLF，
      而 `.prettierrc` 写着 `endOfLine: "lf"` ⇒ 两者打架，输的是工作区。
      ⇒ **仓库内容、CI 都没问题**：`.github/workflows/pr-check.yml` 跑在 **ubuntu-latest** 上，
      Linux 上 checkout 出来就是 LF ⇒ **`pnpm format:check` 在 CI 里是绿的**。

      ### 为什么我**没有**动（这是刻意的）

      - 它不是缺陷 ⇒ 没有紧迫性。
      - 根治办法是加 `.gitattributes`（`* text=auto eol=lf`，索引已是 LF ⇒ **零内容改动**）。
        但它**改的是每个人 checkout 的行为**，加完那 621 个 CRLF 文件会先显示成"已修改"，
        直到重新 checkout —— 正是队列警告的"整仓 diff 炸开"那种扰动。
      - `.gitignore` 这类仓库级配置文件你明确留给自己 ⇒ `.gitattributes` 同族，**等你拍板**。
      - 本地跑 `prettier --write .` 只能治一次：下次 checkout 又变回来 ⇒ 是白工，不做。

      ### 你回来后可以二选一

      ```bash
      # A. 只治你这一台（不影响别人）
      git config core.autocrlf false && prettier --write .
      # B. 根治（全团队，零内容改动，但有一次性扰动）
      echo '* text=auto eol=lf' > .gitattributes && prettier --write .
      ```

### 🔴🔴 最值得排期的一条：向量**救不了**关键词没召回的查询

这一条比上面两条重得多，单独列出来。

召回那一步是**纯 FTS5 关键词**（`searchKbChunks` 里只有 `WHERE kb_chunks_fts MATCH ?`），
向量**只在重排时进场**（`rankKbCandidates` 只能给 FTS 已经召回的候选重排）。
⇒ **FTS 没召回的，向量永远没机会看到。**

而 `unicode61` 不切中文词（`收入主要来自软件订阅` 是一整个 token），所以：

    正文里明明有"软件订阅"，查 `订阅` ⇒ 0 命中
    —— 即使本机 bge-small-zh 嵌得好好的、向量一个不缺

也就是说 **bge-small-zh-v1.5 这个"中文语义模型"目前几乎发挥不了作用**：它的价值本该是
"用户换个说法也能搜到"，而恰恰是这类查询（零字面重叠）被 FTS 挡在门外，向量够不着。
`kb-store.test.ts:265` 早就记了 FTS 层这条"已知边界"，但**没记它的后果**；
`6c1cc65` 只是把"界面不再撒谎"修了，**召回本身没动**。

修法要**设计**（不是顺手改）：得让向量自己也能**召回**，而不只是重排。大致三条路，
都得先想清楚再动：

1. 全量扫向量算相似度（切片上万就慢，但库在本地、可以配个上限/近似）；
2. FTS 召回不足时**回退**到向量全扫（"混合"变成真的两路召回 + 融合，如 RRF）；
3. 先给 FTS 喂一份"中文字间插空格"的文本（改 tokenizer 或加冗余列）——
   只解决中文分词，**不解决同义词**（同义词恰恰是向量的活）。
   ⚠️ 这会动 `kb-schema.ts` 的 FTS 表与 `T6c` 的召回率口径，属于**设计变更**，等用户拍板。
   验收建议：正文含"软件订阅"、查"订阅"能命中；查"盈利来源"（无字面重叠）也能命中。
