## 铁律（自主执行期间）

1. **不碰生产**：relay / supabase 迁移 / 更新源 / 任何服务器操作，一律不做。
2. **不打交付包、不发版**。
3. **不改 `.gitignore`**（长期纪律）。
4. **不做破坏性 git 操作**：不 rebase 别人的分支、不 force push、不 reset --hard。
5. **每刀独立提交**，随时可单独回滚；提交信息写清"为什么"与**怎么回滚**。
6. **TDD + 变异验证**：先红后绿；写完实现才跑的测试必须补变异验证。
   变异判据照旧：按**测试名**判红、必须 `passed > 0`、锚点单行且命中恰好 1 次、
   带一条自检变异证明判据分得开、脚本自己错了要当"脚本错"报出来而不是"存活"。
7. **每刀都要过门禁**：typecheck / typecheck:tests / lint / check:i18n /
   check:ui-contract / check:renderer-copy / check:architecture。
8. **发现真 bug 优先修**，但要与当前这刀分开提交或写清缘由。
9. **诚实记失败**：偶发、跳过的验证、没查的根因，都要写进提交信息与记忆。
10. **可测宣称三件事**：凡「N 项 / 只剩 X 条」这类话，当场写清 ①出处 ②测量日期 ③可重跑的命令。
    （2026-09-19 的教训：过期的数字比没有更坏 —— 它读起来像事实，还会把对的那个否掉。）

### T-a1 干掉 memory 报错（`tools.deny`）

- [ ] **为什么**：模型每次对话都可能调 `memory_search`，而在我们配置下**必然失败**
      （`Session transcript search is not enabled.`）。用户原话：「我不希望每次对话就有这个报错，
      用户会认为卡了」。
- [ ] **怎么做**：客户端生成 `openclaw.json` 时带上
      `tools: { deny: ["memory_search", "memory_get"] }`。- ⚠️ **两个一起**：只 deny search 的话，记忆提示段会换成 `memory_get` 版本，
      "强制回忆"的提示还在。- ⚠️ **不要**用 `memory.search.enabled: false`：那会**静默关掉 "## Project Memory" 注入**。- 依据：`dist/memory-search-BRDEDDT4.mjs:46-55`（`provider:"none"` 不产生 null，
      真正的门是 `enabled` 默认 true）、`dist/index.d.ts:1868-1874` + `5452`（`tools.deny` 的形状）。
- [ ] 先找**客户端在哪写这份配置**（不是我猜的 config.patch，那是改已有配置的通道；
      初次生成走的是另一处）。
- [ ] TDD：生成配置的纯函数加断言 + 变异验证。
- [ ] **实机验证**：改完重启网关，开一轮对话确认**不再出现那个失败卡片**。
- [ ] 回滚：删掉那一行即可（配置是生成的，不需要迁移）。
