##### ✅ 机制（读随包运行时 + 沙箱实测，2026-09-20）

两层缓存，都挂在**同一个版本号**上：`skillEntryCache`（`skills.status` 那条磁盘读缓存，
键里含 `getSkillsSnapshotVersion(workspaceDir)`）与 `skillSnapshotCache`（每会话的技能快照）。
`bumpSkillsSnapshotVersion` 的调用点**全扫过一遍**：

- **fs watcher**（`refresh-C1N_6Xgp.mjs:331`）—— 只在**构建过一次 session snapshot** 时才装
  （`session-snapshot-DsNGsPvO.mjs:37`），chokidar 带 `ignoreInitial: true`，且**首次安装不 bump**
  （`refresh-C1N_6Xgp.mjs:462` 要求 `previousTargets.length > 0`）
  ⇒ **装 watcher 之前发生的增删，它永远看不见**。
  ⚠️ 但它的 watch 根**确实包含** managed 目录（`refresh-C1N_6Xgp.mjs:82` 起的
  `path.join(CONFIG_DIR, "skills")`）⇒ **跑过 agent 之后**的装/卸本来就会自己生效 ——
  这条解释了为什么这个 bug 只在"刚起还没跑过 agent / watcher 被闲置回收"时露头。
- 远端节点、技能工坊 —— 与本场景无关。
- **配置变更**（`server-reload-managed-BZLndg46.mjs:508`）：changedPaths 里有 `skills` 或
  `skills.*` ⇒ **全局** bump（reason `config-change`）。**唯一能从 RPC 够到的一条**。
  ⚠️ 且**值必须真的变**：`changedPaths.length === 0` 会提前 return（实测确认）。

### T-a9 ✅ 发消息后助手头像"闪一下" —— 等待态与流式态必须是**同一个节点**（提交 `b076efaa`）

**前提实测（悬空链接到底"隐形"到什么程度）**：临时目录里造一个指向**不存在**路径的 junction，

### T-a1 `tools.deny` —— 摘掉必然失败的两个 memory 工具

**洞察**：客户端**已经修过一次**这个坑（`MEMORY_SEARCH_PROVIDER = "none"`，
因为不写 provider 默认走 openai，每次都卡 15.0 秒超时）。但 `none` 只让工具不再超时，
**工具照样暴露**，而 `corpus=sessions` 照样硬失败
（`dist/tools-CXlrjPxU.mjs:682`）—— 用户看到的"每次对话都有报错"就是这一层。

**做了什么**：`mergeToolsDefaults` 把 `memory_search` / `memory_get` **并进** `tools.deny`
（并集，不覆盖用户已有的项；`Set` 保证幂等），**并把提前返回的守卫一起改了** ——
那条守卫是存量用户每次启动的必经之路，漏了它这一刀对用户机器完全无效
（文件里那条注释就是为 memory 那次栽的坑写的）。

**⚠️ 代价（写进代码注释了，免得后人以为是白捡）**：`provider:"none"` 下
`memory_search` 对 `MEMORY.md`/`USER.md`/`memory/**` 的 FTS 召回**本来能用**。
可接受的理由：根 `MEMORY.md` 已经**每轮全文注入**，召回它边际价值很小；
真正有价值的 `sessions` 语料在本配置下根本用不了。

**变异验证**：5/5 抓到。⚠️ 其中一条**第一次是存活的** —— 我的"幂等"用例从空配置起步，
第一次跑完就满足了守卫、后续走**提前返回**，**根本走不到查重那一行**（测的是别的东西）。
改成从"只 deny 了一个"起步才真正覆盖查重。
⚠️ 另有一条锚点撞上 **CRLF** 打偏（脚本如实报"脚本错"，没当"存活"糊过去）。
