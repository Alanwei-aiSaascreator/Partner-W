2. **不打交付包、不发版**。

4. **不做破坏性 git 操作**：不 rebase 别人的分支、不 force push、不 reset --hard。
5. **每刀独立提交**，随时可单独回滚；提交信息写清"为什么"与**怎么回滚**。
6. **TDD + 变异验证**：先红后绿；写完实现才跑的测试必须补变异验证。

   带一条自检变异证明判据分得开、脚本自己错了要当"脚本错"报出来而不是"存活"。
7. **每刀都要过门禁**：typecheck / typecheck:tests / lint / check:i18n /
   check:ui-contract / check:renderer-copy / check:architecture。
8. **发现真 bug 优先修**，但要与当前这刀分开提交或写清缘由。
9. **诚实记失败**：偶发、跳过的验证、没查的根因，都要写进提交信息与记忆。
10. **可测宣称三件事**：凡「N 项 / 只剩 X 条」这类话，当场写清 ①出处 ②测量日期 ③可重跑的命令。

### T-a1 `tools.deny` —— 摘掉必然失败的两个 memory 工具

**洞察**：客户端**已经修过一次**这个坑（`MEMORY_SEARCH_PROVIDER = "none"`，
因为不写 provider 默认走 openai，每次都卡 15.0 秒超时）。但 `none` 只让工具不再超时，
**工具照样暴露**，而 `corpus=sessions` 照样硬失败
（`dist/tools-CXlrjPxU.mjs:682`）—— 用户看到的"每次对话都有报错"就是这一层。

**做了什么**：`mergeToolsDefaults` 把 `memory_search` / `memory_get` **并进** `tools.deny`
（并集，不覆盖用户已有的项；`Set` 保证幂等），**并把提前返回的守卫一起改了** ——
那条守卫是存量用户每次启动的必经之路，漏了它这一刀对用户机器完全无效
（文件里那条注释就是为 memory 那次栽的坑写的）。

**⚠️ 代价（写进代码注释了，免得后人以为是白捡）**：`provider:"none"` 下
`memory_search` 对 `MEMORY.md`/`USER.md`/`memory/**` 的 FTS 召回**本来能用**。
可接受的理由：根 `MEMORY.md` 已经**每轮全文注入**，召回它边际价值很小；
真正有价值的 `sessions` 语料在本配置下根本用不了。

**变异验证**：5/5 抓到。⚠️ 其中一条**第一次是存活的** —— 我的"幂等"用例从空配置起步，
第一次跑完就满足了守卫、后续走**提前返回**，**根本走不到查重那一行**（测的是别的东西）。
改成从"只 deny 了一个"起步才真正覆盖查重。
⚠️ 另有一条锚点撞上 **CRLF** 打偏（脚本如实报"脚本错"，没当"存活"糊过去）。
