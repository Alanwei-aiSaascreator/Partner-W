# 荣盈魔方：中国大陆加密与数据安全建设方案

> 版本：v1.0（内测建设基线）  
> 日期：2026-09-16  
> 适用范围：荣盈魔方 Windows / U 盘客户端、国内服务端、运营后台、AI 网关、数据库、对象存储、日志与备份。  
> 说明：本方案是产品与工程建设建议，不替代律师、等级保护测评机构或商用密码应用安全性评估机构的正式意见。

## 1. 建设结论

荣盈魔方不应只做“数据库字段加密”，而应采用六层防护：

1. **数据分类分级**：先判断数据是否应收集、是否属于个人信息/敏感个人信息/重要数据，再决定保存位置和加密强度。
2. **传输加密**：客户端、API、模型网关、数据库、对象存储和后台全部通过加密通道通信。
3. **存储加密**：服务器磁盘、MySQL 敏感字段、对象文件、备份、U 盘工作区分别加密。
4. **密钥独立管理**：数据与密钥分离，使用国内云 KMS 或合规密码机/HSM，不把主密钥写进源码、数据库或安装包。
5. **身份、权限和审计**：用户、运营、开发、数据库管理员分权；高风险操作双人复核并留痕。
6. **AI 专项防护**：模型请求最小化、文件授权可见、敏感信息检测、模型与工具身份标识、输出标识和 Agent 工具权限沙箱。

建议内测期使用“**国内云 KMS + 应用层信封加密 + 云盘/数据库存储加密 + U 盘工作区加密**”；进入政企、重要网络或更高合规等级后，再切换到通过检测认证的国密产品和密码机。

## 2. 中国大陆合规基线

设计和上线至少对齐以下现行规则：

- 《中华人民共和国个人信息保护法》第五十一条要求采取分类管理、加密、去标识化等措施，并建立便捷的个人权利处理机制。([中国网信网](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm))
- 《网络数据安全管理条例》自 2025-01-01 起施行，要求在等级保护基础上采取加密、备份、访问控制、安全认证等措施。([中国网信网](https://www.cac.gov.cn/2024-09/30/c_1729384452307680.htm))
- 修正后的《网络安全法》要求采取日志留存、数据分类、重要数据备份和加密等措施；网络日志原则上不少于六个月。([中国网信网](https://www.cac.gov.cn/2025-12/29/c_1768735112911946.htm))
- 《密码法》和 2023 年修订的《商用密码管理条例》规定，非国家秘密信息使用商用密码保护；涉及重要网络与信息系统时需要进一步判断密码应用方案和密评义务。([国家密码管理局](https://www.nca.gov.cn/sca/xxgk/2023-06/04/content_1057225.shtml)、[司法部解读](https://www.moj.gov.cn/pub/sfbgw/zwxxgk/fdzdgknr/fdzdgknrjdhy/202306/t20230608_480362.html))
- 密码应用设计参考 GB/T 39786-2021《信息安全技术 信息系统密码应用基本要求》。([国家标准信息公共服务平台](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=53282C88712CE157043B7A2C590278FC))
- 网络安全保护参考 GB/T 22239-2019《信息安全技术 网络安全等级保护基本要求》。([国家标准信息公共服务平台](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=BAFB47E8874764186BDB7865E8344DAF))
- 若未来被认定为重要网络与信息系统，应按《商用密码应用安全性评估管理办法》同步规划、建设、运行密码保障系统并开展评估。([国家密码管理局](https://www.nca.gov.cn/sca/xxgk/2023-10/07/content_1061109.shtml))
- 个人信息保护合规审计应覆盖制度、权限、事件响应、加密和去标识化措施。([中国网信网](https://www.cac.gov.cn/2025-02/14/c_1741233507681519.htm))
- 当前公司内部研发应用、未向境内公众提供生成式 AI 服务时，《生成式人工智能服务管理暂行办法》明确不按公众服务适用；一旦公开提供服务，应重新判断备案、安全评估、投诉机制和模型公示义务。([中国网信网](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm))
- 对外上线生成式 AI 功能时，应核查所用模型备案/登记信息，并在产品显著位置标明模型名称和备案号。([中国网信网](https://www.cac.gov.cn/2024-04/02/c_1713729983803145.htm))

## 3. 数据分类与保存位置

| 等级         | 示例                                                 | 默认保存                           | 加密和访问要求                                |
| ------------ | ---------------------------------------------------- | ---------------------------------- | --------------------------------------------- |
| L1 公开      | 公告、公开助手模板、公开价格                         | MySQL / CDN                        | 完整性保护、发布审计                          |
| L2 内部      | 产品配置、普通日志、匿名统计                         | 国内 MySQL / 日志库                | 磁盘加密、最小权限、备份加密                  |
| L3 敏感      | 手机号、设备标识、聊天记录、用户文件、余额与订单     | 国内 MySQL + 对象存储              | 字段/对象信封加密、去标识化、访问审计         |
| L4 高敏/重要 | 身份证、银行卡、精确位置、大规模行为画像、管理员密钥 | 原则上不收集；确需收集时独立安全域 | 单独同意、强加密、HSM/KMS、双人授权、专项评估 |

内测 1.0 建议不收集身份证、银行卡、通讯录、全盘文件列表。客户端只处理用户主动授权的文件/文件夹，并在界面持续显示授权范围。

## 4. 推荐数据架构

```text
Windows / U盘客户端
  ├─ 本地工作区：每任务独立 DEK 加密
  ├─ Windows 凭据/TPM：设备密钥与刷新令牌
  └─ TLS 1.3 / 国密合规通道
             │
国内 API 网关 / 身份服务
  ├─ 短期访问令牌、风控、限流、审计
  ├─ AI 网关：脱敏、模型路由、用量计费
  └─ KMS/HSM：只执行密钥生成、包装、解包
             │
  ├─ MySQL：结构化业务数据、密文和密钥版本
  ├─ 对象存储：用户文件/成果文件密文
  ├─ Redis：短期验证码、会话、限流（不放长期明文）
  ├─ 日志库：去标识化安全日志
  └─ 备份库：独立账号、不可变、加密备份
```

### 4.1 MySQL 是否适合

MySQL 8 可以作为主业务数据库，适合保存用户、任务、消息索引、额度、订单、团队和运营配置。不要把大文件直接存进 BLOB；文件应进入国内对象存储，MySQL 只保存对象 ID、密文元数据、哈希、大小和权限。

建议组合：

- **MySQL 8 / 国内云 RDS**：开启静态加密、TLS、自动备份、审计和主从高可用。
- **对象存储（OSS/COS/OBS 或自建 MinIO）**：保存文件密文，禁止公共读；下载使用短时签名 URL。
- **Redis**：只保存验证码、限流计数和短期状态，设置 TTL；验证码只存哈希/HMAC，不存明文。
- **日志与审计库**：与业务库分开账号和权限，手机号等字段去标识化。

如果自建 MySQL Community，不能把“开启磁盘加密”误认为完成字段保护。应继续做应用层信封加密；数据库备份、binlog、临时文件和导出文件也必须加密。

### 4.2 敏感字段设计

| 数据         | 保存方式                                                                              |
| ------------ | ------------------------------------------------------------------------------------- |
| 手机号       | `phone_ciphertext`（SM4/AES-GCM 信封加密）+ `phone_lookup_hmac`（检索令牌）+ 脱敏展示 |
| 激活码       | 仅保存带服务端 pepper 的 HMAC/哈希；原码只在签发时显示一次                            |
| 短信验证码   | 只保存 HMAC 和 5 分钟以内 TTL，限制手机号/IP/设备频率                                 |
| 刷新令牌     | 数据库存哈希；客户端放系统安全存储，不放 localStorage                                 |
| 聊天内容     | 每用户或每任务 DEK 加密；搜索索引与正文分离                                           |
| 模型 API Key | 只存在服务端 Secret Manager/KMS 密文，客户端永不下发                                  |
| 余额/积分    | 不依赖加密保证正确性；使用不可变账本、事务和审计签名                                  |

## 5. 密钥体系

采用信封加密：

1. 根密钥只存在 KMS/HSM，不可导出。
2. 每环境独立 KEK：开发、测试、生产完全分离。
3. 每租户/用户/任务/文件生成独立 DEK。
4. 数据用 DEK 加密；DEK 再由 KEK 包装，数据库只保存包装后的 DEK、算法和版本。
5. 解密必须经过身份鉴别、授权判断和审计；应用进程仅短时持有明文 DEK。
6. KEK 至少每年轮换，人员离职、疑似泄露或权限变更立即轮换；DEK 支持逐步重包装，不必一次解密全部数据。

算法选择：

- 中国大陆政企/密评场景优先采用经检测认证产品提供的 SM2（签名/密钥交换）、SM3（摘要/HMAC）、SM4（对称加密）。
- 普通商业内测可使用成熟库提供的 AES-256-GCM、TLS 1.3，但不要宣称因此已经“国密合规”。
- 不自行设计算法，不使用 ECB，不使用固定 IV，不把密码直接当密钥。
- 必须使用带认证的加密模式；每次加密随机 nonce/IV，并把版本、算法、AAD、标签与密文一起保存。

## 6. 硬件加密

### 6.1 服务端

- 生产根密钥放国内云 KMS 或通过检测认证的服务器密码机/HSM。
- 数据库盘、对象存储盘、日志盘和备份盘分别启用存储加密。
- 管理员密钥操作采用 MFA、堡垒机、IP 白名单和双人复核。
- HSM/KMS 权限与云主机管理员分离，开发人员不能导出生产密钥。

### 6.2 客户端电脑

- 使用 TPM 2.0 封存设备密钥；刷新令牌放 Windows Credential Manager/DPAPI。
- 代码签名使用 Windows Authenticode；更新清单再做独立签名校验。
- 禁止在 Electron renderer、日志、崩溃报告或配置文件中出现 API Key、KEK、数据库口令。

### 6.3 U 盘

U 盘跨电脑使用，不能只依赖某一台电脑的 TPM。推荐“双封装”：

- 每个 U 盘工作区生成随机 Workspace DEK。
- DEK-A：经在线账号登录后由服务端 KMS 解包，用于跨电脑恢复。
- DEK-B：由用户恢复口令派生的 KEK 包装，用于受控离线恢复。
- 文件逐个使用独立 File DEK，加密文件名映射和文件内容；删除授权时销毁对应包装密钥。
- U 盘丢失后，服务端可吊销账号包装密钥；没有恢复口令/登录授权，盘内只剩密文。
- BitLocker To Go 可作为额外物理防护，但不能替代应用层文件加密，也不能直接等同于商用密码合规。

## 7. 传输、接口与 Agent 工具安全

- 公网 API 强制 HTTPS/TLS 1.3；数据库、Redis、对象存储内部连接也启用 TLS。
- 短期 access token（如 15 分钟）+ 可撤销 refresh token；后台必须 MFA。
- 服务间使用 mTLS 或签名请求，防止伪造 AI 网关、计费或更新服务。
- 文件上传先校验大小、类型、扩展名、真实 MIME、恶意内容；保存时随机对象 ID，不使用用户路径作为服务端路径。
- Agent 只能看到当前任务和用户主动授权材料；所有文件读取使用 taskId/sourceId/relativePath 权限模型。
- shell、网络、写文件、支付、删除等高风险工具采用单独权限；危险操作必须显示目标并二次确认。
- 模型输入前进行敏感数据检测；默认不把完整手机号、密钥、身份证、银行卡、系统日志发送给第三方模型。
- 模型供应商、模型名称、备案/登记信息、数据保留方式应在产品内展示；调用境外模型前必须单独做跨境与个人信息影响评估。

## 8. AI 身份安全与伦理

- 每条回答记录实际模型、助手、工具调用、用量和 traceId，界面标签必须与实际执行一致。
- 明确说明“AI 生成”，对外发布的生成内容按适用规则增加显式/隐式标识。
- 助手提示词、工具权限、知识库版本和模型版本全部版本化，可追溯、可回滚。
- 建立提示词注入防护：外部文件内容永远视为不可信数据，不能覆盖系统指令或自动获得工具权限。
- 对违法内容、个人信息泄露、自伤、诈骗、金融/医疗等高风险请求设置规则、人工复核和投诉入口。
- 训练、微调或评测使用真实用户内容前，取得相应授权并完成去标识化；默认不把用户私有内容用于训练。

## 9. 日志、备份与灾难恢复

- 安全日志记录：登录、激活、授权文件、管理员变更、额度账本、模型调用、密钥操作、导出/删除申请、升级与回滚。
- 日志不记录验证码、token、密钥、完整聊天正文和文件内容；手机号只显示脱敏值或 HMAC 标识。
- 网络运行日志按适用要求设置不少于六个月留存；业务日志根据最小必要原则单独制定期限。
- 每日增量、每周全量备份；备份使用独立 KEK，加密后存入独立账号/区域并开启不可变保留。
- 每季度做恢复演练，验证数据库、对象、密钥版本和账本能共同恢复。
- 明确 RPO/RTO：内测建议 RPO ≤ 24 小时、RTO ≤ 8 小时；商用后提升至 RPO ≤ 1 小时、RTO ≤ 2 小时。

## 10. 三阶段落地

### 阶段 A：3 天内测版必须完成

- 国内服务域名全站 HTTPS；生产密钥不进入客户端和 Git。
- 手机号、刷新令牌、激活码、模型 Key 按本方案处理。
- MySQL/对象存储/备份启用云侧静态加密。
- U 盘/本地工作区先启用操作系统加密建议和应用数据目录权限隔离；预留 Workspace DEK 字段。
- 隐私政策列出数据清单、目的、保存期限、第三方模型和用户权利入口。
- 后台 MFA、角色分权、敏感操作日志。
- 内测数据不得直接用于模型训练；不得上传用户未授权目录。

### 阶段 B：内测后 2–4 周

- 上线 KMS 信封加密，完成手机号、聊天、文件和备份的密钥版本迁移。
- 上线 U 盘 Workspace/File DEK、在线解包和恢复口令流程。
- 完成数据导出/删除、权限撤回、密钥轮换和安全事件处置演练。
- 建立 SBOM、依赖漏洞扫描、代码签名、更新包双签名和灰度升级。

### 阶段 C：公开商用前

- 完成等保定级判断、备案与测评；判断是否属于重要网络与信息系统或关键信息基础设施。
- 由律师和合规机构开展个人信息保护影响评估、跨境评估、委托处理协议审查。
- 如适用，编制商用密码应用方案并委托有资质机构开展密评。
- 公开生成式 AI 服务前核查模型备案/登记、算法备案、安全评估、生成内容标识和投诉机制。

## 11. 禁止事项

- 禁止把数据库密码、模型 API Key、短信密钥写入客户端或 `.env` 后打包。
- 禁止把 KEK 与密文放在同一数据库、同一备份或同一管理员权限下。
- 禁止自行实现“看起来像加密”的算法、固定 IV、ECB、明文日志或可逆的简单 Base64。
- 禁止后台共用账号、永久 token、关闭 TLS 校验或为了调试上传完整用户文件。
- 禁止把“开启 BitLocker/云盘加密”宣传为已完成全部国密、等保或个人信息合规。

## 12. 验收清单

- [ ] 有数据分类分级表和数据资产清单。
- [ ] 每个敏感字段明确算法、密钥层级、保存期限和访问角色。
- [ ] KMS/HSM、数据库、对象存储、备份权限相互分离。
- [ ] 客户端不含生产秘密；更新包可验证签名并可回滚。
- [ ] U 盘丢失后无法直接读取用户工作区明文。
- [ ] 管理员和开发人员不能绕过审计批量解密用户数据。
- [ ] 用户可撤回授权、导出和删除个人信息。
- [ ] 第三方模型、短信、支付、云存储均有数据处理清单和合同约束。
- [ ] 安全日志不含秘密，且满足留存和追溯要求。
- [ ] 完成备份恢复、密钥轮换、泄露吊销和应急演练。
