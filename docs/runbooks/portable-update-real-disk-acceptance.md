### 失败可回滚：**故意造一个"起得来、但不回报健康"的新版本**（本轮必须单独跑一遍）

**目标**：让「换目录成功、但新版本没起好」这条链真跑一遍 ⇒ 期望启动器**回滚**，
盘上回到 0.0.31、程序照常能开、事务相位 `rolled-back`。

⚠️ **两个坑必须先说清，否则验的是别的分支**：

1. **只改暂存树、不重签** ⇒ 启动器在**校验**那一步就拒（`file-integrity`）⇒
   走的是"根本没进换目录"那条路，**验不到换目录之后的回滚**。
   ⇒ 必须**重算文件清单 + 用私钥重签 manifest**，再把两份新清单写回暂存目录。
2. **换成"立刻退出"的桩** ⇒ 走的是 `ErrHealthFailed`（进程早退），**不是** `ErrHealthTimeout`（等满 90 秒）。
   ⇒ 想覆盖 timeout，桩必须**活着、但永远不写回执**。

#### 步骤（全部用仓库里已有的工具，不需要新写脚本）

设 `$CAND` = `D:\Desktop\Partner-W生成outpu\0.0.32-internal-candidate`，`$DISK` = 盘符，`$TX` = 事务 id。

1. **摆一个正常的 `ready` 事务**：暂存树（从 `$CAND\portable.zip` 解出来）+ 两份真清单 +
   真 zip + `update-state.json`（`phase:"ready"`、`targetVersion:"0.0.32"`、`currentVersion:"0.0.31"`）。
2. **造桩**：最小 Go 程序，`main()` 里只有 `time.Sleep(300 * time.Second)`（比 90 秒预算长），
   `GOOS=windows GOARCH=amd64 go build -trimpath -ldflags "-s -w"` ⇒ 约 1.2 MB 的 exe。
   **名字必须是 `Partner-W.exe`**（启动器按固定名字拉起）。
3. **换进暂存树**：`$DISK\.Partner-W更新\staged\$TX\program\Partner-W.exe` ← 桩。
4. **重算清单 + 重签**（这一段是本节补全的关键）：

   ```powershell
   $env:PARTNERW_UPDATE_SIGNING_KEY_FILE = '<仓库外的 Ed25519 PKCS#8 PEM>'
   $env:PARTNERW_UPDATE_PUBLIC_KEY_B64   = '<与私钥匹配的 SPKI Base64 公钥>'
   $env:PARTNERW_MIN_LAUNCHER_VERSION    = '0.0.28'
   $env:PARTNERW_LAUNCHER_VERSION        = '0.0.28'
   pnpm update:portable-package -- --program-dir "$DISK\.Partner-W更新\staged\$TX\program" `
     --version 0.0.32 --channel internal --base-url 'https://api.rongyinghudong.com/updates' --out '<一个空目录>'
   ```

   工具会**按这棵树**重新算 `portable-files.json`、把新的 `fileManifestSha256` 写进 manifest、并**用私钥重签**。
   ⚠️ 它顺带产出的 `portable.zip`（约 400 MB）**用不上**（`Apply` 不读归档，只读树 + 两份清单），删掉即可 ——
   也就是说这次演练**不需要**把新 zip 拷到盘上。

5. **把两份新清单放回暂存目录**：`staged\$TX\manifest.json` 与 `portable-files.json` ← 第 4 步的产物。
6. **跑启动器**（前台跑才看得到模态框背后的原文）：

   ```powershell
   & "$DISK\Partner-W启动器.exe" --apply "$DISK\.Partner-W更新\update-state.json"
   ```

7. **期望读数**（缺一条都算缺陷）：
   - 进度屏停留约 **90 秒 + 校验时间**（新版本起来了，但一直没写回执）；
   - 然后**回滚**：`Partner-W\resources\app.asar` 回到 **0.0.31** 的摘要（`4b122bae…`）；
   - 事务相位 **`rolled-back`**；`staged\$TX` 被清掉；
   - 双击启动器**程序照常打开**（0.0.31）；
   - **不出现**"盘打不开"（那才是回滚失败，那时启动器会提示换整包）。
8. **收尾**：把盘恢复成 **0.0.31 干净基线**（重新整包拷一遍），再进入上面的完整验收。

##### ⚠️ 顺带发现的一条 UX 缺口（**未修**，登记在此）

- 回滚成功时 `Apply` 返回 `nil` ⇒ `applyTransaction` 走的是"成功"分支 ⇒ **不弹错误框**、退出码 `0`；
- 而且这条路上**不会**拉起旧版本 ⇒ 用户看到的是："进度屏走了一两分钟，然后什么都没发生，
  程序也没打开"（得再双击一次才会打开）。
- 代码位置：`launcher/cmd/partner-w-launcher/main.go` 的 `applyTransaction`（`ErrHealthTimeout` 被 `Rollback` 吞成成功）。
- 建议（下一轮再拍，**本轮不改代码**）：回滚成功时也**明确说一句**"这次更新没成功，已还原到 0.0.31"，

⚠️ 注意：**这不是"更新卡住"** —— 事务、证据、盘上状态都对；缺的只是**那句人话**。
