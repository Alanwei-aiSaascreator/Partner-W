# 荣盈魔方协议与隐私同意闭环设计

**日期：** 2026-09-15

**状态：** 方案已确认并保存；延期至正式上线前实施（上线前 P0）

**范围：** 服务条款、产品隐私政策、18 岁确认、同意记录、版本升级后的重新确认及商业能力服务端校验。

## 1. 目标

把登录页现有的本地勾选框升级成可审计、可版本化、不能被旧客户端绕过的同意闭环。用户必须能够在登录前分别阅读《荣盈魔方服务条款》和《荣盈魔方产品隐私政策》；服务端必须保存用户接受的准确版本，并在协议升级后要求重新确认。

本功能首版只面向 18 岁以上用户。未成年人监护人同意、数据导出、账号注销、撤回授权和跨境合规评估属于后续独立功能，不塞进本次实现。

## 2. 已确认决策

- 使用服务端强制记录方案，不以客户端本地勾选作为最终证据。
- 用户未勾选协议时不能获取验证码。
- 验证码登录成功后，先把同意记录绑定到真实用户 ID，再进入正式工作区。
- 同意记录写入失败时不进入工作区，并清除刚建立的登录会话。
- 协议版本升级后，已登录用户下次启动时进入重新确认页；本地任务和工作区数据不删除。
- 协议页面无法联网打开时，应用提供与当前版本一致的内置只读副本，但仍需完成服务端同意记录。
- Demo 和小规模测试阶段继续使用现有 Supabase；数据库结构保持 PostgreSQL 可迁移性。
- 产品隐私政策必须如实说明手机号、设备、支付、提示词、用户主动添加的文件以及模型供应商的数据路径，不能沿用当前“展示网站不收集注册信息”的网站隐私说明。

## 3. 用户流程

### 3.1 新用户或已退出用户

```text
打开登录页
→ 客户端读取当前有效的条款与隐私政策版本
→ 用户分别查看在线页面或内置副本
→ 用户勾选“已满 18 岁，并同意服务条款与产品隐私政策”
→ 服务端校验版本并签发一次性同意票据
→ 获取验证码
→ 输入验证码
→ Supabase 完成身份验证
→ 服务端消费同意票据并把记录绑定到真实用户 ID
→ 写入成功后进入用途引导或工作区
```

登录页在手机号阶段与验证码阶段共用同一份同意状态。用户返回修改手机号时不清除勾选；关闭应用或重新进入登录页后不默认勾选。

### 3.2 已登录但版本过期的用户

```text
启动应用并恢复登录会话
→ 查询当前协议状态
→ 发现条款或隐私政策版本过期
→ 显示独立的协议更新确认页
→ 用户查看变更摘要与完整正文
→ 用户确认新版本
→ 服务端追加新的不可变同意记录
→ 继续进入原工作区
```

用户拒绝新版本时可以退出账号，但不能激活卡密、取得 Relay 能力或调用商业模型。

## 4. 页面与内容

### 4.1 正式页面地址

- 服务条款：`https://www.rongyinghudong.com/terms.html`
- 产品隐私政策：`https://www.rongyinghudong.com/product-privacy.html`

当前 `https://www.rongyinghudong.com/privacy.html` 保留为公司展示网站隐私页面，不再作为荣盈魔方客户端隐私政策。

### 4.2 页面最低内容

《服务条款》至少包含：运营主体、适用范围、账号与验证码、18 岁限制、U 盘和激活权益、积分/额度、AI 生成内容限制、用户文件与电脑工具授权、支付退款、禁止行为、服务变更、责任边界、知识产权、账号终止、争议解决、联系方式、版本号和生效日期。

《产品隐私政策》至少包含：运营主体、收集的数据类型、处理目的、保存期限、设备侧与云端边界、短信服务商、Supabase、支付机构、模型供应商、提示词与主动提供文件的传输、跨境情况、Cookie/本地存储、信息安全、用户权利、账号注销入口、未成年人限制、政策更新、联系方式、版本号和生效日期。

运营主体沿用现有公开信息：深圳市荣盈互动科技有限公司；正式发布前由公司负责人和专业律师审核正文。法律审核是发布验收条件，不改变本文规定的产品和技术行为。

### 4.3 客户端展示

- 登录页文案改为：“我已满 18 岁，并已阅读和同意《服务条款》与《产品隐私政策》”。
- 两个链接来自服务端返回的当前文档元数据，不再存放在 i18n URL 字段中。
- 在线页面打开失败时提供“在应用内查看”入口，展示随客户端打包的当前版本副本。
- 账号设置新增“协议与隐私”分组，显示当前版本、同意时间，以及两个查看入口。
- 版本升级确认页显示条款版本、隐私版本、生效日期和简短变更摘要，不重复要求验证码登录。

## 5. 数据模型

新增 Supabase migration `20260915000034_legal_consent.sql`。

### 5.1 `legal_document_versions`

| 字段             | 类型          | 说明                          |
| ---------------- | ------------- | ----------------------------- |
| `id`             | `uuid`        | 主键                          |
| `kind`           | `text`        | 仅允许 `terms` 或 `privacy`   |
| `version`        | `text`        | 对外稳定版本，如 `2026-09-15` |
| `effective_at`   | `timestamptz` | 生效时间                      |
| `enforce_at`     | `timestamptz` | 服务端开始强制执行的时间      |
| `document_url`   | `text`        | 正式 HTTPS 页面               |
| `content_sha256` | `text`        | 发布正文的 SHA-256            |
| `minimum_age`    | `integer`     | 首版固定为 18                 |
| `change_summary` | `text`        | 升级确认页使用的摘要          |
| `created_at`     | `timestamptz` | 创建时间                      |

同一种 `kind` 在任一时刻只能有一个当前生效版本。客户端只能读取已经发布的文档元数据；只有 `service_role` 可以新增或修改版本。

### 5.2 `legal_acceptance_attempts`

| 字段                      | 类型          | 说明                           |
| ------------------------- | ------------- | ------------------------------ |
| `id`                      | `uuid`        | 不可预测的一次性票据，也是主键 |
| `terms_version`           | `text`        | 已确认的条款版本               |
| `privacy_version`         | `text`        | 已确认的隐私版本               |
| `minimum_age_confirmed`   | `integer`     | 首版固定记录 18                |
| `device_fingerprint_hash` | `text`        | 设备指纹的 SHA-256             |
| `app_version`             | `text`        | 发起确认的客户端版本           |
| `source`                  | `text`        | 首版固定为 `otp-login`         |
| `created_at`              | `timestamptz` | 服务端创建时间                 |
| `expires_at`              | `timestamptz` | 创建后 10 分钟失效             |
| `consumed_at`             | `timestamptz` | 成功绑定用户后的时间           |

票据不保存手机号、验证码、IP 地址或用户 ID，匿名客户端不能直接查询表。匿名 RPC 只能创建票据并取得自己的随机 ID；过期或已消费票据不能再次使用。

### 5.3 `legal_acceptances`

| 字段                      | 类型          | 说明                             |
| ------------------------- | ------------- | -------------------------------- |
| `id`                      | `uuid`        | 主键                             |
| `user_id`                 | `uuid`        | 关联 `auth.users.id`             |
| `terms_version`           | `text`        | 用户接受的条款版本               |
| `privacy_version`         | `text`        | 用户接受的隐私版本               |
| `accepted_at`             | `timestamptz` | 服务端时间                       |
| `minimum_age_confirmed`   | `integer`     | 首版固定记录 18                  |
| `device_fingerprint_hash` | `text`        | 设备指纹的 SHA-256，不保存原始值 |
| `app_version`             | `text`        | 发起确认的客户端版本             |
| `source`                  | `text`        | `otp-login` 或 `version-upgrade` |

记录只追加不更新。唯一键为 `(user_id, terms_version, privacy_version)`，重复请求返回已有记录，实现幂等。用户只能查询自己的记录；普通客户端不能直接插入、修改或删除记录。OTP 登录来源必须引用并消费有效的 `legal_acceptance_attempts.id`；版本升级来源不需要匿名票据，因为用户已经处于已认证会话。

## 6. 服务端接口

### 6.1 `current_legal_documents()`

允许 `anon` 与 `authenticated` 调用，返回当前服务条款和产品隐私政策的版本、URL、摘要、哈希、最低年龄、生效时间和强制时间。若任一文档缺失、重复或配置无效，返回失败，客户端不得自行猜测版本。

### 6.2 `begin_legal_acceptance(...)`

允许 `anon` 调用，接收当前两个版本、最低年龄确认、设备指纹哈希和客户端版本。函数校验版本与年龄后创建 10 分钟有效的一次性票据并返回 ID。表本身不向 `anon` 开放，函数固定 `search_path` 并限制单设备的短时创建频率，避免被用作无界写入接口。

客户端必须先取得票据，再请求发送验证码。短信发送失败时票据自然过期；重新发送可在票据有效且未消费时复用，过期后重新创建。

### 6.3 `current_legal_status()`

仅允许 `authenticated` 调用。返回当前用户是否已接受正在强制执行的两个版本、历史同意时间和需要重新确认的版本。网络或数据库错误必须与“尚未同意”区分，但两者都不能开放商业能力。

### 6.4 `accept_current_legal_documents(...)`

仅允许 `authenticated` 调用。OTP 登录来源接收一次性票据 ID；版本升级来源接收当前两个版本、最低年龄确认、设备指纹哈希和客户端版本。函数使用 `auth.uid()` 绑定用户，使用数据库时间写入记录，并拒绝：

- 票据过期、已消费或不存在；
- 票据或客户端提交的版本不是当前有效版本；
- 最低年龄确认不是 18；
- 客户端版本或来源为空；
- 文档尚未生效或元数据配置不完整。

函数使用 `SECURITY DEFINER`，固定 `search_path`，显式撤销 `public`/`anon` 执行权，只向 `authenticated` 授权。

### 6.5 商业能力强制门

- `activate_license` 在绑定或返回 Relay key 前检查当前用户的有效同意记录。
- Relay 的 key 解析查询同时判断所属账号是否满足当前强制版本；不满足时返回 `legal_acceptance_required`，不转发模型请求，也不产生费用。
- 强制门以 `enforce_at` 为准。首次部署 migration 时设置未来的强制时间，先发布新客户端并验证，再进入强制期，避免旧客户端在没有确认页面时突然全部失效。
- 强制期开始后，旧客户端不能靠已有 Relay key 绕过。用户必须升级并完成确认。

## 7. Desktop 架构改动

### 7.1 主进程商业模块

新增 `packages/desktop/src/main/commercial/legal.ts`，集中负责读取文档元数据、查询状态、提交同意和计算设备指纹哈希。登录模块不拼 SQL，也不保存法律正文。

发送验证码前，商业模块先创建或复用一次性同意票据；票据成功后才调用 Supabase OTP。`verifyLoginOtp` 成功后，由商业 IPC handler 消费票据并写入同意记录。只有身份验证与同意记录都成功，才触发 Relay bootstrap；同意失败时调用 Supabase sign out，返回明确错误码。

新增 IPC：

- `commercial:legal-documents`
- `commercial:legal-status`
- `commercial:legal-accept`

现有 `commercial:send-otp` 改为接收包含手机号和 `LegalAcceptanceInput` 的结构化对象，并返回同意票据 ID。`commercial:verify-otp` 改为接收手机号、验证码和票据 ID 的结构化对象，不继续扩展位置参数。

### 7.2 预加载边界

在 `packages/desktop/src/preload/index.ts` 和 `clawwork.d.ts` 中暴露对应的强类型方法。渲染层只能提交版本与确认信息，不能提交用户 ID 或自定义接受时间。

### 7.3 渲染层

- `Login` 首次挂载读取当前文档元数据；读取完成前禁用获取验证码。
- `Login` 把用户明确勾选的当前版本传给验证码发送 IPC，并保存返回的一次性票据 ID。
- `Login` 验证验证码时同时提交票据 ID；修改手机号不会丢失仍有效的票据，票据过期则重新创建。
- `App` 在已登录会话检查之后、用途引导之前增加法律状态门。
- 新增 `LegalConsentGate` 处理版本升级确认，不复制 OTP 登录逻辑。
- 新增 `LegalDocumentDialog` 显示内置副本；副本版本与哈希由构建时常量固定。
- `AccountSection` 展示当前版本和同意时间，不展示设备哈希。

## 8. 错误处理与文案

| 情况                     | 用户行为                                                 |
| ------------------------ | -------------------------------------------------------- |
| 当前文档元数据读取失败   | 登录按钮保持不可用，显示“暂时无法读取协议版本”，提供重试 |
| 未勾选                   | 获取验证码按钮保持不可用                                 |
| 同意票据创建失败         | 不发送验证码，显示“暂时无法记录协议确认”，提供重试       |
| 同意票据过期             | 不验证登录，重新创建票据并提示用户重新获取验证码         |
| OTP 成功、同意写入失败   | 清除新会话，停留登录页，显示“协议确认未完成，请重试”     |
| 已登录用户版本过期       | 进入协议更新确认页，可确认或退出账号                     |
| 服务端法律状态暂时不可用 | 不进入商业工作区，保留本地数据，提供重试与退出           |
| Relay 拒绝旧协议版本     | 显示需要更新协议/客户端，不把它误报为余额不足或模型故障  |
| 在线法律页面打不开       | 提供内置副本，不把“打不开网页”当成自动同意               |

日志只记录错误码、协议版本、客户端版本和请求 ID，不记录手机号、验证码、正文、设备原始指纹或用户提示词。

## 9. 发布顺序

1. 完成并审核两个法律页面正文，计算发布内容 SHA-256。
2. 部署数据库表、RPC 和未来的 `enforce_at`，此时不阻断旧客户端。
3. 发布支持同意闭环的新客户端和在线更新元数据。
4. 使用全新用户、已有用户、过期版本和离线页面场景完成彩排。
5. 确认新客户端覆盖率和客服预案后进入强制时间。
6. 强制后监控 `legal_acceptance_required`、登录失败率、Relay 拒绝率和协议页面可用性。

## 10. 测试与验收

### 10.1 数据库

- 匿名用户只能读取当前文档元数据，不能读取同意记录。
- 匿名用户可以创建一次性同意票据，但不能读取、修改或消费票据表。
- 已登录用户只能读取自己的同意记录。
- 接受当前版本成功，重复接受幂等。
- 旧版本、虚构版本、未确认 18 岁、空客户端版本、过期票据和重复消费均被拒绝。
- `activate_license` 在强制期前兼容旧客户端，强制期后拒绝未同意用户。

### 10.2 Desktop

- 文档加载前和未勾选时不能发送验证码。
- 两个链接分别打开正确页面。
- 同意票据创建失败时不调用 Supabase OTP；成功发送后保存票据 ID。
- OTP 成功但同意写入失败时不调用 `onSignedIn`，并完成 sign out。
- OTP 与同意都成功时只触发一次账号清理和 Relay bootstrap。
- 已登录且版本过期时先显示 `LegalConsentGate`，确认后恢复原工作区。
- 在线页面失败时可以查看内置副本。
- 账号设置显示当前版本和服务端同意时间。

### 10.3 Relay

- 未到强制时间时保留兼容行为。
- 强制期后，已有 key 但无当前同意记录时返回 `legal_acceptance_required`。
- 合法用户正常通过，0 Token 用户仍由额度门拒绝；两个错误不能混淆。
- 被拒绝请求不调用上游模型、不写消费账本。

### 10.4 最终验收

- 全仓测试、类型检查、i18n、架构检查和生产构建通过。
- 最新 Windows 安装包在全新用户数据目录中完成登录与同意流程。
- 数据库可查询到准确用户、版本、服务端时间、来源、客户端版本和设备哈希。
- 协议升级演练不会删除本地任务，拒绝确认时不会开放商业模型。
- 正式启用强制门前已完成数据库备份和回滚演练。

- 对所有本地工作区文件实施端到端加密。
- 修改短信供应商、支付渠道、额度价格或模型目录。
