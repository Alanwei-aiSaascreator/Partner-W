# 七个助手专业任务工作台设计

**日期：** 2026-09-16  
**阶段：** 公司内测 1.0 功能完善  
**目标：** 为罗盘助手和六个专业助手补齐独立介绍、专业任务模板、资料输入、真实执行、成果交付与继续完善的完整入口。

## 一、范围与原则

本批次覆盖七个助手：罗盘助手、内容创作、拍摄剪辑、电商运营、高效办公、学习研究和生活家庭。每个助手提供四个专业模板与一个自定义任务入口，但共用一套任务工作台组件和数据契约。

模板只帮助用户把目标描述清楚。点击模板不会自动发送、调用模型或扣除积分；用户确认发送后继续走现有真实登录、授权、额度、模型、工具、消息和成果链路。

本批次不新增虚假评分、安装量、收益、云同步或“数据不出网”承诺，也不复制一套新的聊天、文件或计费系统。

## 二、用户体验

### 2.1 助手首屏

用户进入一个尚无消息的助手工作区时，首先看到：

1. 助手头像、名称、定位和一句能力说明；
2. 四个专业任务卡片；
3. 一个“自定义任务”入口；
4. 最近使用的模板；
5. 简短的资料提示，例如“可添加商品资料、参考文案或图片”。

已有消息的任务继续显示正常对话，不用欢迎页覆盖历史内容。

### 2.2 模板选择

点击任务卡片后，系统将结构化 Prompt 填入现有输入框，并聚焦第一个待填写位置。用户可以编辑、添加文件、切换模型后再发送。

如果输入框已经包含用户内容，模板切换必须先显示轻量确认，提供：

- 保留原内容并追加模板；
- 使用模板替换；
- 取消。

系统不得静默覆盖用户输入。

### 2.3 执行与成果

发送后复用现有真实运行阶段：读取资料、分析任务、生成成果、保存完成。原始工具调用继续收进可展开的技术详情。

文本回复完成后显示现有复制和继续对话能力；检测到文件成果时显示成果卡片，提供打开、另存为和打开目录。无文件成果时，“生成文件”动作只把明确的文件生成要求填回输入框，不伪造本地文件。

## 三、任务模板矩阵

| 助手     | 模板一   | 模板二   | 模板三     | 模板四     |
| -------- | -------- | -------- | ---------- | ---------- |
| 罗盘助手 | 目标拆解 | 执行计划 | 方案比较   | 综合分析   |
| 内容创作 | 选题策划 | 长文创作 | 短视频脚本 | 改写润色   |
| 拍摄剪辑 | 拍摄脚本 | 分镜清单 | 剪辑节奏   | 标题封面   |
| 电商运营 | 商品文案 | 活动策划 | 竞品分析   | 评价与客服 |
| 高效办公 | 文档撰写 | 表格分析 | 会议纪要   | PPT 大纲   |
| 学习研究 | 资料梳理 | 观点比较 | 学习计划   | 研究报告   |
| 生活家庭 | 旅行规划 | 家庭清单 | 购买比较   | 日程安排   |

每个模板包含：

- 稳定 ID；
- 所属助手 ID；
- 标题和一句话说明；
- 推荐资料提示；
- 可编辑 Prompt；
- 推荐输出结构；
- 文件成果建议；
- 后续完善建议。

模板 Prompt 必须明确输入空位和输出结构，但不能假定用户已经上传资料，也不能要求模型声称访问了不存在的文件。

## 四、组件与数据边界

### 4.1 模板目录

新增纯数据模块 `assistant-task-presets.ts`，导出类型化模板目录和按助手查询函数。目录不访问 React、存储、网络、模型或 Electron API，便于独立测试和后续扩展。

### 4.2 欢迎与模板组件

新增通用 `AssistantTaskWorkbench`，只负责渲染助手身份、模板卡片、最近使用和自定义入口。组件通过回调请求填充输入框，不直接修改消息、任务或额度状态。

### 4.3 输入框集成

现有聊天输入组件继续拥有草稿。新增一个轻量的模板草稿请求接口，由当前任务和助手共同定位。模板工作台发出请求后，输入组件决定追加、替换或取消，并沿用现有发送校验。

不得新建第二套发送按钮、模型选择器、文件上传器或语音入口。

### 4.4 最近使用

最近使用只保存模板 ID 和时间，按账号隔离，最多保留五条。不得保存 Prompt 正文、用户输入、文件路径、手机号、Token 或聊天内容。损坏或未知模板 ID 直接忽略。

### 4.5 助手身份映射

模板目录以现有助手稳定 ID 为真源。若运行时助手缺失或 ID 无法识别，则显示通用自定义任务入口，不根据名称模糊匹配到错误专业模板。

## 五、状态与数据流

```text
当前助手与任务
      ↓
模板目录查询 ──→ 助手欢迎页
      ↓ 点击模板
草稿请求 ──→ 输入框覆盖确认 ──→ 可编辑草稿
      ↓ 用户发送
现有额度/模型/文件校验 ──→ 真实消息与工具执行
      ↓
文本回复 + 已登记成果 ──→ 继续完善 / 复制 / 打开 / 另存为
```

模板不会直接写入消息数据库。只有用户点击现有发送按钮后，草稿才进入正常消息持久化路径。

## 六、异常处理

- 助手没有模板：显示通用任务输入，不阻塞聊天；
- 模板配置损坏：跳过单个模板并记录开发日志；
- 输入框已有内容：必须确认追加或替换；
- 余额不足、未激活或授权失败：沿用现有阻断，不因模板绕过；
- 推荐资料缺失：提示用户补充，但允许不带文件继续；
- 文件失效：显示现有失效状态并允许重新选择；
- 模型或工具失败：保留草稿、附件和失败信息，允许重试；
- 未生成文件：只展示文本结果，不显示虚假成果卡；
- 本地最近使用记录损坏：回退为空列表，不影响发送。

## 七、视觉与交互约束

- 沿用当前亮色中性表面和官网品牌渐变；
- 品牌渐变只用于当前模板、主操作和少量身份标识；
- 任务卡片以标题、说明、资料提示三级信息组成，不堆叠营销标签；
- 常见窗口宽度使用两列，窄窗口自动单列；
- 所有卡片、确认动作和自定义入口支持键盘操作与可见焦点；
- 遵守减少动态效果设置；
- 深色主题保持语义对比，不出现大片纯黑背景。

## 八、测试与验收

### 8.1 单元测试

- 七个助手各有四个唯一模板；
- 模板 ID、助手 ID、标题、Prompt 和输出结构完整；
- 未知助手返回空模板或通用入口；
- 最近使用按账号隔离、去重、有界且不保存敏感字段。

### 8.2 组件测试

- 七个助手显示正确身份与四个入口；
- 点击模板只请求填充，不自动发送；
- 空草稿直接填充，有草稿时出现追加、替换和取消；
- 自定义任务聚焦现有输入框；
- 历史消息存在时不显示覆盖式欢迎页；
- 键盘和窄窗口结构可用。

### 8.3 集成与 E2E

使用内容创作“短视频脚本”作为标准链路：选择模板、编辑字段、添加本地资料、发送真实任务、观察运行阶段、获得回复、保存文件成果、重启并恢复任务与成果。

同时为其余六个助手验证模板填充和助手隔离，防止模板串台。

## 九、交付顺序

1. 建立类型化模板目录和测试；
2. 建立账号隔离的最近使用记录；
3. 实现通用任务工作台；
4. 接入现有草稿和覆盖确认；
5. 补齐七个助手的模板与介绍；
6. 完善成果后续动作和异常状态；
7. 运行单测、类型检查、UI/i18n 检查和真实 E2E；
8. 构建新的 Windows 内测候选包并创建回滚标签。

## 十、非目标

- 不把团队、市场、悬赏、广场或创作者中心改成云端正式系统；
- 不在本批次实现账号画像云同步；
- 不新增模型供应商、支付方式或价格策略；
- 不用前端模板替代助手的系统 Prompt 或服务端权限；
- 不宣称每次任务都会产生文件；
- 不自动发送、自动扣费或自动访问未授权位置。

## 十一、完成定义

七个助手都拥有可区分、可编辑、不会误发送的专业任务入口；用户可以在原有聊天与文件体系中完成真实任务，并在产生文件时完成打开、另存和重启恢复。所有新增行为通过自动化验证，且不破坏当前已发布的登录、激活、额度、模型和文件闭环。
