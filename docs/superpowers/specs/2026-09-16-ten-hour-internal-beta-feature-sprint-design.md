# 荣盈魔方十小时内测功能冲刺设计

## 目标

在不伪装生产能力、不重写现有商业后端的前提下，把当前桌面端从“基础主路径 + 分散的内测页面”收口成一套可连续体验的公司内测 1.0 功能体。前六小时优先增加可见、可操作的新功能，后四小时用于关键回归、安全合并、Windows 内测包构建和基础彩排。

## 范围原则

- 核心商业链路继续使用真实服务：登录、激活、额度、模型调用、用量和发卡后台不得改成模拟数据。
- 团队、市场、悬赏、广场、创作者中心和成长中心继续使用本机持久化内测数据，但每个页面必须明确标记，不能让体验者误以为已经云端同步。
- 更新中心必须调用现有 Electron 更新接口；开发态或未配置更新源时如实说明，不展示虚假的下载或安装成功。
- 运营后台入口只负责打开配置好的受控后台地址，不在桌面客户端保存管理员密钥，也不把后台高权限能力复制进客户端。
- 新功能全部先写失败测试，再写最小实现；不为本次冲刺引入新的大型依赖。

## 官网视觉参考的吸收方式

本次改版以用户提供的 `AI-U盾` 静态稿为品牌参考，但不逐页照搬。保留以下设计语言：

- 页面以明亮中性底色为主，品牌渐变只用于 Logo、主操作和当前选中态；
- 左侧主导航使用图标加短标签，激活态有浅色底和清晰状态，不使用黑色侧栏；
- 顶部同时表达当前助手、运行状态和主题，不重复堆叠技术信息；
- 首次引导使用清楚的四步进度，用户随时知道当前阶段；
- 助手空状态使用一个角色、一句行动问题、少量推荐任务和固定底部输入框；
- 市场使用可扫描的助手条目，技能使用紧凑列表，积分页使用真实汇总和真实流水表格。

现有 React 组件、语义令牌、Lucide 图标和深浅主题继续作为工程基础。不会直接复制静态稿里的企业账号密码登录、虚构销量/评分、固定充值金额、联系人红点或“数据绝不出网”等尚未实现或不符合真实链路的内容。

配色采用“官网品牌色 + 当前产品语义色”的收敛方案：洋红到橙色渐变只作为品牌锚点；正文、表格、卡片和导航的 95% 面积继续使用中性色；成功、警告、危险和运行中状态使用独立语义色。所有文字对比度满足 WCAG 2.1 AA。

## 功能设计

### 1. 用途与个人目标可重新设置

账号设置新增“我的用途”区域，展示昵称、已选用途和自定义目标，并提供“重新设置”操作。用户进入编辑页后复用现有首次用途表单，保存时覆盖当前账号的本地画像，重新计算目标分析版本，并立即刷新首页推荐和助手排序；不要求退出登录或清除任务。

本次只保证按账号的本机持久化。跨电脑画像云同步保留为后续服务端能力，界面不得宣称已经同步。

首次登录和“重新设置”统一使用四步流程：

1. **你的角色**：企业负责人、运营、销售/招商、客服/售后、财务/人事或自定义；
2. **使用用途**：选择常见任务并填写真正想完成的目标；
3. **分配助手**：根据角色与用途解释推荐原因，用户可关闭不需要的助手；
4. **个性化**：确认昵称、回答详细程度和文件授权偏好，并回显前面输入。

画像结构升级时兼容现有 v1 用户：旧画像能直接进入工作台，进入重新设置后才补齐新字段，不强迫老用户重新走引导。

### 2. 真实升级入口

内测中心“自动升级”页面改为真实状态适配器：

- 检查更新调用 `window.clawwork.checkForUpdates()`；
- 有新版时显示版本号和下载操作；
- 下载调用 `downloadUpdate()` 并展示现有进度事件；
- 下载完成后允许调用 `installUpdate()`；
- 开发态、更新源不可用或失败时显示明确原因和重试入口；
- 不提供伪造的“回滚成功”。回滚能力只作为发布侧流程说明展示。

### 3. 真实运营后台入口

内测中心“运营后台”保留本机演示卡片，同时增加独立的“打开真实运营后台”卡片。地址来自构建环境变量 `VITE_ADMIN_CONSOLE_URL`，存在时通过浏览器外部打开；缺失时按钮禁用并说明需要在内测构建中配置。客户端不携带 service-role key，登录与权限继续由 Supabase Auth 和 `admin_*` RPC 控制。

### 4. 平台模块形成可演示闭环

现有六个平台模块不扩展为云端系统，而是补齐最短闭环和一致反馈：

- 团队：创建或加入、查看邀请码和成员、退出团队；
- 助手市场：搜索、安装、显示已安装状态；
- 悬赏：发布、领取、提交；
- 广场：发布、点赞、评论；
- 创作者中心：创建、改名、发布或下架模板；
- 成长中心：签到、积分、等级和徽章反馈。

所有成功操作产生统一的轻提示，并写入本机内测事件日志。空输入不得创建占位数据；破坏性动作需要二次确认。

### 4.1 工作台与助手首页

工作台采用官网稿的低干扰布局：全局导航保持窄而稳定，助手与任务列表作为第二层导航，内容区只突出当前任务。助手首次打开时显示角色形象、“今天想完成什么”、不超过四个真实可执行的推荐任务和底部输入框；开始对话后空状态让位于消息流，不保留无用装饰。

顶部“运行状态”必须区分本地工作区、荣盈中转服务和所选云模型，不能用“数据不出内网”概括整个链路。文件只在用户主动选择后读取，模型请求仍会通过荣盈 Relay 发往所选模型供应商。

### 4.2 市场、技能与积分页面

- 助手市场沿用大块可扫描条目，但只显示真实或明确标记为内测的安装量、认证和价格；已安装助手提供“立即使用”。
- 技能页面使用紧凑列表，展示技能范围、启用状态和所属助手；不使用同尺寸大卡片墙。
- 积分与充值页顶部展示剩余额度、本月真实消耗和本月真实充值，进度条继续表达“剩余”而不是“已使用”；充值档位来自商业接口，流水来自真实账本。

### 5. 本机内测埋点改为真实交互统计

将当前固定 seed 数字改成“初始样例 + 本次真实交互增量”。记录启动、登录、激活、聊天、文件导入、成果生成和平台模块操作的事件类型、时间与必要的非敏感元数据。分析页显示事件总量、最近事件和分类统计。不得记录提示词正文、文件正文、完整手机号、卡密或认证令牌。

### 6. 账户、设备与文件授权中心

在账号设置中集中展示当前登录账号、激活权益、剩余额度、本机设备摘要和任务文件授权说明。用户可以查看当前任务已经主动添加的文件与文件夹、撤销不再需要的文件夹授权，并从这里进入隐私政策、服务条款和数据权利页面。

撤销授权只移除应用保存的授权记录，不删除用户磁盘上的任何文件，也不删除已经生成的任务成果。所有工作区外文件访问继续遵循逐次说明和用户确认。

## 数据流与边界

```text
账号设置 ──保存──> 当前账号 onboarding profile ──事件──> App 刷新首页推荐

更新中心 ──IPC──> Electron main updater ──HTTPS──> 自有更新源

运营入口 ──外部浏览器──> 管理后台 ──Supabase Auth/RPC──> 生产后台

内测模块 ──动作──> localStorage 版本化 store ──脱敏事件──> 本机分析页
```

本地内测 store 从 `v1` 升级时必须兼容旧数据；解析失败回退到安全默认值，但不得删除其他账号或真实任务数据。

## 错误处理

- 用途保存失败时保留编辑内容，不改变现有画像。
- 更新检查、下载或安装失败时保留当前稳定版本，并允许重试。
- 后台地址未配置时禁止打开空白页或错误 localhost 地址。
- localStorage 不可写时功能仍可当前会话使用，并显示“本次修改无法持久保存”。
- 所有平台模块操作必须幂等或防止连续重复点击产生重复记录。

## 测试与验收

1. 画像编辑测试：不同账号隔离；保存后首页推荐立即变化；取消不修改原数据。
   同时覆盖 v1 画像迁移、四步返回、自由输入参与推荐和助手开关持久化。
2. 更新适配测试：无更新、有更新、检查失败、下载失败、下载完成、请求安装六条路径。
3. 后台入口测试：有 URL 时只外部打开；无 URL 时不可点击；前端产物不包含高权限密钥。
4. 平台闭环测试：六个模块的核心动作、空输入、重复点击和本机恢复。
5. 埋点测试：操作增加对应计数；敏感字段不会进入事件载荷。
6. 最后修正文件成果闭环 E2E，运行定向测试、类型检查、生产构建和全量测试；全部通过后才合并与打包。
7. 视觉验收覆盖 1440×900 和常见窗口化尺寸、浅色与深色、键盘焦点、减少动态效果，并逐屏检查登录、四步引导、助手空状态、市场、技能和积分页。

## 十小时交付门槛

- 第 1–6 小时：上述新增功能按测试优先方式完成，并通过对应定向测试。
- 第 7 小时：修正文件闭环 E2E，验证文件导入、防冲突命名、成果保存和重启恢复。
- 第 8 小时：运行全量测试、类型检查和生产构建，修复本次改动造成的回归。
- 第 9 小时：建立桌面与后台合并前回滚标签，完成安全合并并复跑关键测试。
- 第 10 小时：构建 Windows 内测安装包，验证安装、启动、登录、激活和真实对话的基础路径。若缺少全新手机号或干净电脑，必须将对应步骤记录为外部待验收，不能宣称已经完成实机全流程。

不在本次十小时范围内：六个平台模块真实云端化、管理员 MFA、复杂价格审批、退款、万人并发、正式合规认证和跨境数据法律结论。
