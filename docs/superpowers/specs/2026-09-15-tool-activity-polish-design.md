# 工具活动展示与调用收敛设计

日期：2026-09-15  
状态：待用户复核

## 1. 背景与问题

当前对话页会把底层工具调用以独立大卡片连续展示。一次本机文件任务可能出现多次 `ls` 和 `exec`，技术过程占据大部分视口，用户很难快速判断任务正在做什么、是否成功，以及最终结果在哪里。

这包含两个不同问题：

1. **展示噪声**：每个底层调用拥有相同视觉权重，重复动作没有合并。
2. **执行冗余**：助手可能在未明确目标目录时逐层、重复扫描，增加等待时间和模型消耗。

本轮同时处理两层，但不删除原始调用记录，也不降低失败和授权操作的可见性。

## 2. 目标

- 用户默认只看到一条简洁的工具活动摘要。
- 执行期间只突出当前动作，而不是铺开全部历史动作。
- 相同工具或相同语义动作按数量合并。
- 用户可以展开查看每次调用的名称、参数、结果、状态和耗时。
- 失败、等待授权和产生文件变更的动作保持明显。
- 文件类助手优先确认目标范围，再批量读取，减少重复目录扫描。

## 3. 不在本轮范围

- 不修改网关工具协议或数据库中的原始工具调用结构。
- 不隐藏或删除调用历史。
- 不建设复杂的工作流可视化、调试控制台或性能分析页。
- 不依赖模型准确生成用户可见的工具标题。

## 4. 推荐交互

### 4.1 默认状态

一轮回复中的工具调用默认折叠为一条紧凑活动条：

```text
✓ 已整理电脑文件 · 10 个步骤 · 32 秒        查看详情 ›
```

执行中显示：

```text
◌ 正在整理电脑文件 · 第 6/10 步
  正在查看 Documents 文件夹
```

总步骤数未知时只显示已完成数量，不伪造总数。

### 4.2 展开状态

展开后先显示语义分组，再允许继续查看单次调用：

```text
查看文件夹 × 8
执行操作 × 2
```

每组默认折叠。展开组后显示单次调用；再展开单次调用才显示参数和结果。原始命令名作为次级技术信息保留，例如 `查看文件夹 · ls`。

### 4.3 重要状态

- **失败**：摘要使用危险色并显示失败数量；失败组自动展开到单次调用，但参数和长结果仍折叠。
- **等待授权**：单独显示，不与普通完成步骤合并。
- **文件变更**：创建、修改、移动文件时显示目标文件或目录的用户可读名称。
- **纯读取**：重复目录读取可以合并，不逐张占据主对话。

## 5. 语义映射

界面通过本地确定性规则把工具名映射到少量用户语言，不依赖模型临时命名：

| 底层工具                  | 用户可见动作 |
| ------------------------- | ------------ |
| `ls`、目录列表类          | 查看文件夹   |
| `read`、文件读取类        | 读取文件     |
| `search`、`find`、`rg` 类 | 搜索资料     |
| `exec`、shell 类          | 执行操作     |
| 写入、补丁类              | 修改文件     |
| 浏览器、联网类            | 查询网页     |
| 未识别工具                | 使用工具     |

分组键由“语义动作 + 状态”组成，避免把成功与失败混在同一计数中。映射无法识别时安全退化为原始工具名。

## 6. 组件与数据流

新增纯函数层，将原始 `ToolCall[]` 转换为展示模型：

```text
ToolCall[]
  → 语义分类、状态和耗时计算
  → ToolActivitySummary
  → 紧凑摘要 / 分组详情 / 单次详情
```

- `ToolActivitySummary`：统一承载历史消息和流式消息的工具展示。
- `ToolActivityGroup`：呈现合并后的语义动作与数量。
- `ToolCallCard`：保留为最深层技术详情，不再作为默认主视图。
- 历史消息与流式消息共享同一套展示逻辑，避免执行中与完成后的界面跳变。

流式阶段只更新展示模型，不修改持久化数据。任务完成后，原始 `ToolCall[]` 仍按现有逻辑保存。

## 7. 调用策略收敛

在罗盘助手及六个专业助手的共同操作约束中增加文件探索规则：

1. 用户未指定范围时，先请求选择或关联目标文件/目录。
2. 已有明确目录时，一次列出必要层级，避免对同一路径重复 `ls`。
3. 先根据文件名和类型筛选候选，再读取内容。
4. 能批量读取时不逐文件重复调用。
5. 完成任务所需信息已足够时停止探索，直接交付结果。
6. 不声称访问了未经用户授权或未实际读取的位置。

该约束降低冗余概率，但界面仍必须正确处理任意数量的工具调用。

## 8. 可访问性与视觉规则

- 摘要条和分组均为键盘可操作的折叠控件。
- 状态不能只依赖颜色，同时提供图标和文字。
- 动画沿用现有折叠动效，并尊重系统减少动态效果设置。
- 长参数和结果限制高度，可滚动查看，不撑满页面。
- 手机或窄窗口下保持单列，不横向溢出。

## 9. 验收标准

1. 十次成功工具调用默认只占一条摘要，不显示十张大卡片。
2. 八次 `ls` 和两次 `exec` 展开后显示为两个语义组及对应数量。
3. 用户可以继续展开查看全部十次原始调用及其结果。
4. 流式执行时只突出当前动作，已完成动作进入汇总。
5. 任意失败调用在折叠状态下也能被识别，并显示失败数量。
6. 历史消息与流式消息使用一致的汇总结构。
7. 文件类公共提示明确要求先确定范围、批量读取并避免重复扫描。
8. 不改变工具调用持久化、计费和模型执行行为。

## 10. 测试策略

- 纯函数测试：语义映射、分组、状态优先级、耗时计算和未知工具回退。
- 组件测试：默认折叠、展开分组、展开单次调用、失败自动提示。
- 流式测试：当前调用切换时不产生多张默认卡片。
- 回归测试：历史消息仍能查看参数和结果；现有工具调用数据不变。
- 实机检查：用包含重复 `ls` 与 `exec` 的模拟任务验证窄窗口和普通窗口布局。
