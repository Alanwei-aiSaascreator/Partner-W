## 设计

### 1. 设备身份只接受 Ed25519 配对

`isUsableIdentityPair` 必须同时满足：私钥可解析、公钥可解析、两者的 `asymmetricKeyType` 均为 `ed25519`、探针签名能够由公钥验证。RSA、EC、坏 PEM、错配 Ed25519 都返回 `false`。身份轮换仍沿用现有流程。

测试覆盖：有效 Ed25519；错配 Ed25519；匹配 RSA；匹配 EC；坏 PEM。

### 2. PPT 同时执行单 deck 与单消息累计预算

保留单 deck 最大 200 页，同时在开始生成任何文件前，对本条消息解析出的全部 deck 累计页数做预检。累计页数超过 200 时整条消息拒绝生成，避免部分文件已经落盘后才失败。失败继续使用结构化 `slidegen` 错误，不引入新 UI。

现有恢复文本预算的说明改为引用真实常量或删除错误的 `100,000` 推导，不能再用失真的字符上限证明页数安全。

测试覆盖：单 deck 200 通过；201 拒绝；两个 deck 累计 200 通过；`120 + 81` 在产生任何文件前拒绝。

### 3. 技能探测以“任何完整成功”为优先

保留当前短时间多次探测，但不再用“最后发出的请求先结束”作为结算条件。每轮维护在途计数与 epoch：

- 任一请求返回完整合法报告，立即采用并结束本轮；
- 失败或缺项只记录，不覆盖已有成功；
- 所有请求结束仍无完整结果，或总超时到达，才结算为 `unknown`；
- 卸载、换网关或新 epoch 后，旧请求不得写回。

测试覆盖：末次先失败、早次后成功；末次缺项、早次完整；成功后旧失败不能覆盖；总超时；epoch 切换。

### 4. 助手目录 `loading` 不得执行路由

三个新入口统一使用三态判据：

- `ok`：继续执行；
- `missing`：拒绝并显示现有“助手不在本机”；
- `loading`：不切换、不创建 pending 任务、不写错误 agentId；触发/等待一次目录刷新，刷新成功后重新判定，失败则显示可重试错误。

本次只保证行为正确，复用现有提示组件和文案，不重做界面。

测试覆盖：loading 时零副作用；刷新后 ok 才继续；刷新后 missing 拒绝；刷新失败拒绝且可重试。

### 5. 一次创建流程固定原始 gatewayId

创建自定义助手或选择推荐助手时，由调用方在流程开始处捕获 `gatewayId` 并显式传给后续回调。异步等待后允许读取该网关的最新目录，但不得重新读取“此刻的默认网关”作为路由目标。

测试覆盖：在创建等待期间默认网关从 A 切到 B，校验、选择和 pending 任务仍全部使用 A；普通未切换路径保持不变。
