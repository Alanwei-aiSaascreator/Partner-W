# 荣盈魔方登录到工作台体验设计

日期：2026-09-15
状态：已确认设计方向，待静态 HTML 评审
适用范围：基本盘 Demo 的首次登录、用途选择、权益激活、服务准备和正式工作台入口

## 1. 目标

把当前单一、空旷的手机号登录页改造成一条连贯的首次使用体验，使普通 Windows 用户能够理解荣盈魔方是什么、为什么需要登录、接下来会发生什么，并在激活后尽快看到真实工作台。

本轮交付先制作一份可交互的静态 HTML，用随机手机号、验证码、额度和任务数据模拟完整流程，不接真实接口。静态稿通过后再映射到真实桌面端源码。

## 2. 已确认的核心决策

- 登录首屏采用“双区品牌入口”：左侧建立产品价值和本机安全感，右侧专注手机号验证。
- 登录后选择“使用目的”，不选择老板、员工等身份，也不引入游戏化角色。
- 首次使用流程采用混合式结构：登录、用途选择和激活使用简洁引导；激活成功后立即进入正式工作台，服务继续在对话区准备。
- 色彩采用分层品牌系统：深色用于主导航和品牌区，粉紫橙用于关键动作与状态，内容区保持米白、白色和深色文字。
- 品牌小人用于登录、用途选择和系统加载三个首次使用阶段，进入正式工作台后退出，不长期占用工作区。
- 默认模型为 `deepseek-v4-flash`，模型选择器、回复标签和用量明细必须一致。
- 所有额度进度均表达“剩余”，不表达“已使用”。

## 3. 设计原则

### 3.1 先让用户理解，再要求操作

登录页左侧只回答三个问题：这是什么、能做什么、数据是否安全。右侧只保留当前步骤的表单和一个主要动作。

### 3.2 尽早显露真实产品

激活完成后不继续显示全屏技术加载页。正式三栏工作台立即出现，用户可以浏览导航、助手列表和主体结构；仅对话输入暂时锁定，并在原位置显示准备进度。

### 3.3 用户语言优先

加载阶段使用“连接服务、准备模型、加载助手、完成”等用户可理解的描述，不在主界面暴露 Gateway、进程、端口、容器等技术术语。诊断信息只进入可展开的详情区域。

### 3.4 一个页面只有一个主动作

登录页强调“获取验证码”或“连接工作台”，用途页强调“继续”，激活页强调“激活并进入”，准备页强调进度或“重试”。次级动作保持低对比度。

## 4. 视觉系统

### 4.1 参考与取舍

视觉参考：`F:/edge doenloads/royin-usb-login-v5-final.html`。

保留：

- 深色品牌区与明亮操作区的对比关系。
- 洋红、紫色、橙红形成的品牌识别色。
- 设备服务状态、安全通道和端侧数据保护等信任提示。
- 品牌小人的鼠标跟随、自然眨眼和验证码捂眼交互。

调整：

- 降低广告式大标题的面积，优先说明真实产品用途。
- 减少轨道、光晕和漂浮装饰，保证低配 Windows 设备上的稳定表现。
- 渐变不铺满正式工作台，不用于正文卡片和普通输入框。
- 不承诺尚未稳定实现的“私人知识库已挂载”等能力。

### 4.2 配色角色

- 品牌深色：`#090711`、`#13131C`、`#1A1A25`。
- 内容背景：`#F4F3EF`，主要容器为 `#FFFFFF`。
- 主文字：`#16131D`，次级文字不低于可读对比度。
- 品牌强调：洋红 `#E11A72`、红 `#FF3658`、橙 `#FF7A34`、紫 `#8D28DF`。
- 功能蓝紫可保留用于普通选中状态，但不与品牌渐变同时抢占视觉焦点。
- 渐变总使用面积控制在页面的约 5%–8%，只用于登录主按钮、启动进度、关键成功反馈和少量品牌标记。

### 4.3 形态与密度

- 页面保持桌面软件的精确结构，不做移动端放大卡片。
- 常规卡片圆角约 12px，按钮约 8px，输入容器不超过 16px。
- 主界面使用稳定的三栏结构：主导航、助手与任务栏、内容工作区。
- 避免层层嵌套卡片、全屏大标题和大面积纯装饰留白。

## 5. 完整页面流程

### 5.1 手机号登录

左侧品牌区包含：

- 荣盈魔方与 AI U 盘的品牌标识。
- 一句产品价值表达，例如“插入设备，继续你的 AI 工作”。
- 三到四个简短信任点：插入即用、本机工作、账号同步、端侧数据保护。
- 品牌小人及设备状态“设备服务正常，等待验证”。

右侧登录区包含：

- 标题“登录荣盈魔方”。
- 手机号输入、验证码输入、协议勾选。
- 获取验证码、倒计时、格式错误和验证码错误状态。
- 登录成功反馈，然后自动进入用途选择。

角色交互：

- 默认状态自然眨眼，眼睛低幅度跟随鼠标。
- 聚焦手机号时角色轻微转向输入区。
- 聚焦验证码时角色抬手捂眼，离开验证码输入框后放下。
- 验证成功时出现短暂确认动作，随后开始页面转场。
- 系统启用减少动态效果时，关闭鼠标追踪和位移动画，只保留静态状态切换。

### 5.2 选择使用目的

主问题使用“你主要想用它做什么？”，并说明“以后可以随时修改，这只影响首次推荐”。

用途包含：

- 内容创作：选题、文案、脚本。
- 电商运营：商品、活动、客服。
- 生活家庭：规划、清单、日常事务。
- 高效办公：文档、表格、会议。
- 学习研究：资料整理、分析、总结。
- 拍摄剪辑：脚本、分镜、剪辑规划。

选中用途后，角色用轻量表情或姿态回应；页面同时预告将推荐的默认助手。无需用户再选择真实身份。

### 5.3 激活权益

激活页延续同一引导外壳，包含：

- 激活码输入与清晰的格式提示。
- 激活码会绑定当前手机号账号的说明。
- 成功后的权益摘要：套餐名称、剩余点数、有效状态。
- 已激活用户提供“直接进入工作台”。
- 激活失败保留输入内容，给出可恢复的错误提示。

成功后进入正式工作台，不停留在独立的全屏加载页。

### 5.4 正式工作台内的服务准备

工作台三栏框架立即可见：

- 左侧主导航可浏览，但尚未开放的延后模块不显示。
- 中间展示罗盘助手与六个专业助手。
- 主内容区显示大型准备面板，输入框暂时禁用。

准备阶段只显示四个语义步骤：

1. 连接 AI 服务。
2. 准备默认模型。
3. 加载专业助手。
4. 工作台已就绪。

进度条展示总体完成度和当前阶段。超过约 90 秒后，面板增加：

- 为什么可能需要更久的简短说明。
- “重新尝试”主操作。
- “查看详情”次操作，用于显示诊断信息。
- 不关闭主框架，不要求用户执行开发命令。

品牌小人在此阶段作为状态角色出现：观察、工作中、完成或需要帮助。准备完成后角色退出，面板平滑切换为助手欢迎页。

### 5.5 助手欢迎与正式任务

每个助手必须拥有独立欢迎内容，而不是同一个主模型聊天框换名称：

- 独立名称、简短定位和能力边界。
- 三到四个热门任务入口。
- 与助手匹配的输入框占位文案。
- 推荐模型说明，但用户可切换模型。

罗盘助手负责理解任务并推荐专业助手；专业助手进入后直接服务对应用途。

默认显示 `deepseek-v4-flash`。用户未切换时，首次回复标签也必须显示 `deepseek-v4-flash`；切换后请求参数、回复标签、顶部模型名和账单明细一起更新。

工具调用采用语义化的合并展示，例如“正在整理文件”“已读取 6 个文件”“已生成结果”，不连续堆叠 `ls`、`exec` 等底层命令。详细调用可在单个可展开区域查看。

### 5.6 额度、结果和继续使用

- 顶部固定显示剩余点数，不把“使用比例”作为主信息。
- 用量页进度条代表剩余额度，并明确文字“本周期还可使用”。
- 每次回复后显示本次模型、Token 用量和实际扣费。
- 任务完成后提供结果位置、打开目录或复制结果等下一步。
- 重启或换电脑登录后恢复账号权益、历史任务摘要和最近使用助手。

## 6. 静态 HTML 评审稿范围

静态稿需要允许用户顺序体验：

1. 输入任意符合格式的手机号。
2. 获取随机六位验证码，并可直接填入演示验证码。
3. 选择一个使用目的。
4. 输入演示激活码并查看随机权益数据。
5. 进入工作台并观看加速模拟的准备进度。
6. 进入对应助手欢迎页。
7. 选择模型并发送一条演示任务。
8. 查看模拟的真实回复、工具活动、剩余额度和本次消耗。
9. 切换六个专业助手，查看各自独立介绍和快捷任务。

静态稿不得调用真实短信、支付、模型或文件系统，不保存用户输入的真实敏感数据。页面明确标注为“交互设计预览”。

## 7. 验收标准

- 登录页不再是孤立居中的单一表单，并能在 5 秒内说明产品价值和登录原因。
- 从登录到正式工作台的每一步只有一个清晰主动作。
- 激活成功后立即看到正式工作台框架，不被全屏加载阻断。
- 服务准备期间有明确进度、当前阶段、超时说明和重试入口。
- 品牌角色只出现在首次引导阶段，交互与输入状态一致，不影响可访问性。
- 六个专业助手拥有不同的定位、热门任务和输入提示。
- 默认模型、实际执行模型、回复标签和账单名称一致。
- 所有额度进度表达剩余量。
- 整体视觉能够识别为同一产品，同时满足长时间桌面使用的可读性与克制度。

## 8. 延后范围

团队、市场、悬赏、广场、创作者中心、游戏化成长和复杂社交功能不进入本次静态评审稿。真实短信、支付、模型调用、文件读写和跨设备同步继续由现有真实链路负责，本轮不修改其业务实现。
