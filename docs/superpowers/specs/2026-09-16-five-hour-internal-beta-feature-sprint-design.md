# 荣盈魔方五小时内测功能冲刺设计

## 目标

在不伪装生产能力、不重写现有商业后端的前提下，把当前桌面端从“基础主路径 + 分散的内测页面”收口成一套可连续体验的公司内测 1.0 功能体。前三小时优先增加可见、可操作的新功能，后两小时用于关键回归、合并和 Windows 内测包构建。

## 范围原则

- 核心商业链路继续使用真实服务：登录、激活、额度、模型调用、用量和发卡后台不得改成模拟数据。
- 团队、市场、悬赏、广场、创作者中心和成长中心继续使用本机持久化内测数据，但每个页面必须明确标记，不能让体验者误以为已经云端同步。
- 更新中心必须调用现有 Electron 更新接口；开发态或未配置更新源时如实说明，不展示虚假的下载或安装成功。
- 运营后台入口只负责打开配置好的受控后台地址，不在桌面客户端保存管理员密钥，也不把后台高权限能力复制进客户端。
- 新功能全部先写失败测试，再写最小实现；不为本次冲刺引入新的大型依赖。

## 功能设计

### 1. 用途与个人目标可重新设置

账号设置新增“我的用途”区域，展示昵称、已选用途和自定义目标，并提供“重新设置”操作。用户进入编辑页后复用现有首次用途表单，保存时覆盖当前账号的本地画像，重新计算目标分析版本，并立即刷新首页推荐和助手排序；不要求退出登录或清除任务。

本次只保证按账号的本机持久化。跨电脑画像云同步保留为后续服务端能力，界面不得宣称已经同步。

### 2. 真实升级入口

内测中心“自动升级”页面改为真实状态适配器：

- 检查更新调用 `window.clawwork.checkForUpdates()`；
- 有新版时显示版本号和下载操作；
- 下载调用 `downloadUpdate()` 并展示现有进度事件；
- 下载完成后允许调用 `installUpdate()`；
- 开发态、更新源不可用或失败时显示明确原因和重试入口；
- 不提供伪造的“回滚成功”。回滚能力只作为发布侧流程说明展示。

### 3. 真实运营后台入口

内测中心“运营后台”保留本机演示卡片，同时增加独立的“打开真实运营后台”卡片。地址来自构建环境变量 `VITE_ADMIN_CONSOLE_URL`，存在时通过浏览器外部打开；缺失时按钮禁用并说明需要在内测构建中配置。客户端不携带 service-role key，登录与权限继续由 Supabase Auth 和 `admin_*` RPC 控制。

### 4. 平台模块形成可演示闭环

现有六个平台模块不扩展为云端系统，而是补齐最短闭环和一致反馈：

- 团队：创建或加入、查看邀请码和成员、退出团队；
- 助手市场：搜索、安装、显示已安装状态；
- 悬赏：发布、领取、提交；
- 广场：发布、点赞、评论；
- 创作者中心：创建、改名、发布或下架模板；
- 成长中心：签到、积分、等级和徽章反馈。

所有成功操作产生统一的轻提示，并写入本机内测事件日志。空输入不得创建占位数据；破坏性动作需要二次确认。

### 5. 本机内测埋点改为真实交互统计

将当前固定 seed 数字改成“初始样例 + 本次真实交互增量”。记录启动、登录、激活、聊天、文件导入、成果生成和平台模块操作的事件类型、时间与必要的非敏感元数据。分析页显示事件总量、最近事件和分类统计。不得记录提示词正文、文件正文、完整手机号、卡密或认证令牌。

## 数据流与边界

```text
账号设置 ──保存──> 当前账号 onboarding profile ──事件──> App 刷新首页推荐

更新中心 ──IPC──> Electron main updater ──HTTPS──> 自有更新源

运营入口 ──外部浏览器──> 管理后台 ──Supabase Auth/RPC──> 生产后台

内测模块 ──动作──> localStorage 版本化 store ──脱敏事件──> 本机分析页
```

本地内测 store 从 `v1` 升级时必须兼容旧数据；解析失败回退到安全默认值，但不得删除其他账号或真实任务数据。

## 错误处理

- 用途保存失败时保留编辑内容，不改变现有画像。
- 更新检查、下载或安装失败时保留当前稳定版本，并允许重试。
- 后台地址未配置时禁止打开空白页或错误 localhost 地址。
- localStorage 不可写时功能仍可当前会话使用，并显示“本次修改无法持久保存”。
- 所有平台模块操作必须幂等或防止连续重复点击产生重复记录。

## 测试与验收

1. 画像编辑测试：不同账号隔离；保存后首页推荐立即变化；取消不修改原数据。
2. 更新适配测试：无更新、有更新、检查失败、下载失败、下载完成、请求安装六条路径。
3. 后台入口测试：有 URL 时只外部打开；无 URL 时不可点击；前端产物不包含高权限密钥。
4. 平台闭环测试：六个模块的核心动作、空输入、重复点击和本机恢复。
5. 埋点测试：操作增加对应计数；敏感字段不会进入事件载荷。
6. 最后修正文件成果闭环 E2E，运行定向测试、类型检查、生产构建和全量测试；全部通过后才合并与打包。

## 五小时交付门槛

- 前三小时：上述新增功能完成并通过定向测试。
- 第四小时：修正文件闭环 E2E、建立桌面与后台合并前回滚标签并完成安全合并。
- 第五小时：关键回归、生产构建和 Windows 内测安装包；如果全量测试超过时间窗口，必须明确记录尚未完成的验证，不能把安装包标记为最终发布版。

不在本次五小时范围内：六个平台模块真实云端化、管理员 MFA、复杂价格审批、退款、万人并发、正式合规认证和跨境数据法律结论。
