## 一、HTML：应用内真渲染 `.html`

**判据**：导入一份 `.html` → 点开看到**排版好的页面**，**脚本没跑**、**外链一张都不加载**。

两道锁，缺一不可：

| 层     | 做法                                                                                                           | 为什么不能省                                                                                                |
| ------ | -------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 主进程 | 在 `<head>` **最前面**注入 CSP：`default-src 'none'; style-src 'unsafe-inline'; img-src data:; font-src data:` | 内容层的锁：就算哪天 `sandbox` 被改松，外联与脚本仍然断                                                     |
| 渲染层 | `<iframe sandbox="" srcDoc={...}>`（**不给** `allow-scripts` / `allow-same-origin`）                           | 容器层的锁：给了 `allow-same-origin`，iframe 里的脚本就能摸到父窗口的 `window.clawwork`（= 整台应用的 API） |

- `previewKindFor` 加 `.html/.htm`（预览类型的**唯一真源**）；
- 上限 **4 MiB**（`MAX_HTML_PREVIEW_BYTES`）：超限回 `unsupported` ⇒ 退化成**文本视图**（不是报错、也不是白屏）；
- 已知边界（写进代码注释）：相对路径引用的图片/CSS 不会加载；非 UTF-8（GBK）会乱码（与既有文本视图同一口径）。

## 二、PDF：助手能产出 `.pdf`

**判据**：对助手说"做一份 PDF 报告" → 产物里出现 `.pdf` → 点开是**阅读器**、中文正常、分页合理。

**为什么是 printToPDF 而不是引库**：中文 PDF 的难点是字体。引库要内嵌 CJK 字体（包体 +15~20 MB，商用授权要单独谈），不内嵌就是别人机器上的方块字。Electron 自带 Chromium 的打印管线 —— 用户自己"用浏览器打印成 PDF"就是这条路，中文靠系统字体天然可用，**零新依赖、零字体分发**。

- 内容模型与 docx **同构**：`{"kind":"pdf","title":…,"sections":[{heading?,paragraphs[],bullets[]}]}`；上限沿用 docx 那一档（40 小节 / 每节 60 段 / 单段 2000 字）；
- 渲染：`buildPdfHtml`（纯函数、可单测）→ 隐藏窗口（`javascript:false` + `sandbox` + 无 preload）→ `data:` URL → `printToPDF(A4)` → Buffer → 走**现成的** `saveArtifactFromBuffer`；
- **不落任何临时文件**（内容走 data URL）；
- 逐字转义：助手写的 `<script>` 只是一个尖括号；
- 生成的 HTML **不许有任何外部引用**（内联样式 + 系统字体）——有测试专门钉这一条。

**连锁改动**：`DOCGEN_KINDS` / `DOCGEN_OUTPUT_BY_KIND` / `DocgenPdfRequest` / `parseSections`（docx 与 pdf 共用一份校验）→ `render.ts` 的 `never` 护栏**编译期**逼出分支 → 技能正文加 pdf 段并删掉"PDF 做不到" → 操作契约与 `PRESET_PROMPT_VERSION`（`2026-09-24.2` → `2026-09-26.1`）同步。

⚠️ **没做的（刻意）**：技能与提示词都只在**文件缺失**时才写（`bundled.ts:203-206` 明写"这是另一个决定"）⇒ **已发出的盘不会自动拿到新版技能/契约**。真机验收时手工刷新了那一台，并把"老盘怎么升级"记成 0.0.36 头号事项。

## 三、产物跨对话：两半

用户的反馈是"产物列表跨对话记忆"。查清后发现是**两件事**，分开做：

### 3A. 人看得见 —— 右侧「产物」面板加折叠的「历史产物」区

- 数据层本来就支持全库（`listArtifacts()` 不传参 = 全库），缺的是**这一页**（右侧面板只查当前会话）；
- 现在两条查询各司其职：当前会话的进**主列表**（行为不变），其余进**默认折叠**的「历史产物」区：按来源会话分组、时间倒序、**最多 50 条**，超出的**说出来**（"还有 N 条，去「文件」里看"）；
- 点分组标题 = **跳回来源会话**（与「文件」视图同一套动作）；
- 没有历史 ⇒ **整块不渲染**（不给新用户看一个空框）；
- 分组/排序/上限在纯函数 `lib/artifact-history.ts` 里 ⇒ 跨会话语义**可单测**。

### 3B. 助手知道 —— 新会话首轮注入 `<artifacts-index>`

- 触发：`pendingNewTask` 非空（= 这一轮在开一个新会话）；只给**首轮**，后续靠对话历史；
- 内容：最多 **20 条 / 30 天内的**（文件名 · 来源会话 · 日期 · 大小），**只给索引不给内容** —— 要内容得用户 `@`，那是刻意的成本闸门；
- 净化：文件名是**敌意输入**（能塞换行与 `<script>`，而这段要进提示词）⇒ 去控制字符、压空白、截断 120 字、转义尖括号；有一条测试专门带**伪造的结束标记**验证它逃不出自己的段；
- 无可列 ⇒ 返回 `null`（发空块会被模型读成"这块盘上什么都没有"）；失败**不挡发送**。

| HTML 预览 | 主进程 7 条（CSP 位置/大小上限/大小写）+ 渲染层 4 条（sandbox 两个权限都不许有、HTML 不许进应用文档） | 4 杀 + 1 对照                            |
