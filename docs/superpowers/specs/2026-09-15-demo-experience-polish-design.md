# 荣盈魔方 Demo 体验收口设计

**日期：** 2026-09-15

**设计依据：** 用户实机反馈、荣盈魔方现有主路径、`docs/prototypes/rongying-cube-full-flow-static.html`

**目标用户：** 第一次接触或不熟悉 AI 工具的 Windows 用户

## 1. 目标

本轮只收口基本盘 Demo 的可信体验，不扩展市场、团队、悬赏、社群、创作者中心或游戏化模块。

用户应能在不理解 Gateway、Agent、Provider 或 Token 等内部概念的前提下完成以下流程：

```text
手机号登录
→ 选择用途
→ 输入激活码
→ 立即看到完整工作台框架
→ 等待 AI 对话在工作台内完成准备
→ 明确选择本机文件访问范围
→ 选择一个有清晰能力说明的助手
→ 使用默认 DeepSeek V4 Flash 完成真实任务
→ 确认回复模型、余额和本次消耗一致
→ 重启或换电脑后继续使用
```

## 2. 核心设计原则

1. **先进入，再准备。** 登录、用途和激活完成后立即展示主框架，不用全屏启动页长期阻挡用户。
2. **能力必须可见。** 文件访问范围、助手能力、正在使用的模型和任务产物都应直接显示。
3. **状态必须一致。** 模型选择器、实际网关请求、回复标签和用量记录使用同一模型标识。
4. **隐私边界必须明确。** 产品不能暗示会扫描整台电脑，只能处理用户明确授权的文件或文件夹。
5. **进度方向统一。** 额度进度条表示剩余量，已用量只作为次级数字和明细出现。
6. **错误可以恢复。** 网络、模型目录或助手准备失败时提供原因、当前可用范围和重试入口。

## 3. 信息架构

主工作台保留现有三层结构：

- 56px 全局导航：主页、助手、本机文件、使用概览、设置。
- 224px 上下文侧栏：当前助手及任务，或本机文件和账户子导航。
- 主内容区：任务、对话、文件范围、用量和设置。

短期导航不出现团队、市场、悬赏、活动、社群或创作者中心。参考产品仅用于借鉴进入速度、助手列表密度、任务结果反馈和工作区可见性。

## 4. 首次流程

### 4.1 手机号登录

- 保留手机号验证码登录。
- 登录页直接解释账号会保存权益和余额。
- 不在登录页介绍网关、模型目录或助手安装。
- 登录成功后，新用户进入用途选择；老用户恢复已完成状态。

### 4.2 用途选择

- 展示内容创作、拍摄剪辑、高效办公、电商运营、学习研究和生活家庭。
- 支持多选和填写自定义目标。
- 选择结果只影响首页任务推荐和助手排序，不限制其他能力。

### 4.3 激活

- 手动输入激活码仍是 Demo 主路径。
- 激活成功后说明权益绑定当前手机号。
- 激活配置写入必须可重试；Gateway 尚未连接时不能静默丢失。
- 成功后立即进入主工作台框架。

## 5. 工作台内启动准备

### 5.1 页面行为

移除“Gateway、模型目录、六助手全部完成前不得看到工作台”的全屏门禁。准备期间显示完整导航、助手侧栏和主内容骨架。

对话主区域显示一个主要准备面板：

- 总体准备百分比。
- AI 服务状态。
- 可用模型状态。
- 常用助手完成数量。
- 当前正在进行的步骤。
- 超过 90 秒后的网络说明和“重新尝试”按钮。

### 5.2 可用性分级

- 工作台框架、本机文件范围说明、账户和设置在进入后立即可查看。
- AI 服务和模型未就绪时，对话输入框保持禁用并解释原因。
- 某个助手完成准备后可以立即显示；尚未完成的助手显示“准备中”。
- AI 服务、至少一个可用模型和当前助手均就绪后，当前对话输入框解锁。
- 六个助手不再作为所有对话功能可用的硬门槛，但继续在后台完成准备。

### 5.3 错误状态

- Gateway 失败：显示“AI 服务未连接”，允许重试。
- 模型目录失败：显示“暂时无法获取可用模型”，不展示虚假的默认模型可用状态。
- 单个助手失败：只影响该助手，其他已就绪助手仍可使用。
- 重试不清除登录、激活、用途或已有任务数据。

## 6. 本机文件与 Agent 能力

### 6.1 文件范围

新增用户可理解的“本机文件”入口，展示：

- 已授权文件夹。
- 路径和授权状态。
- 最近使用的授权文件。
- 添加和移除文件夹入口。
- “助手只能处理你明确允许的范围”说明。

首版不自动扫描整台电脑，也不把开发工作区路径直接暴露为用户文件范围。每台电脑单独保存文件授权；账号换电脑后只恢复权益，不自动恢复旧电脑的文件权限。

### 6.2 任务执行反馈

当助手读取文件或生成成果时，对话中显示紧凑的工具执行记录：

- 读取了哪些用户授权文件。
- 当前动作是读取、分析、生成还是保存。
- 成功或失败状态。
- 产物名称和保存路径。
- “打开文件夹”或“打开文件”操作。

这套反馈用于证明助手真的完成了任务，而不是只输出一段文本。

## 7. 助手引导

罗盘助手和六个专业助手继续作为独立 Agent 身份存在，不合并为仅改变名称的主模型快捷入口。

首次打开某个助手且没有历史任务时，主内容区显示内嵌引导：

- 助手名称和一句能力说明。
- 4 个适合该助手的首屏示例任务。
- 可使用的文件、联网、生成文档等能力标签。
- 默认模型和当前准备状态。
- 正常对话输入框。

选择示例任务后，将示例内容填入或直接创建该助手名下的新任务。助手引导不是独立弹窗，不阻止用户直接输入自己的需求。

## 8. 默认模型一致性

### 8.1 默认值

商业 Demo 默认模型统一为：

```text
provider: clawrouter
model: deepseek-v4-flash
display: DeepSeek V4 Flash
```

若生产模型目录返回的真实 ID 不同，以商业目录定义的规范 ID 为唯一真源，展示名称从该目录映射。

### 8.2 数据流

创建新任务或首次打开没有模型偏好的任务时：

1. 从商业默认模型配置初始化任务待发送模型。
2. 模型选择器显示相同模型。
3. 第一条消息显式携带该模型发送，不能依赖 Gateway 的旧默认值。
4. 回复消息保存网关返回的实际模型。
5. 若实际模型与选择值不一致，显示明确的回退说明，不能静默显示选择值。
6. 用量明细记录实际执行模型。

用户切换模型后，新的选择继续按现有任务粒度持久化。

## 9. 额度展示

所有余额主进度条统一计算：

```text
remaining = max(0, quotaTotal - quotaUsed)
remainingPercent = clamp(remaining / quotaTotal × 100, 0, 100)
```

显示规则：

- 主数字：剩余额度。
- 主进度条：剩余百分比。
- 次级信息：总额度和已使用额度。
- 最近一次任务：实际模型、输入 Token、输出 Token 和扣除点数。
- 余额不足警告仍根据已使用比例或剩余阈值触发，但面向用户的文案描述“还剩多少”。

主工作区、账户设置和使用概览必须使用同一计算函数，避免某处显示已用、某处显示剩余。

## 10. 视觉与交互细化

- 延续现有 Inter 字体、4px 间距体系、单一紫蓝强调色和 Windows 主题跟随。
- 页面标题保持 24px 左右，不把应用做成宣传落地页。
- 启动准备使用骨架和单一主要进度，不叠加大量旋转图标。
- 助手、文件和用量采用相同的导航、按钮、状态标签和空状态词汇。
- 状态不能只靠颜色表达，必须同时有文字或图标。
- 所有关键按钮支持键盘焦点，浅色和深色主题达到 WCAG 2.1 AA 对比度。
- 动效仅用于状态变化，常规过渡 150–200ms，并支持减少动态效果。

## 11. 状态与数据归属

- 账号级：激活权益、余额、用量、商业默认模型、用途和自定义目标。
- 任务级：助手 ID、选定模型、消息、实际回复模型和成果引用。
- 设备级：本机授权文件夹、工作区路径、窗口和主题偏好。
- 运行时：Gateway、模型目录和助手准备状态。

UI 不能把设备级文件权限误称为账号云同步，也不能用任务选择模型覆盖所有助手的全局默认值。

## 12. 验收标准

1. 激活后 2 秒内能看到主工作台框架，后续准备在对话区内进行。
2. AI 未就绪时仍能查看本机文件范围、余额和助手列表。
3. 当前助手就绪后可以使用，不等待全部六个助手完成。
4. 超过 90 秒显示原因说明和重试入口。
5. 新任务首条消息默认选择并实际执行 DeepSeek V4 Flash。
6. 模型选择器、回复标签和用量明细三处一致；回退时明确说明。
7. 所有额度主进度条显示剩余比例。
8. 用户能看到 Agent 可访问的文件范围，并能添加或移除授权。
9. 每个内置助手都有内嵌能力说明和至少 4 个示例任务。
10. 文件读取和成果保存均在对话中留下可见记录。
11. 浅色和深色主题均完成实机检查。
12. 新增行为具备自动化测试，完整质量门禁通过。

## 13. 明确延后

- U 盘封装、自动发现和 USB 激活码删除。
- 在线助手市场、技能市场、团队和悬赏。
- 联系人、活动、签到、社群和创作者收益。
- 全盘文件扫描和跨设备同步文件权限。
- 静态原型中的任何虚构运营模块。

本轮交付结束条件是基本盘主路径可信、可理解、可恢复，并生成经过全新环境彩排的最新 Windows 安装包。
