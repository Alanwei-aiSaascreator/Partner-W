# Partner-W浅色首次使用与目标路由设计

日期：2026-09-15  
状态：用户已确认设计方向，待书面规格复核  
适用范围：基本盘 Demo 的手机号登录、用途设置、权益激活、工作台启动、目标分析与专属助手创建

## 1. 目标

把现有静态评审稿映射到真实桌面端，并修正评审中暴露的三个问题：大面积黑色降低亲和力，验证码捂眼动作像悬空手掌，自定义目标虽已保存但没有进入助手推荐和角色生成链路。

本轮完成后，新用户应能在浅色界面中完成登录、用途与目标设置、激活、进入工作台、等待真实 AI 服务就绪，并由罗盘助手把自定义目标路由到现有助手或生成一个可确认创建的专属助手。

## 2. 本规格与既有设计的关系

本规格补充并覆盖以下旧决策：

- 覆盖 `2026-09-15-login-to-workspace-experience-design.md` 中“登录品牌区和用途页使用深色大面板”的决定。本轮默认使用浅色界面，不保留大面积近黑背景。
- 覆盖 `2026-09-15-blocking-startup-readiness-design.md` 中“所有能力就绪前阻止进入工作台”的决定。用户完成必要步骤后立即进入工作台框架，仅暂时锁定依赖 AI 的输入与分析功能。
- 保留 `2026-09-15-overall-ui-design.md` 的双侧栏、独立助手主页、模型与账单真相、延后空壳模块等总体原则。

## 3. 已确认的产品决策

1. 新用户默认进入浅色主题。深色主题继续保留为设置中的主动选择，不再因 Windows 深色模式而让首次体验出现大面积黑色。
2. 登录、用途、激活和加载阶段复用同一个品牌角色；验证码聚焦时移动真实手臂，不渲染一对独立悬空手掌。
3. 用途页面同时支持常见用途多选和显著的自定义目标输入。只填写自定义目标也可以继续。
4. 自定义目标先按账号画像保存。权益有效且 AI 服务就绪后才调用模型分析，避免在模型尚不可用时制造假进度或失败。
5. 分析优先复用罗盘助手和六个预置助手。只有现有助手不适合时才生成专属助手草案。
6. 专属助手不会静默自动创建。用户先查看名称、职责、推荐模型和 Prompt 摘要，点击“创建专属助手”后才执行真实创建。
7. 激活完成后立即显示真实工作台主体。连接服务、准备模型和加载助手继续在主内容区完成。
8. 改造开始前保留 Git 回滚标签 `demo-before-light-onboarding-v3-20260915`，指向提交 `ed750e5`。

## 4. 视觉系统

### 4.1 使用场景

用户在普通办公室或家用 Windows 电脑上首次打开产品，需要长时间阅读和输入。界面应以明亮、低眩光、清楚分区为主，不用深色开发工具视觉制造专业感。

### 4.2 浅色表面层级

- 页面背景：中性浅灰紫，建议从现有浅色主题变量演化，不新增散落的组件色值。
- 全局功能栏：浅灰紫表面，与页面背景存在轻微明度差。
- 助手栏：白色或接近白色，使用细分隔线而不是黑色块。
- 主工作区：明亮中性色；对话、欢迎和加载状态共享同一内容宽度。
- 选中状态：低饱和品牌紫底、品牌紫文字、图标与文字共同表达选中。
- 强调色：仅用于主要按钮、进度、焦点和关键状态，渐变不铺满工作台。

正文、占位符和状态文字满足 WCAG 2.1 AA。卡片圆角控制在 12–16px，普通按钮约 8–10px，不使用玻璃卡片、发光黑底或大面积装饰渐变。

### 4.3 主题行为

首次使用默认浅色。用户在设置中明确选择深色后继续尊重其选择；升级用户已有的明确主题偏好不被覆盖。自动主题仍可作为设置选项，但不作为新用户初始值。

## 5. 品牌角色动效

品牌角色使用一套 SVG 骨架，由头部、眼睛、左臂和右臂组成。每条手臂是包含上臂、前臂和手掌的整体分组，旋转基点位于肩部。

状态规则：

- 默认：自然眨眼，瞳孔在有限范围内跟随指针。
- 手机号聚焦：视线轻微转向输入区。
- 验证码聚焦：左右手臂整体从身体两侧抬起，手掌移动到双眼前；原位置不残留手臂，也不创建第二对手掌。
- 验证码失焦：手臂沿原路径放下，眼睛恢复跟随。
- 验证成功：角色短暂确认后进入下一步。
- `prefers-reduced-motion`：关闭指针跟随和连续位移，只切换静态的睁眼与捂眼姿态。

动画只使用 transform 和 opacity，时长约 180–240ms，采用自然的 ease-out，不使用弹跳。

## 6. 首次使用流程

### 6.1 手机号登录

登录页使用明亮双区布局。品牌区说明产品能力、本机数据与账号权益；表单区承担手机号、验证码、协议和一个当前主要动作。短信发送成功只表示服务端已接受请求，界面同时保留倒计时、重新发送和可理解的失败提示。

### 6.2 用途与自定义目标

页面标题为“你主要想用它完成什么？”。六个常见用途作为快速选择，自定义目标输入紧邻用途列表并保持首屏可见，不隐藏在滚动底部。

自定义输入示例：

> 我想整理抖音素材，每周生成三个短视频脚本。

页面明确说明：“先记录下来，AI 服务准备好后，罗盘助手会为你分析并推荐助手。”用户可以选择用途、填写目标，或同时完成两项。

提交后继续复用现有 `OnboardingProfile` 的 `useCases` 与 `customGoal` 字段，不建立第二份画像数据。

### 6.3 权益激活

激活页保持一个主要动作，展示激活码绑定当前手机号、激活后的剩余额度和有效状态。失败时保留输入内容。已经具有有效权益的账号直接跳过激活输入，不重复绑定。

### 6.4 进入工作台与服务准备

完成登录、画像和必要激活后，应用立即显示浅色双侧栏和主工作区。导航与本地可读内容可以浏览；依赖模型的输入框、目标分析和真实回复在服务就绪前禁用。

主内容区的大型准备模块显示四个用户语义状态：

1. 正在连接 AI 服务。
2. 正在准备默认模型。
3. 正在加载常用助手。
4. 可以开始使用。

进度必须由真实状态推导。超过约 90 秒显示原因说明、“重新准备”和可展开的诊断详情，不要求开发命令或现场改配置。

## 7. 目标分析与助手路由

### 7.1 触发条件

只有同时满足以下条件才自动开始一次分析：

- 当前账号有非空 `customGoal`；
- 权益状态允许模型调用；
- 默认模型目录已可用；
- 罗盘助手或系统会话通道可用；
- 该画像版本尚未成功分析。

分析状态按账号与目标内容生成稳定键，避免 React 重渲染、重启或重试重复扣费。目标被用户修改后产生新版本，可重新分析。

### 7.2 结构化分析结果

模型返回受约束的结构化结果：

- 目标摘要；
- 推荐的现有助手 ID，或 `custom`；
- 推荐理由；
- 推荐模型；
- 三个首发任务；
- 当结果为 `custom` 时，额外提供助手名称、职责、系统 Prompt 和边界说明。

解析失败、返回未知助手 ID 或缺少必需字段时，不创建助手。界面保留原始目标并提供重新分析；同时允许用户直接进入罗盘助手继续对话。

### 7.3 匹配现有助手

当模型判断现有助手适合时，显示一块紧凑推荐区域：推荐助手、推荐模型、理由和三个可执行任务。点击“使用这个助手”才切换当前助手；点击任务只填入输入框，不自动发送。

### 7.4 生成专属助手草案

当六个现有助手都不适合时，展示“为你生成的专属助手方案”，内容包括名称、一句话职责、推荐模型、能力边界和可展开的 Prompt 摘要。

用户点击“创建专属助手”后，复用现有 `createAgentWithRollback`：创建助手、设置模型；任一步失败则删除本轮产生的不完整助手。成功后刷新助手目录、选中新助手，并展示三个首发任务。取消不会写入助手目录。

系统不得因重复点击、重试或恢复会话创建同名重复助手。创建前按稳定草案 ID 和账号目标版本检查已有结果。

## 8. 组件边界

- `LoginExperience`：登录布局、字段状态和品牌角色，不处理短信服务实现。
- `GuideMascot`：SVG 骨架、视线和姿态状态，独立支持减少动态效果。
- `OnboardingGoalStep`：用途选择、自定义目标和本地画像保存。
- `StartupReadinessPanel`：真实服务准备状态、90 秒说明和重试。
- `GoalAnalysisService`：触发条件、幂等键、模型调用、结构校验与持久化。
- `GoalRecommendationPanel`：现有助手推荐或专属助手草案的展示与确认。
- `AgentCreationService`：封装现有事务式创建和重复创建保护。

这些边界继续使用现有认证、商业权益、网关、模型、助手目录和 Zustand 状态，不创建替代数据源。

## 9. 错误与恢复

- 短信未收到：倒计时后可重新发送，保留手机号，并提示检查测试号限制、拦截和运营商延迟。
- 权益无效：保留激活码，说明原因并允许重新提交。
- AI 服务未就绪：目标保持已保存状态，不发起分析、不扣费。
- 分析失败：显示“目标已保存，暂时未完成分析”，可重试或直接用罗盘助手。
- 无法创建专属助手：回滚不完整助手，保留草案与目标，允许再次创建。
- 余额不足：不丢失目标和草案，提供余额入口。
- 应用重启：恢复已保存画像、成功分析结果和已创建助手，不重复分析或创建。

## 10. 测试与验收

### 10.1 自动化测试

- 新用户默认浅色，已有明确主题偏好保持不变。
- 自定义目标单独填写时可以继续并正确保存。
- 目标分析只在权益和 AI 服务就绪后触发，同一目标版本不重复调用。
- 结构化分析分别覆盖现有助手匹配、专属助手草案和无效响应。
- 专属助手只有确认后创建，取消无副作用，失败触发回滚，重复确认不创建副本。
- 登录验证码聚焦和失焦产生正确的角色状态；减少动态效果关闭连续动画。
- 工作台在准备期间可见，AI 输入禁用，准备完成后自动启用。
- 超过约 90 秒出现说明和重试入口。
- 默认模型选择、真实请求、回复标签和用量明细保持 `deepseek-v4-flash` 一致。
- 所有额度进度表达剩余量。

### 10.2 视觉与真实流程验收

- 约 1266×800 和常用桌面窗口下，登录、用途、自定义目标和激活无需水平滚动。
- 全局栏、助手栏和用途右侧区域没有大面积黑色。
- 捂眼时能看出两条真实手臂从肩部抬起，身体侧面不残留原手臂。
- 用户完成激活后立即看见正式工作台结构，准备进度位于内容区。
- 使用全新手机号和干净环境完成一次真实彩排，无需开发命令、数据库操作或现场改配置。
- 运行目标测试、TypeScript、构建与既有全量测试基线后再交付安装包。

## 11. 本轮不包含

- 团队、市场、悬赏、广场、创作者中心和游戏化模块。
- 静默自动创建助手。
- 在 AI 服务尚未就绪时使用模拟分析结果。
- 重写短信、支付、计费、网关或模型协议。
- 自动读取整台电脑。文件系统访问仍必须由用户选择目录、上传文件或明确授权。
