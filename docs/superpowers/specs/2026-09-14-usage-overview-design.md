# 荣盈魔方使用概览设计

**日期：** 2026-09-14

**阶段：** Stage 3B 大众版功能完善

**目标：** 让普通用户随时找到自己的 AI 使用情况，并在一个页面内看懂任务成果、常用助手、模型消耗和积分余额。

## 一、问题

当前 Dashboard 已有真实统计和透明计费明细，但存在三个产品问题：

1. 入口只在首次任务完成卡片中出现一次，之后难以再次进入。
2. 页面先展示 Token、网关、倍率等技术信息，大众用户不容易判断“我用了多少、常用什么、还剩多少”。
3. 本机任务统计和账号计费统计混在一起使用“账号”标签，数据口径不够清楚。

本批次只调整导航、信息层级和展示方式，不修改计费、数据库、模型调用、登录或设备激活逻辑。

## 二、用户路径

```text
任意页面
→ 点击侧栏“我的 AI 使用概览”
→ 查看累计任务、活跃天数、剩余积分和常用助手
→ 查看各模型的真实调用次数、Token 和积分消耗
→ 按需展开透明计费明细
→ 查看最近 30 天的用量趋势
```

侧栏收起时保留图标入口和可访问名称，展开时显示完整名称。

## 三、信息层级

### 第一层：一眼看懂

- 累计任务：本机保存的任务数量。
- 活跃天数：本机有任务活动的天数。
- 剩余积分：账号额度减去已使用额度。
- 常用助手：本机任务数最多的助手及使用次数。

### 第二层：常用助手与账号额度

- 常用助手按现有统计顺序展示。
- 账号额度展示总积分、已用积分、剩余积分和进度条。
- 没有账号额度时显示克制的空状态，不伪造为零余额。

### 第三层：模型消耗

- 继续使用服务端计费表聚合的真实调用模型。
- 默认只展示模型名、供应商、调用次数、Token 和实际扣费。
- 官方参考价、目标倍率、覆盖率等信息放入“查看计费明细”，由用户主动展开。
- 无法获取和确实没有调用使用不同文案。

### 第四层：最近 30 天

- 展示输入 Token、输出 Token、积分消耗和每日趋势。
- 明确标注该部分属于账号统计。

## 四、数据口径

| 信息                                 | 来源             | 页面标记 |
| ------------------------------------ | ---------------- | -------- |
| 任务、活跃天数、消息、文件、助手     | 本机 SQLite 聚合 | 本机     |
| 模型调用、Token、积分消耗、30 天趋势 | 服务端计费聚合   | 账号     |
| 额度总数、已用、剩余                 | 商业账户概览     | 账号     |

模型消耗继续按真正发到上游的模型统计，不读取会话默认模型。透明计费文案继续遵守现有口径，不把官方参考费用描述成供应商账单或实际成本。

## 五、状态处理

- 首次进入主动加载 Dashboard 和账户概览。
- 刷新按钮同时刷新两份数据。
- 加载中保留已有缓存；首次加载时显示明确状态。
- 模型数据为 `null` 时提示暂时无法读取，为空数组时提示尚无调用记录。
- 助手统计为空时提示完成一次任务后即可看到。
- 余额数据缺失时显示“暂时无法读取”，不显示错误的 `0`。

## 六、组件边界

- `LeftNav/index.tsx`：新增 Dashboard 固定入口，展开与收起状态均可用。
- `Dashboard/index.tsx`：重排页面层级，组合 Dashboard store 与 commercial store；不直接请求底层 IPC。
- `dashboardStore.ts`：保留现有缓存与请求行为，本批次不改数据契约。
- i18n：新增页面标题、说明、范围标签、余额和明细操作文案。

## 七、验收标准

1. 侧栏展开和收起时都能进入“我的 AI 使用概览”。
2. 当前页面为 Dashboard 时入口具有选中状态。
3. 页面首屏显示任务数、活跃天数、剩余积分和常用助手。
4. 余额缺失时不会显示为 0。
5. 模型列表默认不铺开专业计费字段，点击后可查看原有透明计费明细。
6. 本机与账号统计有清楚的范围标记。
7. 浅色、深色主题和约 1266×800 窗口下均无裁切或遮挡。
8. 原有首次完成卡片进入 Dashboard 的路径继续可用。

## 八、后续边界

余额变动流水需要服务端提供充值和消费的时间序列，本批次不使用现有总额推测。用途云端同步、修改用途、团队、市场、定时任务和 Stage 3A 设备激活继续按后续批次处理。
