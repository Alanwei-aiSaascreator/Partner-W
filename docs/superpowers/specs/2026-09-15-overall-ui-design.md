# 荣盈魔方整体 UI 设计

**日期：** 2026-09-15

**阶段：** Stage 3B 大众版功能与 UI 统一

**状态：** 视觉方向已由用户确认

**适用范围：** Windows 桌面客户端的登录后主界面、首页、助手导航、对话、成果区、文件、使用概览与设置

## 一、设计目标

荣盈魔方面向不熟悉 AI 工具的大众 Windows 用户。界面要帮助用户从“我不知道怎么问”进入“我完成了一件事”，并在过程中保持助手、模型、余额、文件位置和任务状态清楚可信。

首要成功标准：

1. 用户登录后 3 分钟内理解产品用途并完成第一次真实 AI 任务。
2. 用户不需要理解 Agent、Gateway、Provider、Token 等内部术语。
3. 用户在任意主要页面都能找到助手、最近任务、余额和下一步操作。
4. 浅色与深色主题拥有相同结构、可读性和完整状态。
5. 界面具有荣盈魔方自己的识别方式，不依赖职业人物头像、装饰渐变或游戏等级。

## 二、已确认的整体方向

| 设计项   | 已确认方案                                 |
| -------- | ------------------------------------------ |
| 产品气质 | 大众任务中心：清楚、亲切、可信             |
| 首次主题 | 跟随 Windows，用户可在设置中覆盖           |
| 主导航   | 双侧栏：56px 全局功能栏 + 224px 助手栏     |
| 助手形象 | “魔方能力面”几何图形系统                   |
| 首页重心 | 先完成一件事，任务优先于功能陈列           |
| 对话成果 | 默认关闭，用户打开文件时按需展开右侧成果区 |

同行界面只作为交互参考。荣盈魔方借鉴助手持续可见、示例任务可直接开始、底部输入区稳定和余额容易找到这四个原则，不复用其双栏比例、页面布局、人物头像、视觉素材或文案。

## 三、信息架构

登录后的标准应用结构由四个区域组成：

```text
┌────────┬──────────────────────┬─────────────────────────────────┬──────────────────┐
│ 全局栏 │ 助手与最近任务       │ 当前主工作区                    │ 按需成果区       │
│ 56px   │ 默认 224px           │ 自适应，普通状态优先获得空间    │ 默认关闭，320px  │
└────────┴──────────────────────┴─────────────────────────────────┴──────────────────┘
```

### 3.1 全局功能栏

全局栏固定为 56px，仅放跨助手、跨任务的入口。图标必须配有 Tooltip 和无障碍名称。

从上到下：

1. 荣盈魔方品牌标记。
2. 首页。
3. 文件管理。
4. 我的 AI 使用概览。
5. 当前已经可用且与主路径直接相关的其他入口。
6. 底部放身份中心和设置。

尚未完成的团队、技能市场、智能体市场、需求悬赏、广场、创作者中心和游戏化中心不进入首版全局栏。它们在具备真实功能后再按使用频率决定是否进入一级导航。

余额在应用顶部持续可见，点击后进入充值或额度详情。全局栏不重复显示完整余额数字。

### 3.2 助手栏

助手栏默认宽 224px，可在 200–260px 之间调整。正常桌面窗口中始终显示全部预置助手，并在下方显示当前助手相关的最近任务。

结构从上到下：

1. 标题“我的助手”和“添加助手”按钮。
2. 搜索助手。助手不超过 7 个时可弱化搜索框，但保留键盘搜索能力。
3. 罗盘助手和六个专业助手。
4. 分隔线。
5. 当前助手的最近任务，最多直接显示 3–5 条。
6. “查看全部任务”入口。

交互规则：

- 首页默认选中罗盘助手，但中心内容仍是用户的个性化任务首页。
- 单击助手只切换中心内容和任务范围，不自动创建任务，也不发送消息。
- 单击最近任务直接恢复对应对话。
- “添加助手”打开现有安装或添加流程，不进入尚未完成的市场页面。
- 选择助手只改变当前视图，不移动、删除或改写原有任务。

### 3.3 主工作区

主工作区承载首页、对话、文件管理、使用概览与设置内容。页面标题、主要动作和状态反馈都属于主工作区，不在两个侧栏中重复。

### 3.4 成果区

成果区默认关闭，推荐宽度 320px，允许在 288–420px 内调整。用户点击生成文件、引用或任务产物后才打开。

- 打开成果区后保留当前消息位置和输入内容。
- 用户可以边查看成果边继续对话修改。
- 关闭成果区后，对话区恢复全部可用宽度。
- 成果区状态按任务保存，切回任务时可恢复上次打开的成果。
- 当剩余对话宽度不足 600px 时，成果区使用覆盖式面板；关闭后回到原消息位置。
- 成果区明确显示文件名、类型、保存状态和真实保存位置，并提供“导出文件”“打开目录”等直接操作。

## 四、页面设计

### 4.1 登录与首次设置

登录和首次用途设置发生在主应用壳之外，避免新用户在完成身份和目标设置前看到复杂工作台。

- 登录页只突出手机号、验证码和继续操作。
- 首次设置延续当前称呼、常用场景多选、自定义目标和跳过能力。
- 进度信息说明当前步骤，不使用等级、成长值或“新手村”等游戏包装。
- 完成后进入个性化首页。
- 老用户可以从身份中心重新编辑用途与目标。

### 4.2 个性化首页

首页回答三个问题：现在能做什么、最适合先做什么、从哪里输入自己的需求。

页面顺序：

1. 简短问候和当前用户称呼。
2. 页面主标题“先完成今天最重要的一件事”。
3. 一个优先任务：优先展示可继续任务；没有历史任务时展示基于用途推荐的首个任务。
4. 三个常用任务入口，按用户用途动态排序。
5. 固定在工作区底部的任务输入框。

首页不展示大面积助手介绍、模型列表、技术能力清单或虚假数据。助手已经在左侧常驻，首页只在任务文案中说明推荐由哪个助手完成。

点击任务模板后只把可编辑任务说明写入输入框，不自动发送。用户确认后再创建任务并调用模型。

### 4.3 助手主页

用户在助手栏选择专业助手且当前没有选中任务时，中心显示该助手主页：

1. 魔方能力面图标、助手名称和一句能力说明。
2. 3–4 个可以直接开始的真实任务。
3. 当前助手的最近任务。
4. 底部任务输入框。

助手主页不使用完整人物故事、履历或夸张称号。重点解释它可以帮助用户完成哪些结果。

### 4.4 对话页

对话页延续任务流，不做聊天机器人展示页。

- 顶部显示任务标题、当前助手、已选择模型和必要的任务操作。
- composer 模型选择表示用户对下一次调用的选择。
- 每条 assistant 消息显示网关返回的实际生成模型；不能用 composer 当前选择或模型自述替代。
- 消息正文以阅读为主，工具执行、思考内容和技术日志默认收起。
- 文件和成果以紧凑条目出现在对应消息下方，点击后打开成果区。
- 输入区固定在底部，保留上传、模型、推理档位、语音和发送；低频能力收入口径一致的菜单。
- 第一次任务完成后显示真实完成反馈和一个明确的下一步动作，不展示虚假等级或徽章。

### 4.5 文件管理

文件管理使用工作区内的列表或分栏视图，重点显示用户能理解的信息：文件名、来源任务、修改时间、大小和位置。

- 默认展示最近文件和来源任务。
- 支持搜索、按助手或类型筛选、打开文件和打开所在目录。
- 文件预览复用成果区或现有预览组件。
- 文件不存在、U 盘拔出或路径不可用时，说明发生了什么，并提供重新连接或选择目录的操作。

### 4.6 我的 AI 使用概览

沿用已经完成的大众版信息层级：

1. 累计任务、活跃天数、剩余积分和常用助手。
2. 常用助手与账号额度。
3. 实际模型调用、Token 与积分消耗。
4. 默认收起的透明计费明细。
5. 最近 30 天趋势。

本机数据与账号数据继续明确标记范围。数据暂时无法读取和确实没有使用记录必须使用不同文案，不把缺失值显示为 0。

### 4.7 身份中心与设置

身份中心负责用户可理解的账号信息：手机号、称呼、用途与自定义目标、账户状态。设置负责应用行为：主题、启动、数据位置、模型和高级连接信息。

- “编辑我的用途”是身份中心的一级操作。
- 主题默认“跟随 Windows”，同时提供浅色和深色覆盖选项。
- Gateway、Provider、路径和调试信息放入“高级设置”，避免进入大众用户默认视线。
- 高风险操作使用明确动词和影响说明。

## 五、品牌与视觉系统

### 5.1 魔方能力面

每个助手使用同一几何规则生成能力面：

- 32px 左右的基础方形。
- 一个统一的折面或方向角，表达“魔方的一面”。
- 中心使用简单线性符号表达能力。
- 罗盘助手使用品牌紫蓝；专业助手各自拥有一个低饱和分类色。
- 分类色只出现在图标、细小状态线和少量标签中，不扩展为整页背景色。

首批能力符号：

| 助手     | 符号含义       |
| -------- | -------------- |
| 罗盘助手 | 方向或罗盘核心 |
| 内容创作 | 灵感或文字火花 |
| 拍摄剪辑 | 镜头与播放方向 |
| 高效办公 | 文档网格       |
| 电商运营 | 商品与增长路径 |
| 学习研究 | 连接与知识节点 |
| 生活家庭 | 日程与生活空间 |

不使用模板化职业人物头像作为系统默认形象。用户自建助手未来可以上传头像，但必须有几何能力面的默认回退。

### 5.2 色彩

继续使用现有 CSS 变量和已提交品牌色：

- 深色页面底色：`#13131C`。
- 深色面板：`#1A1A25`。
- 深色主强调：`#8088FB`。
- 浅色页面底色：`#F4F3EF`。
- 浅色面板：`#FBFAF7`。
- 浅色主强调：`#5860EA`。

组件代码不新增孤立的十六进制颜色。新增能力分类色时先进入主题变量，再由组件引用。文本和交互状态达到 WCAG 2.1 AA 对比度要求。

### 5.3 字体与密度

- 界面字体继续使用 Inter Variable，中文使用系统无衬线回退。
- 正文 14px，辅助文字不低于 12px；关键操作不使用同行截图中难以辨认的小字。
- 页面标题通常为 24–28px，工作页面标题保持 16–20px。
- 助手行高 48px，全局栏按钮视觉尺寸 38–40px，关键点击区域至少 40px。
- 间距以 4px 为基准，主要使用 8、12、16、20、24px。
- 普通卡片圆角 8–12px，主输入框可使用 18–24px；不全局扩大圆角。

### 5.4 深浅主题

首次启动读取 Windows 主题。用户在设置中选择浅色或深色后，以用户选择为准。

两套主题必须保持：

- 相同页面结构、尺寸和交互。
- 相同信息优先级。
- 清楚的 hover、focus、selected、disabled、warning 和 danger 状态。
- 相同的能力分类色含义。

浅色使用温和中性背景与白色浮层；深色使用近黑紫背景与有限高亮。禁止用大面积渐变、发光球、玻璃卡片和装饰网格表达“AI 感”。

## 六、状态与反馈

每个主要页面必须覆盖以下状态：

| 状态         | 设计要求                                         |
| ------------ | ------------------------------------------------ |
| 首次加载     | 保留页面骨架，明确当前正在读取什么               |
| 空状态       | 说明为什么为空，并提供一个可执行动作             |
| 数据不可用   | 与“数据为 0”区分，保留重试入口                   |
| 网络离线     | 顶部显示连接状态；本地任务和文件仍可查看         |
| 模型不可用   | 说明所选模型暂时不可用，并提供重新选择           |
| 余额不足     | 在发送前提示影响和充值入口，不丢失输入内容       |
| 文件路径失效 | 说明 U 盘或目录不可用，提供重新连接或选择目录    |
| 操作成功     | 在动作附近确认结果，避免只依赖短暂 Toast         |
| 操作失败     | 使用日常语言说明原因、保留用户输入、提供恢复动作 |

## 七、响应式与窗口规则

本产品以 Windows 桌面窗口为主，不做移动端式堆叠。

1. 宽窗口：显示 56px 全局栏、224px 助手栏和主工作区；成果打开时增加 320px 成果区。
2. 中等窗口：助手栏可缩至 200px，任务和助手名称使用单行省略并提供 Tooltip。
3. 当主工作区无法保留 600px 对话宽度时，成果区改为覆盖式面板。
4. 更窄窗口允许临时收起助手栏，仅保留 56px 全局栏；点击当前助手图标可重新展开。
5. 用户手动调整的助手栏与成果区宽度按设备保存，并受各自最小值和最大值限制。
6. 所有主要布局在约 1266×800 的演示窗口下必须完整可用。

助手栏收起后，全局栏在首页入口下方临时显示当前助手的能力面按钮。该按钮只负责重新展开助手栏，不改变当前助手或任务。

## 八、动效与可访问性

- hover 和按钮反馈使用约 100–150ms。
- 侧栏与成果区展开使用约 180–220ms 的 ease-out。
- 不动画宽高导致大面积页面抖动；面板使用 transform、opacity 或受控布局过渡。
- 遵守 `prefers-reduced-motion`，关闭位移和装饰性动画。
- 所有功能可用键盘完成，焦点顺序与视觉结构一致。
- Tooltip 不能承载完成任务所必需的唯一信息。
- 图标按钮提供可访问名称，选中状态不能只靠颜色表达。
- 表单错误与字段绑定，错误后焦点移动到首个需要处理的位置。

## 九、组件边界

整体改造优先建立可复用边界，避免把页面继续堆进单个大型组件：

| 组件                 | 职责                                     |
| -------------------- | ---------------------------------------- |
| `AppShell`           | 组合全局栏、助手栏、主工作区和成果区     |
| `GlobalRail`         | 全局导航、品牌入口、身份与设置入口       |
| `AssistantRail`      | 助手选择、助手搜索、最近任务和宽度状态   |
| `CubeFaceIcon`       | 统一渲染预置助手与自建助手的默认形象     |
| `PersonalizedHome`   | 问候、优先任务、常用任务和首页输入框     |
| `AssistantHome`      | 单个助手说明、任务模板和最近任务         |
| `ConversationHeader` | 任务标题、助手信息、任务级操作和模型选择 |
| `ArtifactPanel`      | 文件预览、成果操作、任务内开关和宽度状态 |
| `UsageOverview`      | 组合本机任务统计和账号计费统计           |

组件继续通过现有 Zustand stores、IPC 和路由状态读取数据。整体 UI 改造不新建第二套任务、消息、余额或模型数据源。

## 十、数据与交互真相

1. 任务、消息、文件和助手使用次数继续来自本机数据层。
2. 余额、账号额度和模型计费继续来自商业服务端数据。
3. composer 显示用户选择的下次调用模型。
4. 每条 assistant 消息显示网关返回的实际生成模型。
5. 用途与自定义目标当前读取本地画像；后续账号云同步完成后使用版本化合并，不由 UI 猜测覆盖关系。
6. 文件保存结果必须等待真实写入确认，UI 才显示“已保存”。

## 十一、分批实施顺序

整体设计按可验收的小批次实施：

1. **设计基础**：整理主题变量、尺寸变量、焦点与状态规范，建立 `CubeFaceIcon`。
2. **应用壳与双侧栏**：实现 56px 全局栏、224px 助手栏、最近任务和收起逻辑。
3. **首页与助手主页**：统一首页任务层级、推荐入口和助手主页。
4. **对话与成果区**：重排对话头部、消息元信息、底部 composer 和按需成果区。
5. **其余页面统一**：文件管理、使用概览、身份中心、设置和首次引导。
6. **视觉验收**：浅色、深色、1266×800、窄窗口、键盘、减少动态效果与关键异常状态。

每一批都应保持手机号登录、余额、模型选择、真实回复和现有任务恢复路径可用。

## 十二、不在本轮范围

- 团队、技能市场、智能体市场、需求悬赏、广场和创作者中心的完整产品实现。
- 等级、徽章、成长值和活动裂变。
- Stage 3A 的 `license.key` 自动发现、一次性兑换、USB 激活码删除、device activation 与 `max_activations` 重构。
- 重写计费、认证、模型路由或网关协议。
- 为模仿同行而增加职业人物头像、双重品牌栏或大面积空白展示区。

## 十三、整体验收标准

1. 首次启动主题跟随 Windows，设置中的手动主题选择可覆盖系统主题。
2. 正常窗口显示 56px 全局栏和默认 224px 助手栏，全部预置助手可访问。
3. 双侧栏总宽不会让约 1266×800 窗口中的核心任务路径裁切。
4. 首页首屏包含一个优先任务、三个常用入口和可直接输入的 composer。
5. 单击助手不会自动创建任务或发送消息；助手主页显示真实任务入口。
6. 最近任务按当前助手正确显示并能恢复原对话。
7. assistant 消息显示实际生成模型，切换 composer 模型不会改写历史消息标记。
8. 点击生成成果可以打开右侧成果区，用户能够边查看边继续对话。
