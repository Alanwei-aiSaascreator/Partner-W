# 简约登录与首次进入流程设计

## 目标

登录页只完成登录。登录后的首次引导负责收集用途、目标和昵称，随后准备本地 AI 服务并进入工作台。

## 界面取舍

- 删除登录页左侧四个用途按钮，避免与首次引导重复。
- 左侧保留品牌、固定短标题、小人和一句权限说明，不再提供业务选择。
- 手机号、验证码、协议、错误提示和小人验证码交互保持不变。
- 首次引导继续提供六类用途、自定义目标和昵称；用途允许多选，自定义目标可单独完成。
- 已完成引导的账号不重复进入引导。

## 页面顺序

1. 检查登录状态。
2. 未登录时显示登录页。
3. 登录成功且账号未完成引导时，先显示用途与目标引导。
4. 引导完成后，如工作区尚未配置，显示工作区准备页。
5. 工作区可用后进入工作台；AI 服务尚未完全就绪时，工作台内显示真实启动阶段和重试入口。

## 数据规则

- 登录页不再写入 `partner-w-login-purpose`。
- 兼容旧版本已经写入的用途值：首次引导可以读取一次作为预选，但用户可修改。
- 引导完成后继续按账号 ID 保存 `OnboardingProfile`，用于推荐专业助手和首次任务入口。

## 验证

- 登录页测试确认不存在用途按钮，只保留单一登录主操作。
- 引导测试继续覆盖多选用途、自定义目标和持久化资料。
- 入口路由使用纯函数测试，确认顺序为登录、引导、准备、工作台。
- 运行桌面端相关测试、类型检查、i18n 检查和生产构建。
