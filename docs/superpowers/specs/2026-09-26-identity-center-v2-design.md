# 身份中心 v2 —— 让"改得了"（2026-09-26）

**触发**：用户真机反馈「身份中心里面改不了，重新选择、换标签这些点击没反应」。
**结论先行**：**不是事件坏了，是页面是个空壳** —— 每个控件都真的执行了，但它们**不改变任何实质东西**。

---

## 一、真机复现（盘上 0.0.34，CDP 真实鼠标事件，不是 `el.click()`）

手法：盘上的应用以 `--remote-debugging-port=9222` 重启，用 `Input.dispatchMouseEvent` 打到元素的
`getBoundingClientRect()` 中心，并在同一坐标上问 `document.elementFromPoint` **是谁**（查"被谁挡住"）。

| 控件                   | 真机读数                                           | 判定              |
| ---------------------- | -------------------------------------------------- | ----------------- |
| 五个标签               | 点击后 `data-selected` 真的翻转                    | ✅ 好的           |
| 「重新选择」           | 点击后 5 个全变 `false`；`topAtPoint` 就是按钮自己 | ✅ 好的           |
| 「换一个标签」         | 空选 ⇒ 回到默认四个                                | ✅ 好的           |
| 「应用此画像」         | 真的走 `useSelectAgent`                            | ✅ 好的           |
| **「其它客群」四张卡** | `cursor: auto`、**没有 onClick**、`tagName=DIV`    | ❌ **死的**       |
| 「推荐技能」7 个       | 文案是编的（网关里没有这些技能）                   | ❌ **假的**       |
| 画像卡片正文           | 客群/角色/技能/描述**全是常量**，与选择无关        | ❌ **点了不会变** |

⇒ 用户的"改不了"是**产品层的真话**：页头写着「选择你的客群……随时可切换」，而**没有任何一处**能改客群；
五个标签只改变自己的高亮。**能点的都点了，什么都没发生** —— 这就是"没反应"。

⚠️ 出货包里**不是**"按钮没接线"那版：`cw:identity-tags`、四个按钮文案都在 `app.asar` 里
（上一版 `713cc164` 已接上），`identity-center.test.tsx` 16 条也全绿。**jsdom 测得到"有没有 handler"，
测不到"点了以后世界有没有变化"** —— 这一条是这个 bug 的教训。

## 二、修法：只接**真实存在**的东西，一个都不编

| 页面元素       | v2 做什么                                                                                                                                            | 数据来自                                                                                 |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| **客群卡**     | 换成**真实内置助手**（罗盘 / 内容创作 / 短视频 / 电商运营 / 高效办公 / 学习研究 / 生活家庭），点一下**真的切助手**（`useSelectAgent`），当前助手高亮 | `lib/assistant-task-presets.ts` 的 `ASSISTANT_ID_BY_WORKSPACE` + `agentCatalogByGateway` |
| **画像正文**   | 随（客群 + 标签）**实时变化**（纯函数），点一下标签立刻看得见文字变了                                                                                | 新增 `lib/identity-persona.ts` 的 `describeIdentity()`                                   |
| **保存并应用** | 切助手 + 把身份块**合并写进每个助手的 `USER.md`**（读→合并→写，带标记，≤4000 字符）                                                                  | `window.clawwork.getAgentFile/setAgentFile`（记忆页同一条通道）                          |
| **推荐技能**   | 换成**该助手真实的四件事**（不再是编的 7 个技能名）；本轮仍是展示，点击开任务记为待办                                                                | `ASSISTANT_TASK_IDS` + presets 的 i18n 标题                                              |

**为什么要写进 `USER.md`**：它是运行时**每一轮都注入**的 6 个文件之一（`agents.files.set` 白名单内），
是"身份配置真的生效"的唯一真实承载位。**不许覆盖用户已有记忆** ⇒ 必须读→合并→写，
用 `<!-- 身份中心 --> … <!-- /身份中心 -->` 标记包裹，重复保存是替换而不是追加。

**如实报错**：没有网关 / 读不到 `USER.md` / 部分助手写失败 ⇒ 按现有口径如实说（几个没写成），
**不许**报"已保存"。切助手那条路（`missing` 态）沿用现有 `AgentMissingNotice`，不动。

## 三、判据（可证伪）

1. 点「电商运营」⇒ 左侧当前助手变成电商运营，页面高亮跟着变（真机 + 单测）；
2. 点任意标签 ⇒ **画像正文文字发生变化**（精确串断言，不是"元素存在"）；
3. 点「保存并应用」⇒ `getAgentFile` 先读、`setAgentFile` 写入的内容**包含**标记块与所选标签，
   且**原有内容仍在**（回归：绝不覆盖用户记忆）；超 4000 字符 ⇒ 如实报错且不写；
4. 无网关 ⇒ 不写、不切、如实报错；
5. ⭐ **回归守卫**：任何一个主控件点下去，**必须有一次可观察的 DOM 变化**（本次反馈的形状）。

## 四、刻意不做（本轮）

- 客群卡与"新建任务"打通（点击直接开一个该助手的任务）—— 记 0.0.35 待办；
- 「其它客群」里**没有对应助手**的四个名字（教育工作者/法务合规/研发工程师）**不再假装存在**：
  它们从页面上消失，换成真实助手 —— 编一个不存在的角色比少一个入口更坏。
