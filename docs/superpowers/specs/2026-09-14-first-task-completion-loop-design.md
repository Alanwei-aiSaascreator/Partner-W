# 荣盈魔方首次任务闭环设计

**日期：** 2026-09-14

**阶段：** Stage 3B 大众版功能完善

**目标：** 让首次使用者从首页选择一个常见任务后，进入正确的专业助手，获得一条真实回复，并得到明确而克制的下一步引导。

## 一、问题

当前首页已经提供个性化快捷任务，也可以安装六个独立 Agent，但两者尚未形成完整路径：

1. 点击快捷任务只会填入提示词，不会选择对应的专业 Agent。
2. 用户收到第一条真实 AI 回复后，界面没有说明任务已经完成，也没有可执行的后续动作。
3. 已有 Dashboard 能展示真实使用数据，但首次任务结束后没有入口引导用户认识积分消耗。

本批次只补齐首次任务闭环，不修改登录、计费、模型调用、消息持久化、License 或设备激活逻辑。

## 二、用户路径

```text
个性化首页
→ 点击内容 / 拍摄 / 办公 / 电商 / 研究 / 家庭快捷任务
→ 如果对应专业 Agent 已安装，则把待创建任务切换到该 Agent
→ 如果对应 Agent 未安装，则由当前罗盘助手承接
→ 将任务模板填入输入框，用户可以修改
→ 用户主动发送
→ 收到非空的真实 assistant 回复，且本轮已结束
→ 消息流底部出现一次“第一次任务已完成”提示
→ 用户选择继续完善 / 开始新任务 / 查看使用情况
```

自定义目标不自动猜测角色，沿用用户当前选择的助手。系统不会替用户自动发送任何内容。

## 三、角色路由

快捷任务使用固定映射：

| 快捷任务 | 目标 Agent ID        |
| -------- | -------------------- |
| 内容创作 | `rongying-content`   |
| 拍摄剪辑 | `rongying-video`     |
| 办公提效 | `rongying-office`    |
| 电商运营 | `rongying-ecommerce` |
| 学习研究 | `rongying-research`  |
| 家庭生活 | `rongying-family`    |

路由规则：

1. 只有目标 ID 存在于当前网关的真实 `agents.list` 目录时才切换。
2. 目标 Agent 不存在时不触发安装，不显示错误，保留当前有效助手。
3. 选择目标 Agent 后更新 `pendingNewTask`，ChatInput 仍通过原有 `commitPendingTask()` 创建正确 session key。
4. 已经存在空任务时，不改写其 session key；快捷入口只影响尚未提交的新任务。
5. 网关切换后重新按该网关目录判断，禁止跨网关引用 Agent。

映射作为纯函数放在预置 Agent 目录模块中，方便单元测试并避免 UI 重复定义 ID。

## 四、首次完成判定

首次完成提示必须来自真实消息状态，不使用计时器、假进度或前端模拟回复。

一次任务满足以下全部条件时视为完成：

1. 当前账号尚无完成记录。
2. 当前任务中至少有一条 `user` 消息。
3. 用户消息时间不早于该账号的 `onboardingProfile.completedAt`。
4. 用户消息之后存在一条内容非空的 `assistant` 消息。
5. 当前任务没有等待、流式输出或尚未完成的工具调用。

完成记录按账号存入本地存储：

```text
rongying-cube:first-task:v1:<userId>
```

记录内容包含 `taskId`、`completedAt` 和 `assistantMessageId`。写入失败不会影响聊天，但本次会话仍显示提示；下次启动可能再次出现。

为避免老用户升级后看到错误提示，只有发生在首次用途设置完成时间之后的任务才参与判定。

## 五、完成提示

完成提示作为消息流中的普通内容块，位于首条合格 assistant 回复之后，不悬浮、不遮挡输入框，也不使用等级、经验值、勋章或庆祝动画。

内容包括：

- 标题：第一次任务已完成
- 说明：结果已经保存在当前任务中，你可以继续完善，也可以开始下一件事。
- `继续完善`：把一条可编辑的后续要求填入输入框，不自动发送。
- `开始新任务`：调用现有 `startNewTask()`，返回个性化首页。
- `查看使用情况`：打开已有 `dashboard` 页面。
- 关闭按钮：只隐藏当前提示，完成记录仍保留。

继续完善的默认文本只要求检查、补充和整理刚才的结果，不声称任务质量已经达到某种标准。

## 六、组件边界

### `preset-agents.ts`

新增快捷任务到 Agent ID 的纯映射和解析函数。它只负责产品预置关系，不读取网关或修改状态。

### `first-task-milestone.ts`

负责存储键、记录解析、合格消息判断和记录写入。该模块不依赖 React，不写消息数据库。

### `FirstTaskCompletionCard.tsx`

负责展示完成提示和四个操作入口。所有文案来自 i18n，动作由父组件传入。

### `WelcomeScreen.tsx`

在快捷任务点击时先解析已安装目标 Agent，再更新待创建任务，最后填入提示词。自定义目标保持现有行为。

### `MainArea/index.tsx`

组合当前任务消息与活动状态，决定何时显示完成提示；处理继续完善、开始新任务和打开 Dashboard。它不新增任何消息持久化路径。

## 七、状态与错误处理

- Agent 目录尚未加载：保留当前助手并正常填入提示词。
- 目标 Agent 未安装：保留当前助手，不中断用户。
- 本地完成记录损坏：视为未完成，并在下一次真实完成后覆盖。
- 本地存储不可写：界面仍可使用，不弹阻断式错误。
- Dashboard 获取数据失败：沿用 Dashboard 现有错误和空状态。
- 切换任务或网关：只根据当前任务、当前账号和当前网关重新判断。

## 八、测试与验收

### 单元测试

1. 六类快捷任务映射到六个稳定 Agent ID。
2. 已安装目标返回专业 Agent，未安装目标返回当前有效助手。
3. 完成记录按账号隔离，损坏数据安全降级。
4. 只有用途设置完成后的真实 user → assistant 完整往返才算首次完成。
5. 流式输出、空 assistant 消息、只有历史消息和只有用户消息均不触发。

### 组件测试

1. 点击已安装角色的快捷任务会更新待创建 Agent 并填入草稿。
2. 未安装角色时只填入草稿，不切换到不存在的 Agent。
3. 完成提示展示三个主操作和关闭入口。
4. “继续完善”只填入草稿，“开始新任务”清空当前任务，“查看使用情况”进入 Dashboard。

### 回归验收

1. 原有手机号登录、用途设置、模型选择和真实回复不受影响。
2. 不新增 assistant 消息写入路径，不改变 session key 规则。
3. 浅色与深色主题下，完成提示不遮挡消息和输入框。
4. `pnpm check` 除已登记的既有 UI-contract 存量问题外无新增失败。
