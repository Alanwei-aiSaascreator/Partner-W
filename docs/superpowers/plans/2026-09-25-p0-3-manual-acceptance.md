# P0-3 人工验收清单：登录 → 网关 → 付费模型 → 助手 → 真实回复

**为什么这份只能人工**：这条路要**真实短信验证码**和**一张真的付费卡**，两样都不是代码能
替代的。**自动化跑不了它**，所以它必须写成一份照着做就能得出"过 / 不过"的清单。

## ⛔ 两条纪律（执行之前先读）

1. **验证码只在客户端里输入**。任何情况下都不要把验证码发给别人（**包括发给 AI 助手**）。
   如果哪一步要求你交出验证码，那一步就是错的 —— 停下来，把它当缺陷报。
2. **这份清单不改任何代码、不改任何服务端数据**。它只观察、只记录。

## 前置

| 项         | 要求                                                             | 怎么确认                 |
| ---------- | ---------------------------------------------------------------- | ------------------------ |
| 一块盘     | exFAT 或 NTFS（⛔ **FAT32 不行**：网关读写工作区身份文件必失败） | 盘属性里看文件系统       |
| 一个手机号 | 能收短信                                                         | —                        |
| 一张卡     | **没有被别的组织绑过**（见下面「已知限制」第 1 条）              | 卡密后台查；绑过就换一张 |
| 客户端     | 装上即可（装机器版或便携版都行）                                 | —                        |

## 主链（按序做，每步都有判据）

| #   | 动作                                                        | **判据**（看得见的结果）                           | 不通过时先看什么                                                                 |
| --- | ----------------------------------------------------------- | -------------------------------------------------- | -------------------------------------------------------------------------------- |
| 1   | 打开应用 → 输入手机号 → 收到短信 → **在客户端里**输入验证码 | 进到主界面；左上有助手名字                         | ① 登录页有没有报错文案 ② 日志里 `commercial.auth.probe` 的 `verdict`             |
| 2   | 等"准备"那条横幅消失                                        | 横幅**不再转圈**，出现助手与输入框                 | ① 横幅上那句话**逐字**记下来（它现在会说是哪一类失败）② 等了多久（面板上有秒数） |
| 3   | 设置 → 激活 → 输入卡密                                      | 提示激活成功                                       | 若说"**属于另一个组织**" ⇒ 见「已知限制」第 1 条                                 |
| 4   | 等模型列表                                                  | 模型下拉里**列得出模型**（不是"暂无可用模型"）     | ① 设置→关于 里的更新频道无关 ② 日志 `relay.bootstrap` 那条的状态码               |
| 5   | 新建一个助手（或用预置的）                                  | 助手出现在左列，能选中                             | 助手卡片是否点得动                                                               |
| 6   | 发一句普通的话（比如"你好"）                                | **收到真实回复**（不是一直转圈、不是"模型不可用"） | ① 输入框上方有没有错误条 ② 日志 `chat` 相关事件                                  |

**判据是"用户看得见的结果"，不是"命令返回 0"。** 六条全过才算这条链过。

## 换账号那一段（**单独验**，别与主链混）

同一块盘上换账号是本轮**明确不迁移**的东西（不做按账号分区），所以它有**已知的行为**：

| #   | 动作                                                 | 预期                                      |
| --- | ---------------------------------------------------- | ----------------------------------------- |
| 1   | 主链跑完之后，退出登录                               | 回到登录页                                |
| 2   | 换**另一个手机号**登录                               | 能登录成功                                |
| 3   | 看模型列表                                           | ⚠️ **很可能说"这张激活卡属于另一个组织"** |
| 4   | 设置 → 激活 → **换一张卡**（输入第二个账号自己的卡） | 激活成功、模型列表回来                    |

⚠️ **第 3 步是设计后果，不是缺陷**（卡存在盘上，退出登录不清它 —— 见
`main/commercial/auth.ts` 的 `signOutCommercial`：它只退会话，不碰 `licenseKey`）。
**要验的是第 4 步走得通**：出口必须存在、必须好找。

## 已知限制（**验之前先知道**，别把它当新缺陷）

1. **卡一旦绑了组织就永不换绑**（服务端迁移 56 定的，防串卡）。
   卡绑在你**以前的公司号**上、而你现在用个人号 ⇒ **客户端没有任何自助出路**，
   只能找运营侧改。⇒ **前置里才要求"没有被别的组织绑过的卡"**。
2. **卡跟盘走，不跟账号走**：同一块盘换账号，盘上还是上一张卡。
   这是本轮的明确边界（不做按账号分区迁移）。
3. **改绑仍然没有自助出路** —— 这一条**未拍**，不是本轮的产物。

## 不通过时抓什么（三条，按顺序）

1. **那条横幅上的原话**（逐字，含它说的类别）。
2. **调试日志**：`<盘根>\Partner-W-运行数据\logs\debug-*.ndjson`
   （装机器版在 `%APPDATA%\@clawwork\desktop\logs\`）。
   关键事件名：`relay.bootstrap`、`commercial.auth.probe`、`gateway.ws.close`、
   `runtime.bootstrap.*`、`renderer.runtime_status.read_failed`。
3. ⚠️ **日志里可能有凭据**：贴出来之前先扫一遍，别把 `token` / 卡密 / 手机号发出来。

## 这份清单**不**覆盖的

- 真机上的**网关失败三类**（端口被占 / 凭据被拒 / 等就绪超时）：那要另外造场景
  （比如先开第二个实例占住 18789），见 integration worktree 的第一批任务。
- 便携更新的下载与换目录：那是 A 线的 0.0.31 → 0.0.32 验收。
