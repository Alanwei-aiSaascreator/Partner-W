# 对标 WorkBuddy 的差距表 + 准 1.0 八小时排程（2026-09-26）

**怎么读出来的**：WorkBuddy 5.6.2 装在本机（`F:\edge doenloads\WorkBuddy`），
它的 renderer 有 **831 个 Vite 懒加载 chunk** —— **chunk 名就是功能名**，等于一张产品功能地图。
下面是**只读**读出来的，不是猜的（⚠️ 它的中文文案在远端下发，**结构拿得到、行文拿不到**）。

## 一、差距表（按"用户碰得到"排序）

| 能力                       | WorkBuddy                                                                            | 我们                                            | 差在哪          |
| -------------------------- | ------------------------------------------------------------------------------------ | ----------------------------------------------- | --------------- |
| **应用内预览 Office 文件** | ✅ `pdf-preview` / `docx-preview` / `pptx-preview` / `sheet-preview`（各有独立组件） | ❌ **只有图片 / Markdown / 代码**               | ⛔ **最大缺口** |
| **生成 Word/Excel/PPT**    | 未见表（它偏"看"）                                                                   | ✅ **有**（docgen，能产真 `.docx/.xlsx/.pptx`） | ⭐ **我们领先** |
| 拖拽上传                   | ✅ `document-upload-dock` + `document-upload-runner`                                 | ❓ 待核                                         | 待定            |
| 打开/保存对话框            | ✅ `file-open-*` / `file-save-*`                                                     | 部分（存为有）                                  | 待核            |
| "我的文件"                 | ✅ `my-files`                                                                        | ✅ FileBrowser（叫"产物"）                      | 叫法不同        |
| 记忆面板                   | ✅ `MemorySettingsPanel`                                                             | ❌ 一期未做                                     | **计划内**      |
| 知识库                     | ✅ `knowledge-base-panel`                                                            | ✅ 资料库                                       | 平              |
| 技能市场                   | ✅ `skills-market` / `skill-picker`                                                  | ✅ 技能市场                                     | 平              |
| **MCP 同意卡**             | ✅ `McpPoiConsentCard`                                                               | ❌                                              | 走 MCP 联网时要 |
| 终端视图                   | ✅ `desktop-terminal-view`                                                           | ❌                                              | **不做**        |
| 自动化                     | ✅ `automation-panel`                                                                | ❌                                              | **不做**        |
| 同事协作                   | ✅ `colleagues` / `colleague-artifact-detail-panel`                                  | ❌                                              | **不做**        |
| 深链（会话可寻址）         | ✅ `conversation-route` / `deeplink`                                                 | 原语有，用得少                                  | 低优先          |

### ⭐ 这张表里最要紧的一行

**我们自己就能生成 `.docx / .xlsx / .pptx`，但用户在应用里看不见它们** ——
`FilePreview` 只认图片 / Markdown / 代码 ⇒ 用户只能"导出之后用 Office 打开"。
**做出来的东西自己看不见**，这是 1.0 之前最该补的一处。

## 二、文件预览怎么做（按代价从低到高）

| 格式     | 办法                                                                                                       | 新依赖       | 代价 |
| -------- | ---------------------------------------------------------------------------------------------------------- | ------------ | ---- |
| **PDF**  | **Electron 自带 Chromium PDF 阅读器** —— iframe 指文件即可                                                 | **零**       | 极小 |
| **XLSX** | **`exceljs` 我们已经在依赖里**（P2 装过），直接读工作表                                                    | **零**       | 小   |
| **DOCX** | `docx-preview`（纯前端渲染）或 `mammoth`（转 HTML）                                                        | 一个纯 JS 包 | 中   |
| **PPTX** | **没有现成好库** ⇒ `jszip`（`pptxgenjs` 的依赖）解包 → 抽文字与图片 → 做**简版预览**（逐页列出标题与正文） | **零**       | 中   |

⚠️ 一律**在渲染进程里读**、**只读**、**不落临时文件**；
⛔ 不许为了预览把文件写到工作区外面（红线）。

## 四、明确不做（省掉期待）

- **代码签名 / 360 拦截** —— 要证书，不是代码问题
- **任何未单独授权的打包 / 发布 / 迁移生产**
