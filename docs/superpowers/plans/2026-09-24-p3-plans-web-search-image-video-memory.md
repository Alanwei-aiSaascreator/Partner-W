### 计划

1. **只读核实**（第一小时）：`mcp.servers` 管道在本线是否存在（grep 配置 schema + 网关侧 `mcp` 相关能力）；`enable_search` 的接线点是否与它冲突（两条路同时开会重复计费）。
2. 定义范围：哪些助手/任务允许联网；默认开还是显式开；单次搜索的成本上限。
3. 计费口径：成本并入积分（[[search-cost-into-credits]]，毛利 37.5%）；⚠️ 记忆里那条**"按调用还是按动作计费未验"**必须先量出来。
4. 验收标准（真机 + 真账号）：一次真实搜索请求走通；积分扣减与成本口径一致；搜索结果里**不出现任何 key**；关掉开关时行为与今天一致。
5. 灰度与回滚：开关默认关；按助手白名单逐步开；回滚 = 关开关。

### 要用户拍

## 3. 自我感知 / 记忆 / 发芽笔记（P3.3）

**只做**：按**已提交的规格**拆计划。**不进 0.0.27 稳定版。**

### 已拍的约束（不要再讨论）

- 记忆**必须随盘走**（[[memory-feature-product-decisions]]）；一期**只做确认轨道**（双轨写里的确认那条），自建落盘。
- 资料库**落 U 盘、不上云**，嵌入用**本地 ONNX**（[[kb-udisk-local-self-learning]]）。
- 助手提示词只由 **6 个硬编码文件**注入，**不能自造 `PERSONA.md`**（[[agent-prompt-files-are-fixed-six]]）。
- `memory_search` 曾**宣传一个关掉的能力** ⇒ 要用 `tools.deny` 摘掉（[[memory-search-advertised-but-disabled]]）；"工具可见"≠"能力可用"。

### 计划骨架

1. 一期范围：写入口（用户显式"记住这条"）+ 确认轨道 + 读出口（召回进上下文的方式与预算）+ 隐私出口（查看/删除/导出）。
2. 落盘位置：记忆随盘 ⇒ 放工作区；**不进**网关 state 目录（那条路被 exFAT 堵死）。
3. 与资料库的边界：记忆是"用户要求记住的"，资料库是"用户放进去的文档"—— 召回通道要不要共用，要定。
4. 验收标准：写→重启→读得到；跨机器（换电脑插同一块盘）读得到；删除后确实不再召回；越权（别的账号/别的盘）读不到。
5. 明确**不做**：不做云端记忆、不做自动写入（一期）、不碰网关 state。

### 要用户拍

- 一期是否就按"显式写 + 确认轨道 + 查看/删除"做（其余留二期）。
- 记忆与资料库的召回通道共用还是分开。

### 6.5 ⭐ 计费：按张/按秒**没有任何承载位**（这条最要紧）

| 层         | 现状                                                                                                          | 证据                                                          |
| ---------- | ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| 单位       | 1 元 = 100 积分 = 100 分 = 1e8 微积分；价格列单位是「分 / 百万 token」                                        | 迁移 23 头注释、`20260910000003_mvp_closure.sql:26,33`        |
| 计价公式   | **唯一**自变量是三个累计 token 量                                                                             | `20260921000057_report_usage_v3_license_identity.sql:247-256` |
| 账本表     | `usage_reported_totals(cum_input, cum_output, cum_cached, …)`、`usage_records(input/output/cached_tokens, …)` | `20260910000003:42-61`、`20260910000002:22-34`                |

⇒ 「按张计费」缺的不是金额单位（账本本来就是纯金额），而是**"量 → 金额"那一段输入**：
要么给 ledger 加"张数/秒数"这类维度 + 价目表加对应列，要么在 relay 侧换算成等效金额再进现有口径。

### 6.6 ⚠️ 上游 usage 归一化会把"只有张数"的返回**静默吃掉**

`extractUsage`（`services/relay/src/upstream.ts:14-35`）只认 OpenAI 风格
`prompt_tokens` / `completion_tokens` / `prompt_tokens_details.cached_tokens`，非数字或非正一律归 0；
三个值全 0 ⇒ relay **静默早退**（`index.ts:495-526`：不发计费 RPC、不写 `usage_records`，
只补一条 `log_billing_usage_zero_before_rpc` 诊断）⇒ 表现是
**「模型调用成功、余额不动、账上哪儿都查不到」**。

⇒ 图像/视频模型那种"没有 token、只有张数"的返回**走现有口径必然落进这条静默路**。
这条必须在接图像模型**之前**先解决（否则就是白白送出去的调用）。

### 6.7 现在能回答"要用户拍"的那几条
