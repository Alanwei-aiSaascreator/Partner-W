## 1. 联网搜索（P3.1）—— 采用已选的**官方 MCP** 方案

### 现状（两条互不相干的路，别混）

| 路径                                        | 现状                                                                                               | 依据                                                                |
| ------------------------------------------- | -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| ① 百炼内置 `enable_search`                  | **已在生产**：relay catalog 里对支持的模型开 `enable_search`（`83c40616`，qwen-plus / qwen-turbo） | 记忆 [[bailian-enable-search-facts]]、[[openclaw-web-search-facts]] |
| ② 官方 MCP（用户 2026-09-21 拍的 **B 案**） | ⚠️ **未实施**；当时记录「`mcp.servers` 管道不存在」，**这条必须先在当前线上重新核实**              | [[udisk-realdisk-findings-2026-09-21]]                              |

### 计划

1. **只读核实**（第一小时）：`mcp.servers` 管道在本线是否存在（grep 配置 schema + 网关侧 `mcp` 相关能力）；`enable_search` 的接线点是否与它冲突（两条路同时开会重复计费）。
2. 定义范围：哪些助手/任务允许联网；默认开还是显式开；单次搜索的成本上限。
3. 计费口径：成本并入积分（[[search-cost-into-credits]]，毛利 37.5%）；⚠️ 记忆里那条**"按调用还是按动作计费未验"**必须先量出来。
4. 验收标准（真机 + 真账号）：一次真实搜索请求走通；积分扣减与成本口径一致；搜索结果里**不出现任何 key**；关掉开关时行为与今天一致。
5. 灰度与回滚：开关默认关；按助手白名单逐步开；回滚 = 关开关。

### 要用户拍

- 走 ①（已上线、零开发）**还是** ②（官方 MCP，要新管道）？—— 若走 ②，是否接受它相对 ① 的额外延迟与成本？
- 搜索成本**按调用**还是**按动作**计价（未验的那条）。

## 2. 文生图 / 文生视频（P3.2）

**只做**：最小实施计划 + **第一小时 API 权限验证**。**不接入生产。**

### 第一小时（只读、不接生产）

1. 列目录：relay `/v1/catalog` 里有没有图像/视频模型（现在 13 款里没有 ⇒ 大概率要新开 provider）。
2. 账号权限：拿**服务器侧**的 key 做一次**最小**的图像生成调用（提示词固定为一个词、请求 1 张、记耗时与费用），确认百炼/方舟账号**是否已开通**该模型；**key 不出服务器**。
3. 记录：模型 id、单张/单条成本、最长耗时、失败码表（内容审核、排队、超时）。

### 计划骨架（验证通过后再展开）

- 产物落盘：图片/视频进工作区（**随盘走**），不进资料库索引。
- 计费：**并入积分**（与搜索同口径）；单次上限 + 单日上限。
- 提示词与产物的合规面：是否需要在界面上标注"AI 生成"。
- 验收标准：一次真实生成 → 文件落盘 → 可在会话里引用 → 积分扣减正确；失败时有分类文案（内容审核 / 排队超时 / 额度不足）。
- ⛔ 不进 0.0.27/0.0.28 稳定版。

### 要用户拍

- 先做**文生图**还是两者一起；是否允许"生成的东西自动进工作区"。
- 单次/单日成本上限。

## 3. 自我感知 / 记忆 / 发芽笔记（P3.3）

**只做**：按**已提交的规格**拆计划。**不进 0.0.27 稳定版。**

### 已拍的约束（不要再讨论）

- 记忆**必须随盘走**（[[memory-feature-product-decisions]]）；一期**只做确认轨道**（双轨写里的确认那条），自建落盘。
- 资料库**落 U 盘、不上云**，嵌入用**本地 ONNX**（[[kb-udisk-local-self-learning]]）。
- 助手提示词只由 **6 个硬编码文件**注入，**不能自造 `PERSONA.md`**（[[agent-prompt-files-are-fixed-six]]）。
- `memory_search` 曾**宣传一个关掉的能力** ⇒ 要用 `tools.deny` 摘掉（[[memory-search-advertised-but-disabled]]）；"工具可见"≠"能力可用"。

### 计划骨架

1. 一期范围：写入口（用户显式"记住这条"）+ 确认轨道 + 读出口（召回进上下文的方式与预算）+ 隐私出口（查看/删除/导出）。
2. 落盘位置：记忆随盘 ⇒ 放工作区；**不进**网关 state 目录（那条路被 exFAT 堵死）。
3. 与资料库的边界：记忆是"用户要求记住的"，资料库是"用户放进去的文档"—— 召回通道要不要共用，要定。
4. 验收标准：写→重启→读得到；跨机器（换电脑插同一块盘）读得到；删除后确实不再召回；越权（别的账号/别的盘）读不到。
5. 明确**不做**：不做云端记忆、不做自动写入（一期）、不碰网关 state。

### 要用户拍

- 一期是否就按"显式写 + 确认轨道 + 查看/删除"做（其余留二期）。
- 记忆与资料库的召回通道共用还是分开。
