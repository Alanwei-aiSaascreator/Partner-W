## A 更新验收线

**只做**：`0.0.31 → 0.0.32` 的 **internal 真盘验收**。

- ⛔ **不得**改业务代码 / UI / 版本号 / launcher / 更新脚本。
- ⏸ **等发布授权**后才动；**只发 internal**，⛔ 不碰 `stable`、不碰 `latest.yml`。
- 验收判据（缺一条都算没通过）：
  1. 频道切 `beta` ⇒ 检查更新**看得到 0.0.32**；
  2. 下载 → 校验 → 解压 → **只点一次** → 自动重启；
  3. 盘根 **launcher 哈希不变**（`703eca85…`）；
  4. `荣盈魔方-运行数据` / `荣盈魔方工作区` **逐文件哈希不变**（验收前先放真数据）；
  5. 健康回执 `version = 0.0.32`；
  6. **真实登录 + 一轮聊天正常**。
- 脚本与读数：`docs/runbooks/portable-update-real-disk-acceptance.md` 的「本次实例」。
  回滚演练那一节**必须先跑**（它不需要发布）。

## B 基础功能线

**只允许这三个优先级，按序做**：

1. 登录后「正在准备模型 / 启动 AI 服务」**超过合理时间**的问题；
2. **付费账号的模型列表与真实聊天**；
3. **团队 Agent 点击后必须进入对应对话**（不能跳主罗盘）。

**做法**：先**复现**、留证据（日志/截图/时间线），**再** TDD 修。
⛔ 不得碰 `launcher/`、`scripts/` 里的更新脚本、`packages/desktop/package.json` 的 `version`。

## C UI / 新功能线

**只做用户立刻看得见的改善**：

1. 准备模型：显示**真实阶段**、**超时**与**重试入口**；
2. 网关 / 授权失败：显示**明确原因**；
3. 团队 Agent：**卡片与对话入口**。

- 本轮要加 AI 能力的话，**只做"文生图"一个闭环**；
  ⛔ **文生视频 / 图生视频排下一版**，不为赶时间塞进当前内测包。
- 所有 UI 文案走**现有 i18n**；⛔ 不改更新与登录主链。

### ⚠️ B3 与 C3 会撞在同一片区域（必须遵守的切分）

两条线都碰"团队 Agent"。**按职责切，不按文件切**：

- **B3 负责行为**：点击之后**路由到哪**、进不进对应对话（`useGatewaySelector` / 任务归属 / 导航那一层）；
- **C3 负责呈现**：**卡片长什么样**、入口怎么摆、文案（组件与 i18n 那一层）。

⇒ B 线**不要**为了让入口好看去改组件；C 线**不要**为了让入口能点去改路由。
真需要对方那一层配合，先在各自线里停下、说清楚，而不是顺手改。

## 共同纪律

- **每刀独立提交**：`git commit -- <显式 pathspec>`，⛔ **不用 `git add -A`**（本仓栽过多次）。
- ⛔ **不打包、不发布、不改 feed**（除 A 线拿到单独授权后发 internal）。
- 🚨 **发现 P0（登录失败 / 聊天失败）立即停 UI 花活，优先修 P0** —— 三条线都适用。
- 提交信息**英文**（仓库规矩）；文档可以中文。
- 每刀：RED → GREEN → **变异电池** → 门禁（`pnpm check` RC=0）→ 独立提交。
- 临时文件不写进仓库（`mktemp` / `%TEMP%`）。
