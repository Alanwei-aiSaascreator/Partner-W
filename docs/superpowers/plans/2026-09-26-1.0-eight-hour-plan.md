## 二、八小时排程

### H1（0:00–1:00）· 基线收口

- 集成分支理干净、把这一轮的账本补齐；建 `release/1.0`。
- 跑一次**全门禁**确立基线（`pnpm check` RC=0）。
- **判据**：基线绿、工作树干净、每一刀的提交都能追。

### H2（1:00–2:30）· 联网搜索：让功能**可见**

- 功能是现成的，缺的是"用户够得着"。做法（**方案 B**）：
  设置里一个**联网开关**，**只在支持的两款模型上可点**，不支持时**说明为什么**。
- 9 个 locale + 测试 + 变异验证。
- ⚠️ **不许全开**：百炼对不支持的模型是**直接报错**，全开会把 deepseek/glm/kimi/doubao 一起打挂。
- **判据**：切到 `qwen-plus` 能开关；切到 `deepseek` 开关是禁用的**且写明了原因**。

### H3（2:30–4:00）· 记忆一期

- 第一层：`USER.md`（≤4,000 字符硬上限）。
- 确认轨道：助手**只提草案**，用户点头才落盘（"它自己写"这一期关掉）。
- 落盘位置跟着**盘**走（不是机器）。
- **判据**：草案能提、能拒、能改；拒绝之后不再重复提同一件；换机器插盘记忆还在。

### H4（4:00–5:00）· UI 打磨第一批（收口类）

- **整屏门禁那个死组件**：按复核结论处理（搬文案 → 删组件），**不许**让它继续"有测试、没人看"。
- `presentationPathFor` 死代码删除（复核结论：可删，**打包产物里本来就没有它**）。
- 关于页那句「用新的文件夹替换」在 `available` 相位**不许**再出现（0.0.33 起已有下载入口）。
- **判据**：删掉的每条都有测试跟着删/改；`check:dead-code` 与 `layouts-reachability` 都绿。

### H5（5:00–6:00）· 细节补齐

- **`使用说明.txt` 按新版重写**（版本专属、不在仓库，盘上那份还是 0.0.27 的）。
- **商业调用 8 秒超时**：只读定位根因；**能在这一小时里修就修，修不了就如实登记**（不硬凑）。
- **团队助手跨机器**：这一轮**只做真实运行时核查**（注册表在机器本地、盘上没名字）——
  ⛔ 核查之前**不写一行代码**。
- **判据**：使用说明逐项对得上这一版；核查结论写进账本。

### H6（6:00–7:00）· 合规二期 ⚠️ **要你一句话**

- `user_agreements` 表 + `record_agreement` RPC（**IP 由服务端取，不信客户端**）+ 版本单一真源 +
  启动比对进"需重新确认"门禁。
- 另两处口径差异（**埋点披露**、**注销路径**）二选一：**改文本** 或 **改实现**。
- ⚠️ 这一项**要往生产推迁移** ⇒ 是**另一道授权门**，我不会自己开。
- **判据**：登录页那个勾选框**真的落库**；改了协议版本能触发"需重新确认"。

### H7（7:00–7:30）· 集成 + 全门禁

- 所有刀合进 `release/1.0`；`pnpm check` **RC=0**；全量测试读数记进账本。

### H8（7:30–8:00）· 打 0.0.34 + 发布 + **真机验证更新链**

- 版本号 → 构建 → 签名 → **独立复核**（公钥从出货启动器里当场取）。
- 发 internal。
- ⭐ **你在界面上点一次**（检查更新 → 下载并准备 → 立即重启）——
  **这才是"更新能用"的唯一证明**，也是这一轮最重要的一个动作。
