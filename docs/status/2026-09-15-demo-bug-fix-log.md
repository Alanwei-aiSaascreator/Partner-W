## 2026-09-17 新增缺陷：多问题回答丢失导致 Word 任务锁死

### 现象

内容创作助手在生成 Word 前同时询问“科目”和“文档类型”。用户回答或继续发送完整提示词后，任务仍持续报错：

`GatewayClientRequestError: question 'doc_type' requires an answer`

### 已确认根因

- Gateway 正常创建了包含 `subject` 与 `doc_type` 两个必答项的 `ask_user` 请求。
- 桌面端后续调用 `question.resolve` 时只提交了部分答案，遗漏 `doc_type`。
- 未完成的问题继续保持 pending；同一会话内的新消息被 reply resolver 当作旧问题答案处理，因此普通提示词无法开始新任务。
- `doc_type` 是内部字段名，直接显示给用户属于错误信息泄漏和中文体验缺陷；Word 文件及 Word 生成能力本身没有损坏。

### 临时恢复办法

1. 新建会话后重新提交任务，并明确要求直接生成、不再追问。
2. 若新会话仍继承异常状态，完全退出并重启客户端，以清除内存中的挂起问题。
3. 不在已锁死的旧会话中反复重试。

### 正式修复要求

- 多个必答问题必须全部有答案后才能调用 `question.resolve`。
- 未答项目应在界面明确标出，并保持问答卡片可见。
- 提交失败后不得吞掉用户的新消息或让会话永久卡在 pending 状态。
- 提供“取消问题 / 跳过并继续 / 重新回答”入口。
- 用户已在原始任务中明确科目和文档类型时，应优先自动补全，避免重复追问。
- 将内部错误转换为中文提示，例如“请选择文档类型后继续”，不得暴露 `doc_type` 等字段名。

### 后续回归验收

1. 单个问题选择并提交。
2. 两个及以上问题全部选择后一次提交。
3. 漏选第二项时阻止提交并显示中文提示。
4. 自由文本同时回答多个问题时正确映射全部答案。
5. 取消、超时、重启和新建会话后不残留 pending 问题。
6. Word、表格及其他会触发澄清问答的任务均能继续生成成果文件。

## 2026-09-17 修复落地与根因订正

### ⚠️ 订正：Word 问答锁死的根因

前面那条「桌面端调用 `question.resolve` 时只提交了部分答案」**不准确**，别再照着它查。

实测（客户端调试日志 `%APPDATA%/@clawwork/desktop/logs/debug-2026-09-17.ndjson`）：
**桌面端整条问答链路从来就没实现过** —— 网关推来的 `question.requested` 事件在
`gateway-dispatcher` 里被静默丢弃（那里只认 chat / agent / sessions.changed / exec.approval）。
于是问题一直挂起，而网关会把该会话里用户发的**任何**新消息当成「答案」解析
（`resolvedBy: "plain-text"`），单行文本只能填第一题 ⇒ 抛
`question 'doc_type' requires an answer`，会话**静默 15 分钟**。
日志里 05:12:05 起用户发的 `你是谁` / `卡了吗` / `完整提示词` **全部被吞**，
直到 05:21:01 用户点中止（`chat.abort` 会顺带 cancel 掉挂起的问题）才恢复。
另：客户端连 `operator.questions` 权限都没申请（`operator.admin` 已覆盖，所以不是阻断点）。
