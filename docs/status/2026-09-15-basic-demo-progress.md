# 荣盈魔方基本盘 Demo 进度汇报

**日期：** 2026-09-15  
**当前分支：** `feat/stage3b-demo-polish`  
**评估口径：** 面向老板、合作方或首批体验用户，可以通过 Windows 安装包独立完成一条真实业务链路。

## 一、当前结论

荣盈魔方的**源码级基本盘 Demo 已经成形**，登录、激活、启动准备、助手、模型、真实 AI 回复、余额和用量已经能组成完整主路径。按功能完成度估算，源码主路径约完成 **85%–90%**。

目前还不能把现有安装包直接定义为最终 Demo 交付件。现有 `0.0.16` 安装包生成于 2026-09-12，晚于它完成的启动门禁、六助手准备进度和最新 UI 尚未完整进入该安装包。再加上两项会影响现场演示可信度的已知问题，当前“可发给别人独立演示”的完成度约为 **70%–75%**。

短期目标应收敛为：用一个最新 Windows 安装包，在全新电脑环境或全新用户数据目录中，稳定走完“登录—选择用途—激活—准备服务—选择助手与模型—获得真实回复—看到额度变化”的闭环。

## 三、正在收口和仍未完成

### P0：基本盘 Demo 发出前必须完成

1. **重新构建最新 Windows 安装包并做打包态彩排。** 当前 EXE 是旧快照，源码通过测试不能代表用户安装后的行为已经验证。
2. **修复激活时网关未连接的恢复链路。** 当前存在 `relay.config-no-gateway`：激活发生时若网关尚未连上，中转配置可能静默未写且没有可靠重试。这会让全新账号演示依赖启动时序。
3. **统一“界面选择模型”和“网关实际执行模型”。** 当前 composer 显示值与网关默认值可能不一致。消息级实际模型徽章可信，但首条消息可能没有使用界面所显示的模型。
4. **完成一次可重复的全新账号彩排。** 必须使用未绑定组织的新测试手机号，依次验证登录、用途选择、手动激活、启动准备、七个助手、模型选择、真实回复、余额或用量变化、退出重开。
5. **增加超时后的明确恢复入口。** 启动准备长期停留时，建议在约 90 秒后显示“仍在准备、检查网络、重新尝试”，避免用户继续判断为卡死。

### P1：基本盘 Demo 稳定后马上补

- “重新设置我的用途”：允许用户从身份中心修改场景和自定义目标，并立即刷新首页推荐。
- 账号画像云同步：同手机号换电脑后恢复用途、目标和偏好，同时保留本地副本。
- 优化六个助手的首屏示例任务、空状态和首次完成后的下一步引导。
- 收紧成果区的文件预览、导出和打开目录体验，使演示不止停留在聊天回复。

### 暂不纳入短期基本盘

- `license.key` 自动发现、USB 激活码自动删除、一次性兑换 RPC、`redeemed_at`、设备激活次数重构。
- 团队、技能市场、智能体市场、悬赏、广场、创作者中心和游戏化中心。
- 在线从 GitHub 下载助手。首版六个助手随客户端内置，避免安装过程受网络和第三方仓库影响。

这些属于后续商业化和平台化能力，不应占用当前 Demo 收口时间。

## 四、短期 Demo 应呈现的完整故事

演示时只讲一条容易理解的价值链：

```text
插入荣盈魔方 U 盘并启动客户端
→ 手机号登录
→ 选择“我想用它做什么”
→ 输入随 U 盘提供的激活码
→ 系统准备 AI 服务、模型和六个常用助手
→ 选择一个助手或直接描述任务
→ 选择模型并获得真实结果
→ 在使用概览中看到余额和本次实际消耗
→ 退出后在另一台电脑登录同一账号仍可继续使用
```

首场建议用“拍摄剪辑”或“内容创作”作为任务示例。例如用户输入一段产品资料，让助手生成短视频脚本、镜头清单和发布文案。这个场景能同时展示用途引导、专业助手、真实模型、连续修改和成果输出，比单纯问答更像一个可售卖产品。
