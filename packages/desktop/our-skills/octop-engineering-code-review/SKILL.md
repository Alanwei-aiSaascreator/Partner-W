# 代码变更审查

## 确认审查对象

明确目标提交或 diff、文件范围、验收条件及用户关注点。只有 PR 链接但无法读取时，请提供差异或说明访问缺口；未给对象先确认范围，不审不存在的代码。
优先读变更与直接调用链，区分本次新增缺陷和旧问题。读取适用的工程约定、已有测试及真实 CI 输出；测试绿不能单独证明业务可用。

## 四个审查维度

| 维度     | 必查内容                                                                 |
| -------- | ------------------------------------------------------------------------ |
| 安全     | SQL注入、XSS、CSRF、认证授权、代码内凭据、不安全反序列化、路径穿越、SSRF |
| 性能     | N+1查询、无谓分配、热路径O(n²)、缺索引、无界查询/循环、资源泄漏          |
| 正确性   | 空输入/null/溢出、边界偏移、并发竞争、错误传播、类型安全                 |
| 可维护性 | 命名、职责边界、重复逻辑、测试覆盖、非直观行为的说明                     |

对每个确定问题追踪可达输入、调用条件和用户影响；必要时在授权范围执行聚焦验证。发现测试被其他条件短路或断言错对象，要指出为什么其通过没有证明目标行为。推测与未验证项另列，不编造运行结果。

## 输出

1. 概述：变更解决的问题、整体判断、已核验范围。
2. 确定问题表：文件路径及行号 / 可达触发 / 问题 / 严重度 / 影响 / 证据。
3. 建议表：最小改法 / 类别 / 回归反例；需要代码示例时给最小片段，不默认直接改代码。
4. 已正确处理的关键边界（有证据才列）。
5. 结论：通过、请求修改或待讨论；列出测试命令、结果、未跑项。

## 可选资料

只有现有工具能读且用户范围允许时，读取 PR diff、CI 状态、关联工单和团队规范。未连接代码托管平台不影响审查本地差异；不自动发布评论、合并PR、创建工单。

## 执行与交付边界

不改变现有权限、工具审批、工作区和文件产物合同。技能是工作流程，不是额外工具、连接或执行授权；只使用当前实际可用且在任务授权范围内的工具与资料。没有连接器时使用本地或用户提供的材料，不宣称平台已接通。
发布、部署、生产处置与对外通知仅输出建议清单或草稿；本技能不默许执行，也不自动创建工单、通知他人或后台监控。实际执行须由获授权的流程另行处理。
需要文件交付时沿现有能力生成并写入允许位置，校验 → 登记 artifact → 用户能打开 才算成功；未保存的文本称草稿，未跑的验证标 NOT RUN，不虚报完成。
