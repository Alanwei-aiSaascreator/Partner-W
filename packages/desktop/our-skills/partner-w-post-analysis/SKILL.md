# 分析交付模板（岗位：分析师）

分析的价值在于**让用户敢拍板**。所以结论在前，过程在后，不确定的东西单列。

## 固定的五段结构

```markdown
# <要回答的那个问题>

## 一、结论

一到三句话。给不出确定结论时，直接写"证据不足，暂时不能下结论"，并写差什么。

## 二、依据

每条依据写：**事实 / 数据来源 / 它支持结论的哪一部分**。
数字必须带口径（时间段、样本、口径定义），没有口径的数字等于没有数字。

## 三、怎么算的

把推导过程写出来（公式、对比、假设表）。别人照着能复算出同一个数，这一段才算写完。

## 四、假设与风险

| 假设 | 成立时结论如何 | 不成立时结论如何 | 怎么验证 |
| ---- | -------------- | ---------------- | -------- |
| …    | …              | …                | …        |

## 五、下一步

最多三条，按性价比排序；每条写清"谁做、做什么、什么时候能看到结果"。
```

## 硬规矩

1. **不要用"综上所述"糊过去**。结论那一节必须能独立读懂。
2. **区分相关与因果**：只有相关性的，写"相关"，不要写"导致"。
3. **不给没有量纲的建议**："提升效率"不是建议；"把单次处理时间从 X 降到 Y"才是。
4. **发现输入本身有问题**（口径打架、数据缺失、目标互斥）时，**先停下来说这件事**，
   不要在一个坏前提上把分析做完。
5. 涉及金额、比例时给出**区间与依据**，不要给一个假装精确的数。

## 按行业调整

- 制造业：先算产能与在制品的约束，再谈排产优化；
- 金融 / 房地产：先定合规口径与现金流模型，再谈策略；
- 教育：先把目标写成可检验的结果，再设计过程；
- 租赁与商务服务：先算单位经济性（单客成本、续约率），再谈规模。

行业只影响**先算哪一个**，不影响上面的结构。
