# 幻灯版面（自己排）

要**拿给人看**、而且**内容不想被固定格子限制**的演示文稿，用这条路。

## 它和另外两条的区别

|                        | 怎么排的                       | 你受什么限制                                                                 |
| ---------------------- | ------------------------------ | ---------------------------------------------------------------------------- |
| 「文档生成」           | 客户端画白底 + 标题 + 项目符号 | 只能这样，**没有版式**                                                       |
| 「商务演示（模板版）」 | **填格子**进设计师做好的版     | 固定槽位有容量限制；超量内容可能拆页或转为备用版式，不能承诺固定页数与原版式 |
| **这条路**             | **你自己写版面**（CSS 布局）   | 单份上限 **1 MiB / 200 页**；⚠️ 且**必须写成文件**，贴进回复正文会被截断     |

⚠️ 如果内容很多，先按章节拆页，再走这条路；不要把一页十几条内容硬塞进固定格子。
反过来，**随手记点东西**别用它 —— 写版面比填格子慢。

## ⭐ 整份版面**写成一个文件**，不是写进回复

把整份源码**用写文件工具写到工作区里的一个文件**，文件名以 `.slidegen` 结尾，例如
`九月经营简报.slidegen`。客户端读的是**这个文件**，不是聊天里的字。

⚠️ **不要**把整份源码贴进回复正文。回复正文有一个**很紧的长度上限**，
贴进去会被截断，而截断之后**整份都作废** —— 用户什么都拿不到。
文件不受聊天展示截断，但写文件工具的参数仍受模型单次输出上限限制。长稿按下面的分段方法完成，不假定工具调用可以无限长。

- 文件**内容**照旧是**一个** `slidegen` 围栏块（就是要你平时放进回复的那种），
  **围栏必须闭合**。客户端按围栏取源码，缺了结尾围栏就取不出来。
  ⚠️ 开头与结尾那两行 ` ``` ` 都要**单独占一行** ——
  结尾的 ` ``` ` 若黏在 `</Slide>` 后面（写成 `</Slide>````），
  客户端就**认不出围栏已经结束**，会当作"没写完"而整份丢掉。
- **最终只有一份完整源文件**。先确定章节、每页要点和共享样式，使用当前实际提供的文件写入/编辑工具分段完成，每段控制在几页；不要一次输出整份长稿。中间片段用不含`.slidegen`的临时文件名，最后合并到同一个`.slidegen`文件，开头、共享声明和结尾围栏各保留一份。不要把未合并的片段提交为独立PPT，不得为了缩短而丢章节。
- 有执行能力时继续下面的本轮预检、生成和诊断，不要写完源码就结束。回复给出实际最终文件名、页数和仍未通过的检查，不要复述源码；没有执行能力时才说明**版面源文件已提交生成，请以右侧「产物」的实际结果为准**，不得把源文件说成已交付 PPTX。

> 为什么这样：真机上"整份写进回复"**连续四次**都因为超过上限被截断而失败；
> 而同一次**写进文件的那份是完整的**（13 KB）。

⚠️ **一栅最多 200 页**（`SLIDEGEN_MAX_PAGES`）。整册内容很多时请自己拆成几份，
不要一份写到 200 页以上 —— 超了整份不会生成。

## 本轮预检、生成与受限纠正

先确认当前会话实际提供`exec`或等效命令执行工具，且随包Node可用；只有技能文字不代表工具已授权。用现有执行工具，工作目录设为当前任务工作区，运行真实命令：

```text
node "<this-skill-dir>/scripts/preflight.cjs" "九月经营简报.slidegen"
```

`<this-skill-dir>`指**本技能目录**（`scripts/` 与本 SKILL.md 同目录）；先用现有工具定位它的绝对路径（列技能目录或读本文件路径），不要照抄占位符。引号必须保留，兼容中文和空格路径。命令只读取工作区内这份UTF-8源文件，不生成PPTX、不收费、不安装依赖。不要调用不存在的`slidegen_check`工具。

- 命令退出0、JSON的`status`为`source-valid`，才说明本版本的语法、组件求值和页数预算通过。`artifactCreated:false`与`visualReview:not-performed`明确表示尚未生成或视觉检查最终PPTX。
- 退出1时读取`diagnostics`中的错误码、`diagnostic.offset`及`detail`，根据原始文件修正并运行同一命令重检。每次源码改动后`sourceSha256`会变化，旧检查不能证明新稿。
- `invalid closing tag`必须核对实际关闭标签；截断围栏须补齐源稿，不能只补结尾伪称内容完整。每次最多两轮有针对性的源码纠正；仍失败时保留源文件并说明具体原因，不无限循环或发起隐藏的付费调用。
- 检查器缺失、Node不可用、执行未授权或超时，分别如实说明；不得伪造检查结果或改用你猜测的工具名。当前没有执行能力时只提交源稿，明确未经预检，不能声称质量通过。
- 不要在 `source-valid` 后结束回复：预检成功仍没有PPTX。继续用同一现有执行工具、同一任务工作区运行实际生成命令；不要加不存在的`--source`参数，不要自行寻找Electron路径或修改运行时配置：

```text
node "<this-skill-dir>/scripts/generate.cjs" "九月经营简报.slidegen"
```

生成使用随包Electron与已有PptxGenJS，不调用收费模型，不安装依赖。只读取已授权工作区的源稿和已有图片；命令不会替你编写内容。

⚠️ **PowerShell 形状（2026-10-03 真机事故，别重演）**：优先直接用上面那行 `node "..."` 命令。
只有在 `node` 确实不在 PATH、改用**带引号的绝对路径**（如随包运行时 node）时，PowerShell 里
**必须**写调用运算符 `&`：

```text
& "C:\...\node.exe" "<this-skill-dir>/scripts/generate.cjs" "九月经营简报.slidegen"
```

漏掉 `&` 得到的是 `术语 "..." 不会被识别为 cmdlet` 这类**shell 级错误**——它**没有**生成器的
JSON 报告，会被本轮的产出确认整体判为「无法确认」，从而**暂停自动交付**（即使文件其实已生成、
已入库）。也就是说：命令形状写错一次，就可能让一轮已经成功的生成无法作为成果呈现。
不要靠猜：先 `Get-Command node` 确认；用绝对路径时就照上面的 `&` 形状逐字写。

| 实际返回                                                                              | 本轮下一步                                                                                                                                                                                                                                             |
| ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 退出0、`status:file-generated`、`fileCreated:true`、`receiptStatus:ready`             | 核对返回的`fileName`、`pages`、`bytes`、`sourceSha256`和`outputSha256`，用现有文件工具确认实际 `.pptx` 文件存在、可读；读取该版本的`warnings`与`layoutReview`。保留原始完整工具结果及`receiptFile`，客户端收尾据此核验并登记，不能用口头成功替代凭据。 |
| 工具返回仍运行及实际会话标识                                                          | 用当前实际提供的`process`工具、`action:poll`和原`sessionId`继续等待同一进程终态。不要另开生成命令，不要把调用工具的0秒当生成耗时。没有轮询能力就说明尚未确认，不宣称完成。                                                                             |
| 明确失败且`fileCreated:false`                                                         | 读取实际`diagnostics`；源码错误按位置修正。运行时缺失或不可用如实报告，不要让用户安装插件，也不猜工具名。没有证据证明问题已修复时不重复执行。                                                                                                          |
| `output-unconfirmed`、`fileCreated:null`、`receiptStatus:unavailable`、超时或结果截断 | 文件可能已生成，状态或凭据尚未确认；不得再次执行生成命令。保留源稿和已有文件，用现有工具核对真实状态；说明未确认的环节，不说文件不存在或一定会出现。                                                                                                   |

`artifactIndexed:false`表示生成命令尚未写入产物库，不能据此说已进入产物；右侧登记和打开入口以客户端实际结果为准。`visualReview:not-performed`表示没有进行最终Office视觉检查。`layoutReview:no-known-warnings`仅表示当前自动检查未发现已知问题，不能把零告警说成视觉验收通过。

对已确认生成版本的诊断，按具体页码、错误码和元素修改源码，保持章节、标题、正文与页脚完整。源码和版式纠正合计最多两轮，不无限重试；没有具体问题就不再生成。已生成版本的源文件及PPTX都保留，纠正稿另存明确的`九月经营简报-v2.slidegen`，预检后生成该新版本，避免覆盖旧源导致旧凭据失效。每个版本仍是一份完整源码，不能把未合并片段交付成多份PPT。最终回复明确最新版真实文件名；旧版警告不得说成新版检查结果。达到上限仍有问题时，交付真实可用文件并列明未解决的具体页，不说质量通过。仅在结果已确认时才能走纠正，未知状态不能借“修质量”重复生成。

本轮所有待收集源稿累计最多200页，保留的修订版也计入；不是每版都能额外获得200页预算。达到累计预算时停止继续出版本，保留真实结果并说明限制，不隐瞒旧版或删用户章节来规避。

引用图片也属于已生成版本，连同源稿、PPTX和隐藏凭据一起保留；不得覆盖或删除旧图片。换图先另存为例如`assets/chart-v2.png`，让新版源码引用新文件名，旧稿仍引用旧图片。只保留旧源稿而修改同名图片，会使旧版资源SHA和凭据失效，不能继续说旧版已核验。

## ⭐ 先保覆盖，再写紧凑

长材料不能直接压成「极简三页」。写版面前先在心里列一份**覆盖大纲**，再一页页实现：

- **保留用户命名的章节**：用户给出的章节名、阶段名、案例名和必须覆盖项都要在大纲里有对应页，不得擅自合并或改名后丢失。
- **页数跟着内容走**：不要固定三页，也不要为了显得“极简”而删掉用户要的章节。一个观点放不下就拆页。
- **交付前对账**：逐项对照覆盖大纲，确认每个命名章节都已进入某一页，封面和尾页不算内容覆盖。

源码越短，排版越快、越不容易出问题。默认按紧凑写法，**不要**写讲稿式的长段落：

- **一页只说一页的事**：标题 + 三到六条要点，每条一两行就够。成段的讲稿留给备注或另开一份文档。
- **CSS 别重复**：能写在 `<Slide>` 上就别每页复制一遍；同样的字号 / 颜色 / 间距**抽成一处**，
  不要每个元素都内联写满。重复的样式是源码里最占体积、也最容易写错的部分。
- **有重点地设计**：每页用一到两个大数字、色块、分栏或图片形成视觉重心；避免十几个无信息作用的装饰块，也不要把每页做成只有几行小字的空白页。
- **单页文字控制住**：一页塞进几百字，投影出来没人看得清，而且很容易溢出。

> 内容真的很多（一份完整课件的讲稿式内容）时：先依覆盖大纲拆出足够页数，
> 再把每页的讲稿收成可展示的要点；不要删掉整个章节来换取“紧凑”。

## 页标题、页脚和可读性

- 每张内容页写明非空主标题；副标题不代替主标题。`PageTitle` 这类自定义组件必须传正文，不能只传 `sub` 后自闭合。封面、尾页也要有明确主题。
- 1280×720画布默认留出底部80px给页脚，正文卡片和文字在640px之前结束。页脚是独立区域；把页脚画在卡片上面仍然是区域冲突。放不下先拆页或调整正文结构，不能删用户必含信息或把字号缩到不可读。
- 深浅背景分开配文字色。小字号正文与页脚优先采用至少4.5:1的对比，大字号至少3:1；深色尾页不要复用浅色页的灰色页脚。透明色要按实际底色检查，不能把未知图片或渐变当作已验证。
- CSS字号以px计，导出PPTX时乘0.75转换成pt：24px对应18pt，不是24pt。商务稿正文用24–32px（18–24pt），主标题48–64px（36–48pt），辅助信息20–24px（15–18pt）。小字号不能承担关键正文。先用目标电脑可用字体，中文优先Microsoft YaHei。
- 短标题、说明与两三行正文可用 `textWrap: 'balance'`，由现有 Chromium 平衡断行，避免末行仅剩一个中文字。普通横排、左到右的单层纯文字会把已核对的浏览器行保留为可编辑PPT换行，不让Office重新贪心折行；嵌套文字、预格式化空白、竖排和RTL不保证保留平衡。不要对所有长段落套用，也不能靠缩字解决孤行；最终仍检查目标软件的字号、换行和安全区。
- 流程图每个箭头都应有对应的下一步或交付项；引用不能代替用户要求的结论。资料里缺少事实或数字时说明缺项，不自行编造。
- “节省80%时间”“提升某个百分比”必须来自用户资料或可核验来源，并保留口径；没有来源就写具体工作用途，不生成漂亮但无依据的绩效数字。能力介绍也不能把未接通的工具或未经实测的效果写成保证。
- 对话中出现页脚侵卡、低对比、越界或遮挡提示时，按具体页码修改源文件，另存新版本。旧可编辑PPTX仍然保留；只有实际生成、检查和右侧产物结果能说明交付状态，不能把无告警说成视觉必定合格。

## 怎么写

文件**里面**放**一个**围栏代码块，语言标记是小写 `slidegen`，内容是 **JSX 版面源码**：

````
```slidegen
// title: 九月经营简报
<Slide style={{ width: 1280, height: 720, background: '#FFFFFF', position: 'relative' }}>
  <Text style={{ position: 'absolute', left: 80, top: 60, width: 900, fontSize: 40, fontWeight: 'bold', color: '#100D13' }}>
    九月经营简报
  </Text>
</Slide>
```
````

**第一行必须是 `// title: 文件名`** —— 它是这份文件的**名字**，漏了整份会被拒。
一个围栏里可以并列**多个 `<Slide>`**，那就是多页（最多 200 页）。

## 四个内置标签

| 标签    | 是什么       | 说明                                                               |
| ------- | ------------ | ------------------------------------------------------------------ |
| `Slide` | 一页（画布） | **必须是 1280×720**，且要有 `background`                           |
| `Box`   | 容器         | **自动是 flex 容器**，用 `flexDirection` / `gap` / `alignItems` 排 |
| `Text`  | 一段文字     | 直接写内容，或 `{表达式}`                                          |
| `Image` | 图片         | `src="assets/xxx.png"` —— **只能引用工作区里已有的图**             |

内置元素只有上面四种；HTML 标签（含 `div`、`span`、`h1`）不支持。
可以使用**已声明的大写函数组件**，例如 `Footer`、`ItemCard`，最终必须返回这些内置元素。
没有声明就使用 `<Footer />` 会报未定义错误，不会被当作新内置元素。

**文字必须放在 `<Text>文字</Text>` 内**，表达式产生的文字或数字也一样。
`<Text ... />` 是空元素，后面的文字不属于它；不要写 `<Text ... />标签`，
应写 `<Text ...>标签</Text>`。不要把裸文字直接放在 `Slide` 或 `Box` 里。
开闭标签名字必须一致，不能省略闭合标签。客户端不会猜测文字该归哪个元素。
结构错误会给出 `dsl-close-mismatch`、`dsl-stray-close` 或 `dsl-text-outside-text` 等错误码；
`@数字` 是围栏内源码（从 `// title:` 开始）的零基字符偏移，中文按一个 UTF-16 单元计算。

## 样式就写 CSS（用 JS 对象的样子）

`style={{ 属性: 值 }}`，属性用驼峰（`fontSize`、`flexDirection`、`borderRadius`）。

- 数值默认是 px（`width: 548` → 548px）；`fontWeight` 和比例形式的 `lineHeight` 不带单位。
- 颜色优先写不透明的 `'#RRGGBB'`。
- **不支持完整 CSS**：浏览器负责量位置，PPTX 转换器只输出下表中支持的可编辑元素。浏览器能显示不等于 PPTX 能保留。

| 类别         | 可用范围与边界                                                                                                                                                                           |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 布局         | `position: 'absolute'`、`left/top`、宽高、flex、`gap`、`padding`；最后转成元素的实际坐标                                                                                                 |
| 文字         | `fontFamily`、`fontSize`、字重、斜体、明确的 `lineHeight`、颜色、左中右对齐、`letterSpacing`；字体须在目标电脑可用，不会嵌入字体                                                         |
| 色块         | 纯色或 `rgba()` 半透明背景、统一边框、圆角矩形；有边框的 Box 同时设置非全透明背景。文字和边框的 `rgba()` 透明度也会保留                                                                  |
| 图片         | 工作区中已有图片，按元素矩形输出；不承诺圆角裁剪或完整 `objectFit`/`objectPosition` 行为                                                                                                 |
| 渐变         | 仅简单线性渐变与明确百分比色标；渐变文字为逐字取色近似，不是任意 CSS 背景效果。关键文字优先用实色                                                                                        |
| 不支持的效果 | 整组 `opacity`、半透明渐变色标、`boxShadow`、`textShadow`、`backdropFilter`、旋转/倾斜 `transform`、SVG 标签、复杂遮罩与裁剪不能保证按浏览器外观导出，请改成实色、分栏和图片等支持的表达 |

不要靠阴影、半透明或毛玻璃承担内容层级。用支持的字号、颜色、留白和构图表达，不能把缺失效果说成已实现。

## 可以写 JavaScript

支持顶层 `const` / `let` / `function`，变量与函数按 JavaScript 作用域和执行顺序生效。
配色、间距可以抽成对象，重复布局可以抽成大写函数组件，不必复制内联样式。
**顶层表达式**返回的 `Slide`（或 `Slide` 数组）会按顺序收集成页面；
变量声明和组件声明本身不是页面，声明后要在顶层使用。

```jsx
const C = { background: '#FBFBFD', muted: '#4A4356' };
const Footer = ({ label }) => <Text style={{ fontSize: 24, color: C.muted }}>{label}</Text>;
<Slide style={{ width: 1280, height: 720, background: C.background }}>
  <Footer label="九月经营简报" />
</Slide>;
```

这不是完整 React/浏览器程序：不支持导入模块、DOM、网络、`process`、`require`，
禁止 `eval` / `Function` 动态编译；整份同步求值与序列化最多 2 秒。
不要使用异步代码产出页面；组件必须返回内置元素。未知变量会保留错误原因，不能靠省略内容绕过。

里面的 `{}` 是**真的 JS**，所以**列表用 `.map()` 展开**，不要手抄 N 遍：

````
```slidegen
// title: 三阶段落地节奏
<Slide style={{ width: 1280, height: 720, background: '#FBFBFD', position: 'relative' }}>
  <Box style={{ position: 'absolute', left: 80, top: 150, width: 1120, flexDirection: 'row', gap: 20 }}>
    {[
      ['Phase 01', '0 - 1 个月', '启动筑基期'],
      ['Phase 02', '1 - 2 个月', '现金流爬坡期'],
      ['Phase 03', '2 - 3 个月', '全域盈利期'],
    ].map((it, i) => (
      <Box key={i} style={{ width: 360, flexDirection: 'column', gap: 10, padding: '20px', borderRadius: 14, background: '#FFFFFF', border: '1px solid #ECE9F0' }}>
        <Text style={{ fontSize: 24, color: '#7A1CA8', fontWeight: 600 }}>{it[0]}</Text>
        <Text style={{ fontSize: 30, fontWeight: 'bold', color: '#100D13' }}>{it[1]}</Text>
        <Text style={{ fontSize: 28, color: '#4A4356' }}>{it[2]}</Text>
      </Box>
    ))}
  </Box>
</Slide>
```
````

## 页脚与正文分区

页脚说明和页码放进**同一个横向 flex 容器**：说明在左，设 `flex: 1, minWidth: 0`；页码在右，设 `flexShrink: 0`，中间留出 `gap`。
**两段文字都要保留**，不要把它们分别绝对定位到同一个 `left` / `bottom`；共享坐标会让说明盖住页码。
页脚文字用与背景有足够对比的**不透明实色**，不要靠低透明度制造层级。

先为页脚预留区域，再排正文。下面这份完整示例中，正文区域到 `y = 620` 结束，页脚占 `y = 660–692`；
**正文不得进入页脚区域**。放不下就拆页，不要缩小字号硬塞，也不要截断或删掉页脚文字。

````
```slidegen
// title: 正文与页脚分区示例
const Footer = ({ note, num, total }) => (
  <Box style={{ position: 'absolute', left: 80, bottom: 28, width: 1120, height: 32, flexDirection: 'row', alignItems: 'center', gap: 24 }}>
    <Text style={{ flex: 1, minWidth: 0, fontSize: 24, lineHeight: 1.25, color: '#4A4356' }}>{note}</Text>
    <Text style={{ flexShrink: 0, fontSize: 24, lineHeight: 1.25, color: '#4A4356' }}>{num} / {total}</Text>
  </Box>
);
<Slide style={{ width: 1280, height: 720, background: '#FBFBFD', position: 'relative' }}>
  <Box style={{ position: 'absolute', left: 80, top: 64, width: 1120, height: 556, flexDirection: 'column', gap: 32 }}>
    <Text style={{ fontSize: 48, lineHeight: 1.2, fontWeight: 'bold', color: '#100D13' }}>先留出页脚，再安排正文</Text>
    <Text style={{ fontSize: 28, lineHeight: 1.5, color: '#4A4356' }}>正文只放本页结论与证据；更多内容拆到下一页。</Text>
    <Text style={{ fontSize: 28, lineHeight: 1.5, color: '#4A4356' }}>来源说明与页码在底部各占一侧，保持完整可读。</Text>
  </Box>
  <Footer note="来源：九月经营复盘 · 内部讨论稿" num={1} total={1} />
</Slide>
```
````

## 版式纪律（一套视觉系统，不是一个死模板）

所有页保持 1280×720、字号层级、主色和页脚规则一致，但**不要每页都用同一种三卡片布局**。
根据内容选用并交替这些版式：

- **封面 / 章节页**：大标题 + 一句结论，留出足够空白。
- **核心观点页**：一个大结论 + 二到四个证据块。
- **对比 / 流程 / 时间线页**：用左右分栏、横向阶段或连线，不要强塞进三张相同卡片。
- **数据 / 案例页**：大数字、重点表格或案例前后对照，视觉重心跟着数据走。

**左右留白建议 72–80px**。标题、主色、对齐和页脚统一；内容构图随信息类型变化。

**出稿前逐页自检**：在源码注释中列出每页的「页码、核心结论、版式骨架、视觉重心」，
例如封面 → 大结论与证据 → 左右对比 → 时间线 → 大数字 → 案例前后对照 → 行动收束。
骨架按实际信息位置与层级判断，换颜色、标题或卡片文案不算换骨架。
**禁止连续 3 页及以上使用同一种骨架**；发现后先重排，再交付。
7 页短稿优先让相邻页骨架不同，末页回答封面提出的问题或兑现封面的核心结论。
统一字号、颜色、页脚即可保持视觉系统一致，不需要靠重复三卡片来统一。

反例：用户反馈「ppt质量不够好」，助手自查为「版式太平面了，卡片的重复度也高」。
把三卡片换一套颜色后继续复制并没有解决问题；应根据内容改成对比、流程、数据或案例构图。
这份自检不能代替真实 `.pptx` 交付：仍须写完整 `.slidegen` 文件，客户端成功生成后才有产物。

**几条让页面不土的规矩**：

- **标题写结论**，不写"关于……的说明"
- **一页只讲一件事**；装不下就**拆成两页**，别把字缩小硬塞
- 用**大数字**、色块、留白做视觉锚点；**不要用 emoji**、不要用花哨插画
- 正文优先24–32px、卡片标题32–40px、主标题48–64px；页脚20–24px。层级靠字号差；放不下先拆页，不要缩成难读的小字

## 按本轮结果与客户端反馈修正

**❌ 整份没生成**（提示里会说原因）：

- `// title:` 漏了 / 标签写错 / 版面语法错 / 表达式算不出来
- 看到提示就按错误码与位置修改原文件；重试后仍须核实生成结果，不能保证重试一次必定成功

本轮执行命令时直接读取实际诊断，不要等用户下一次发送才查看。无执行能力时的客户端失败会保留在会话系统提示里，并随用户下一次发送作为诊断背景提供给你。
用户要求继续或修复时，按错误码与位置修改源稿并重新交付；失败本身不触发自动重试，
也不能把“稍后出现在产物里”当成成功证据。

**⚠️ 生成了，但有几处要调整**（命令生成不代表已经登记到产物）：

- **内容超出画面** ⇒ 那一块放映时看不到。改法：**拆页**、缩内容、或调 `top` / `height`
- **文字被别的元素盖住** ⇒ 用户看不到那句话。改法：挪开盖住它的那块

⚠️ 这两种都**不会**让文件消失 —— 但用户会看到一句提示。**主动按上面两条自查一遍**
（内容别超出 720 高、`position:'absolute'` 的块之间别重叠），比事后被提示更省事。

## ⭐ 修改已有版面文件的编辑纪律（2026-10-06 真机教训）

用户要求改某一页时，用**文件编辑工具改的就是那份 `.slidegen` 文件本体**。按下面三条做，
否则会出现 `Could not find edits[n]`（引用的旧文本与当前版本不一致）或
`Found 2 occurrences of edits[n]`（锚点不唯一）这类失败：

1. **编辑前先读回当前文件**：按**你读到的原文**构造编辑文本。不要凭记忆或上一轮印象写 oldText ——
   文件可能已被你或用户改过，过期锚点必然找不到。
2. **锚点要唯一、带足上下文**：只拿一两个词去找会命中多处；带上整行（或相邻一两行），
   保证这段文本在整份文件里只出现一次。多条编辑互不重叠。
3. **同一处连续 2 次编辑失败 ⇒ 停止局部修补，改为整版重写**：不要再试第三次。
   读全文 → 写出**完整的新修正稿**（同名整体覆盖，或另存 `-v2.slidegen`），
   然后照常走本文档的**预检 → 生成 → 核收据**流程。文件保留与版本纪律同上一节。

> 为什么：真机上改稿阶段因过期/重复锚点连续消耗了二十多次工具调用，
> 事后还留下"结果未确认"的中间态。**两次不成，整版重写**是最短的路。

## 说给用户的话

有执行能力时本轮生成并读取结果；没有执行能力时，客户端在收尾尝试生成，不能保证成功：

- ✅ 源文件写入成功后可以说：「版面源文件已提交生成，共 N 页；请以右侧『产物』的实际结果为准，失败会显示原因。」
- ✅ 只有确认实际 `.pptx` 文件存在、可读并收到成功生成结果后，才可以说「PPTX 已生成」，并给出真实文件名、页数及已知问题。只有收到成功的产物结果后，才能说已进入右侧产物或给出对应打开入口。
- ❌ 不要预告「稍后一定出现」「点开就是 PPTX」或「文件在你桌面上」来代替生成结果。写文件成功、模型回复结束和 PPTX 生成成功是三件不同的事。
- ✅ 用户要改哪一页，**你改那一页的版面重发一份**即可（他能看到全文，改起来是直达的）。

## 什么时候不要用它

- 用户要的是**随手草稿**、不在乎版式 ⇒ 用「文档生成」，快得多。
- 用户要**填一份现成的设计模板** ⇒ 用「商务演示（模板版）」。
- 用户要 **Word / Excel / PDF** ⇒ 那是「文档生成」的事。
- 用户要**网页** ⇒ 那是「网页交付」的事。
- 用户要**图片**（照片、插画）⇒ 做不到，别拿 `Image` 顶替 —— 它只能引用工作区里**已经存在**的图。
