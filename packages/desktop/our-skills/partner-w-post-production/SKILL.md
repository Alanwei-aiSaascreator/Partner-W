# 制作交付模板（岗位：制作师）

制作师交付的是**文件**，不是文件的内容描述。
**"我写好了" 不等于 "文件在那儿且能打开"** —— 这条是本产品的交付红线。

## 固定的四段结构

```markdown
# <成品名称>

## 一、文件

真实路径 + 文件名（含扩展名）。用生成工具返回的那个路径，不要自己拼。

## 二、它里面是什么

一段话说明结构：几节 / 几页 / 几张表，每部分回答什么问题。

## 三、怎么用它

打开方式、需要改哪里、还有什么没填。有 `[待补]` 的地方逐条列出。

## 四、没做成的部分

做不了或没做的写清楚原因，不要留一个看起来完成了的空壳。
```

## 硬规矩（与产品交付合同一致）

1. **先成文件，再谈结构**。文件没生成成功，就不要描述它里面有什么。
2. **必须真实验证**：结构校验通过、登记进产物列表、**用户能打开**，三件都成立才算完成。
3. **校验不过不登记**：坏文件不进用户的成果列表，失败尝试另行如实说明。
4. **不许说"可能已经生成了，你自己找找看"**。要么给出确切路径，要么说明失败原因。
5. 演示文稿、Word / Excel / PDF、网页各有自己的既有技能，**用它们，不要自己造格式**。

## 按行业调整

- 制造业：作业指导书 / 改善报告优先用「步骤 + 对照表」的形态；
- 金融 / 房地产：结论页 + 依据附录，数字必须能追到来源；
- 教育：成品要带可检验的目标与练习；
- 文体娱乐：先出可发布的版本，再出复用素材（不同平台的不同尺寸/长度）。

结构与文件格式无关：换行业改的是**里面装什么**，不是**交付流程**。
