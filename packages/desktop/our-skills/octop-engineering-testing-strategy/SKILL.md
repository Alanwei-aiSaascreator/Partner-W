# 测试策略设计

## 先定成功标准

读取需求、真实调用链与已有测试，明确关键业务路径、错误处理、边界、安全边界和数据完整性。列出测试环境、依赖、数据与允许执行的范围；测试计划不能代替实际测试结果。

## 测试金字塔

- 单元测试：数量较多、快速、聚焦业务逻辑。
- 集成测试：数量适中，核实层与层及真实依赖边界。
- E2E测试：数量较少、较慢，以少数关键用户路径获得整体信心。
  按风险调整比例，不追求固定数量或虚高覆盖率。

## 按组件选择

| 组件     | 测试策略                                            |
| -------- | --------------------------------------------------- |
| API端点  | 业务逻辑单元测试、HTTP层集成、消费者契约测试        |
| 数据管道 | 输入校验、转换正确性、幂等与重复/乱序/失败恢复      |
| 前端     | 组件、交互、视觉回归、可访问性、关键端到端流程      |
| 基础设施 | 冒烟、负载和故障/混沌测试建议；环境与影响需独立授权 |

## 覆盖与取舍

优先业务关键路径、错误传播、空值与极限输入、权限隔离、资源清理和数据完整性。
通常不为琐碎getter/setter、框架内部代码或一次性低风险脚本堆测试；若有具体风险则按风险补测。
检查负例是否真的到达目标分支，避免被其他门槛短路；断言用户可见结果或正确依赖边界，不复制实现算一次相同结果。

## 输出测试计划

按区域列：验收条件 / 测试类型 / 环境与前置条件 / 正例与反例 / 预期结果 / 覆盖目标 / 当前缺口 / 执行成本。
给出代表性输入与断言，区分mock、真实文件/依赖、真实UI证据。执行时先看失败是否因目标行为，再验证修复；报告真实命令、输出与NOT RUN。负载/故障注入、付费调用和生产测试只列建议，不默认执行。

## 执行与交付边界

不改变现有权限、工具审批、工作区和文件产物合同。技能是工作流程，不是额外工具、连接或执行授权；只使用当前实际可用且在任务授权范围内的工具与资料。没有连接器时使用本地或用户提供的材料，不宣称平台已接通。
发布、部署、生产处置与对外通知仅输出建议清单或草稿；本技能不默许执行，也不自动创建工单、通知他人或后台监控。实际执行须由获授权的流程另行处理。
需要文件交付时沿现有能力生成并写入允许位置，校验 → 登记 artifact → 用户能打开 才算成功；未保存的文本称草稿，未跑的验证标 NOT RUN，不虚报完成。
