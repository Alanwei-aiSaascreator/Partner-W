# 结构化故障调试

## 收集最小事实

记录预期与实际行为、完整原始错误、精确复现步骤、首次发生时间、影响范围、最近部署/配置/依赖变化。日志和截图可作证据，但不要改写原始错误；生产与测试差异、大负载条件单独列明。

## 四步流程

1. **复现**：建立稳定的失败输入与可观察信号，说明何时发生、影响谁。不能复现时记录环境和缺失条件，不宣布根因。
2. **隔离**：缩小组件、服务或代码路径；对照最近变更与日志，区分时间相关和因果关系。
3. **诊断**：列出少量可证伪假设，逐一设计最小实验、预期结果和排除标准；追踪到真正根因而非仅消除症状。
4. **修复建议**：解释最小修复、可能副作用和边界；先设计能击穿旧行为的失败测试，再由获授权的实施者修复并复跑回归。不要盲目改多个变量或无限重试同一操作。

## 输出调试报告

- 复现：预期、实际、步骤、环境、样本和日志位置。
- 诊断：假设→实验→真实观察→排除或支持；明确仍不确定的点。
- 根因：解释输入如何经过代码路径导致失败，证据不足则标“待定”。
- 修复：建议的代码或配置变化及原因，影响范围与回退条件。
- 防回归：新增测试、边界用例、监测信号，实际执行结果与 NOT RUN。

## 可选证据

可读取已授权的监控日志、错误率、部署时间线、提交和已知问题；不可访问则列为缺证据。生产查询、处置、工单创建等不因本技能自动获得权限；先产出建议与工单草稿。

## 执行与交付边界

不改变现有权限、工具审批、工作区和文件产物合同。技能是工作流程，不是额外工具、连接或执行授权；只使用当前实际可用且在任务授权范围内的工具与资料。没有连接器时使用本地或用户提供的材料，不宣称平台已接通。
发布、部署、生产处置与对外通知仅输出建议清单或草稿；本技能不默许执行，也不自动创建工单、通知他人或后台监控。实际执行须由获授权的流程另行处理。
需要文件交付时沿现有能力生成并写入允许位置，校验 → 登记 artifact → 用户能打开 才算成功；未保存的文本称草稿，未跑的验证标 NOT RUN，不虚报完成。
