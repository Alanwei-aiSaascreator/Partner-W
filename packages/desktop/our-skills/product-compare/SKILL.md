# 方案对比

对比的价值在于**把选择变简单**，不在于把资料堆齐。
一份好的对比表看完之后，用户能说出一句"那我选 X，因为……"。

## 步骤

### 1. 先定"选这个是为了什么"

问（或从材料里读出）**决策目标**：是要便宜？要省事？要能长期用？要有面子？
目标不定，对比表就只能按价格排序 —— 那不是对比，那是列表。

⚠️ 目标不同的方案**不要放在同一张表里**（比如把"买断"和"按月租"混在一张表按价格排），
那样得出的结论一定是错的。分开比，或者换算成同一口径再比（**并说明换算方式**）。

### 2. 定维度（5–7 个，别再多了）

必须包含：**总花费**、**关键能力**、**限制/门槛**、**风险**。
每个方案不一定都有数据 ⇒ 缺的格子写「未知」，**不要**留空、**不要**猜。

### 3. 出表

```markdown
| 维度      | 方案 A | 方案 B | 方案 C |
| --------- | ------ | ------ | ------ |
| 总花费    |        |        |        |
| 关键能力  |        |        |        |
| 限制/门槛 |        |        |        |
| 风险      |        |        |        |
```

⚠️ 每格尽量写**事实**（"含 3 台设备"），不写评价（"性价比高"）。
评价统一放到最后一节，且必须说明**依据哪个维度**。

### 4. 给出差异，而不只是并列

表下面写一段 **「真正的差别在哪」**：把**只有一两个方案不同**的维度挑出来。
往往三四个维度里只有一个真正决定选择，其余是噪音。

### 5. 有条件的推荐

```markdown
**如果你 <条件> ⇒ 选 <方案>**，因为 <依据>。
**如果你 <另一个条件> ⇒ 选 <另一个>**。
```

⚠️ **不要给无条件推荐**。条件写不出来，说明你还缺信息 ——
那就把"缺什么"列出来，而不是硬选一个。

## 硬规则

- **资料缺口单列一节**，写清"要判断 A 和 B 谁便宜，还差 \_\_\_\_"。
  缺口不写出来，用户会以为表里的信息就是全部。
- **不做未经说明的换算**。年付转月付、含税转不含税、外币转人民币，
  只要做了就必须写出汇率/口径与时点。
- **不替用户加权**。不要把"价格 40% + 能力 60%"算成一个总分 ——
  权重是用户的偏好，不是你能定的。要算就先问，并把权重写在结论上面。
- **不隐藏反面**。查到某方案的问题（差评、限制、涨价史）就照实写，
  哪怕只有一个来源 ⇒ 写「据 <来源>（单一来源，未经核实）」。
