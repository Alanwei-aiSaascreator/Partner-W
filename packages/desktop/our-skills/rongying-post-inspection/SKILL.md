# 质检交付模板（岗位：质检师）

质检的产出是**问题清单**，不是"我检查过了"。
没有查到问题时，要说清**你是怎么查的** —— 否则"没问题"这句话没有信息量。

## 固定的四段结构

```markdown
# <被检查的东西> 质检结果

## 一、结论
通过 / 有问题需修改 / 无法判断（要说明缺什么才能判断）。

## 二、逐条核对
| 原始要求 | 实际情况 | 判定 | 证据 |
|---|---|---|---|
| 用户原话 / 文档里的那一条 | 交付物里对应的是什么 | 符合 / 部分符合 / 不符合 | 文件路径 + 行号 / 页码 / 截图位置 |

## 三、问题与改法
按严重度排序，每条写：
- **问题**：哪里、什么现象
- **为什么算问题**：会带来什么后果
- **最小改法**：改哪里、改成什么
- **怎么验证改好了**：一个能复现的检查动作

## 四、没查到 / 没验证的
查不了、看不到、没条件验证的，逐条列出并写明原因。
```

## 硬规矩

1. **"测过了" ≠ "没问题"**：测试通过只说明测到的部分通过，没测到的照旧是未知。
2. **不要只挑小毛病**。严重度高的先写；全是格式问题的清单会让用户以为没问题。
3. **每条问题都要有证据**。说不出"在哪看到的"，就不算发现。
4. **不许为了让报告好看而漏报**。宁可写"本次只检查了 X，没检查 Y"。
5. **不为了反对而反对**：确实做对的地方，在第一段简短说明"已核对无误"即可。

## 按行业调整

- 制造业 / 建筑：优先查**安全与合规**项，这些不通过就不必往下看；
- 金融 / 房地产：优先查**数字口径与来源**；
- 教育：优先查**目标是否可检验、练习与目标是否对得上**；
- 文体娱乐：优先查**事实性表述与版权/署名**。
