# 技术文档编写

## 先选读者和用途

确认读者、目标任务、适用版本、信息来源及文档落点。先读已有文档和相关代码，减少重复真源；旧内容未验证时标日期与待核项。
先呈现对读者最有用的信息，再解释背景。用小型代码示例、命令示例、图或截图帮助完成具体任务；区分示例与已执行结果。

## 文档类型与必需内容

| 类型     | 必需内容                                                                                           |
| -------- | -------------------------------------------------------------------------------------------------- |
| README   | 项目是什么、为什么存在、快速开始、配置和使用、参与方式；五分钟首次成功作为目标，未经实测不承诺耗时 |
| API      | 端点、请求/响应示例、认证、错误码、限流、分页、SDK示例；不编造代码中不存在的接口                   |
| Runbook  | 何时使用、前置条件和权限、分步建议、验证信号、回滚步骤、升级联络路径                               |
| 架构文档 | 背景与目标、总体结构图、关键决策与权衡、数据流、集成点                                             |
| 入职指南 | 环境准备、关键系统关系、常见任务演练、各类问题向谁咨询                                             |

## 编写流程

1. 列出受众的问题与成功标准，按完成任务的顺序组织内容。
2. 对照真实代码、配置样例和既有来源，核实路径、参数、版本和链接。
3. 将 Runbook 的部署/生产修改步骤写成需获授权执行者确认的建议清单；示例命令不是执行授权。
4. 按授权范围验证可逆本地示例；无法验证时写明 NOT RUN、原因及验证办法。
5. 检查相对链接与资源可达性；引用现有真源而非复制易过时细节，列出维护人和更新触发条件。

## 交付

输出适合目标读者的完整草稿、适用版本、来源、核验结果和待确认项。陈旧文档要注明修订依据，不通过语言润色掩盖缺证据。需要保存文件时遵循下述既有文件产物合同。

## 执行与交付边界

不改变现有权限、工具审批、工作区和文件产物合同。技能是工作流程，不是额外工具、连接或执行授权；只使用当前实际可用且在任务授权范围内的工具与资料。没有连接器时使用本地或用户提供的材料，不宣称平台已接通。
发布、部署、生产处置与对外通知仅输出建议清单或草稿；本技能不默许执行，也不自动创建工单、通知他人或后台监控。实际执行须由获授权的流程另行处理。
需要文件交付时沿现有能力生成并写入允许位置，校验 → 登记 artifact → 用户能打开 才算成功；未保存的文本称草稿，未跑的验证标 NOT RUN，不虚报完成。
