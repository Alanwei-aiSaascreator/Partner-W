# 技术债盘点

## 先确定证据范围
读取本次获授权的代码、缺陷记录、失败测试、维护负担与业务目标。每项债务要指向具体证据，不把个人风格偏好当成技术债，也不因为“单体”就默认必须拆分。

## 分类
| 类型 | 例子 | 主要风险 |
|---|---|---|
| 代码债 | 重复逻辑、抽象不当、魔法数字 | 易出错、开发慢 |
| 架构债 | 已证实阻碍目标的服务边界或存储选择 | 扩展受限 |
| 测试债 | 缺集成测试、脆弱测试、关键行为未覆盖 | 回归流出 |
| 依赖债 | 过时或无人维护的依赖 | 安全与兼容风险 |
| 文档债 | 缺Runbook、过期README、口头知识 | 上手与维护困难 |
| 基础设施债 | 手工发布、无监控、缺基础设施配置管理 | 事故与恢复慢 |

## 排序方法
每项按1–5分填写：影响（拖慢团队程度）、风险（不处理的后果）、工作量（处理难度）。列出评分依据及不确定度。
优先级 = (影响 + 风险) × (6 - 工作量)
较低工作量提高排序得分；此分数是讨论辅助，明确的安全/业务阻断仍要优先，不靠公式遮蔽严重问题。

## 输出治理清单
事项 / 分类 / 文件或证据 / 业务理由 / 影响分 / 风险分 / 工作量分 / 优先级 / 依赖 / 建议负责人 / 验收点。
按可独立交付的小批次形成分阶段计划，使治理与功能开发并行；分别写近期止损、结构改善、长期维护。估算与事实分开，未授权不自动升级依赖、重构代码或创建远端工单。

## 执行与交付边界
不改变现有权限、工具审批、工作区和文件产物合同。技能是工作流程，不是额外工具、连接或执行授权；只使用当前实际可用且在任务授权范围内的工具与资料。没有连接器时使用本地或用户提供的材料，不宣称平台已接通。
发布、部署、生产处置与对外通知仅输出建议清单或草稿；本技能不默许执行，也不自动创建工单、通知他人或后台监控。实际执行须由获授权的流程另行处理。
需要文件交付时沿现有能力生成并写入允许位置，校验 → 登记 artifact → 用户能打开 才算成功；未保存的文本称草稿，未跑的验证标 NOT RUN，不虚报完成。
