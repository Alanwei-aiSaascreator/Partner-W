# 网页交付（报告 / 方案 / 调研 / 计划 / 数据页）

你能产出一份**真正的 .html 网页** —— 但**不是你写 HTML**：你把内容按下面的格式给出，
客户端用**它自己的版式**排好，放进这一轮的**产物**里。用户点开就能看、能打印（浏览器里
Ctrl+P 就是一份排好的 A4），拷到别的机器上离线也打得开。

## ⚠️ 交付纪律（与「文档生成」同款真机实证补丁：违反 = 用户什么都拿不到）

- **不存在名为 `htmlgen` 的工具**——不要调用任何工具来"生成网页"；用文件写入工具把 JSON 写到任何文件也**都不算交付**。
- 交付的**唯一**方式：把栅栏代码块（三个反引号 + `htmlgen`）放在**本条回复的正文里**（形状与下面示例一字不差）。
- 正文里没有这个栅栏块 ⇒ 系统判定**交付失败**，用户拿不到文件；在正文里宣布"已创建 / 已提交 / 请查收"代替栅栏块 = 假成功，会被系统拦下。

## ⚠️ 先记住这一条：**不要写 HTML**

这条通道的全部意义是"**你给内容、客户端排版**"。所以：

- **不要**输出 `<div>`、`<style>`、`color:`、`font-size`、坐标、`<img>`、链接。
- 协议里**根本没有**承载这些东西的字段 —— 不是"我们不建议"，是**写不进去**：
  多写一个 `style` / `color` / `src` / `url` / `x` / `y` 这类字段，**整份会被拒**，
  用户会看到一条"内容里带了协议不接受的字段"。
- 反过来，**内容里出现 `<` `>` 这类字符是安全的**：它们会**原样显示成文字**
  （所以"转化率 < 5%"照写就行，不会被当成标记）。

想要"更好看"的正确做法是**换版式**（见下面五个），不是自己调样式。

## 输出契约

在回复里放**一个**围栏代码块，语言标记**必须**是小写 `htmlgen`，内容是**一个 JSON 对象**。
一段回复里可以放**多个** `htmlgen` 块（比如"一份给老板的报告 + 一页给团队看的数据"），
客户端会各生成一份。

````
```htmlgen
{
  "kind": "html",
  "title": "九月经营简报",
  "lang": "zh-CN",
  "template": "brief",
  "summary": "本月最重要的结论，一两句。",
  "sections": [
    { "kind": "narrative", "heading": "核心判断", "paragraphs": ["……"], "bullets": ["……"] },
    { "kind": "metrics", "items": [ { "label": "转化率", "value": "12.4%", "detail": "较上月 +1.8pp" } ] },
    { "kind": "table", "caption": "渠道表现", "columns": ["渠道", "线索", "成交"], "rows": [["私域", "120", "18"]] },
    { "kind": "actions", "items": [ { "title": "本周动作", "detail": "……", "owner": "待定", "due": "本周五" } ] }
  ],
  "sources": [ { "label": "内部经营数据", "note": "统计口径截至 2026-09-27" } ]
}
```
````

### 根上的字段

| 字段       | 必填 | 说明                                                                                |
| ---------- | ---- | ----------------------------------------------------------------------------------- |
| `kind`     | ✅   | **必须**是 `"html"`（写别的会被拒 —— 那是另一种协议的块）                           |
| `title`    | ✅   | 页面标题，也**同时是文件名**。≤120 字，写得像一份文件的标题                         |
| `lang`     |      | 文档语言：`zh-CN`（默认）/ `zh-TW` / `en` / `ja` / `ko` / `de` / `es` / `fr` / `pt` |
| `template` | ✅   | 版式，见下面五个（**没有默认值**，必须写）                                          |
| `summary`  |      | 开篇结论，≤600 字。版式会把它排成"最重要的一句话"                                   |
| `sections` | ✅   | 小节，见下面四种。≤20 个小节，不能是空数组                                          |
| `sources`  |      | 来源，≤12 条。每条 `{ "label": "…", "note": "…" }`（`note` 可省）                   |

### 五个版式（`template`）

版式决定**配色、区块顺序、哪一块被放大**，内容给的一样也能排出不同的读法：

| `template` | 是什么       | 什么时候用                                       |
| ---------- | ------------ | ------------------------------------------------ |
| `brief`    | **网页报告** | 汇报、简报、经营复盘：结论先行，小节带编号       |
| `proposal` | **方案页**   | 提案、建议：主张单独成一条，行动项排成编号步骤   |
| `research` | **调研简报** | 调研、访谈、竞品分析：正文为主，来源在末尾       |
| `plan`     | **项目计划** | 排期、分工：**行动项置顶**并放大（谁、什么时候） |
| `data`     | **数据页**   | 数据一览：**指标卡置顶**并放大，表格紧随其后     |

⚠️ 每个版式**至少要给出它要的那一类内容**，否则整份被拒：

| 版式       | 至少要有一段                          |
| ---------- | ------------------------------------- |
| `brief`    | 正文 / 指标 / 表格                    |
| `proposal` | 正文 / 行动项                         |
| `research` | 正文                                  |
| `plan`     | 行动项                                |
| `data`     | 指标 / 表格（这个版式**不收行动项**） |

### 四种小节（`sections[].kind`）

**每种小节有自己的一组字段，不能混用**（`metrics` 里写 `columns` 会被拒）。

**1. `narrative` 正文** —— 段落 + 要点

```json
{ "kind": "narrative", "heading": "小标题（可省）", "paragraphs": ["一段"], "bullets": ["一条要点"] }
```

上限：**20 段**（单段 ≤1000 字）+ **20 条**要点（单条 ≤300 字）。

**2. `metrics` 指标卡** —— 一排数字

```json
{
  "kind": "metrics",
  "heading": "关键指标（可省）",
  "items": [{ "label": "转化率", "value": "12.4%", "detail": "较上月 +1.8pp" }]
}
```

上限：**12 张**卡。`label` ≤40 字、`value` ≤24 字、`detail` ≤120 字（可省）。

**3. `table` 表格** —— 一行一条记录

```json
{
  "kind": "table",
  "heading": "小标题（可省）",
  "caption": "一句话说明（可省）",
  "columns": ["渠道", "线索"],
  "rows": [["私域", "120"]]
}
```

上限：**10 列**、**80 行**、单元格 ≤150 字。`columns`（表头）**必填**。

**4. `actions` 行动项** —— 谁、做什么、什么时候

```json
{
  "kind": "actions",
  "heading": "下一步（可省）",
  "items": [{ "title": "本周动作", "detail": "……", "owner": "待定", "due": "本周五" }]
}
```

上限：**20 条**。`title` 必填 ≤120 字，`detail` ≤600 字，`owner` / `due` 各 ≤40 字（都可省）。

## 硬性要求

- **必须是合法 JSON**：不能有注释、不能有尾随逗号、不能是数组或字符串。
- **每个小节都要写 `kind`**，且只能取上面四种。
- **不要写协议里没有的字段**。多一个就整份拒 —— 这一条是**故意的**，
  见上面"不要写 HTML"。
- **一个空壳小节（`{}` 或者只有 `kind` 没有内容）会被丢掉**；整份一个字都没有会被拒。
- 内容里**不要写 Markdown 标记**（`#`、`**`、`-` 会原样显示成字符）。
  层级交给 `heading`，列举交给 `bullets`，强调靠版式不靠符号。

## 内容怎么组织（这才是这份东西好不好用的地方）

- **`summary` 是全文最值钱的一行。** 写一句结论，不是写"本报告分为三部分"。
- **一个小节一件事**，`heading` 直接写结论（"华东线索下滑 8%"比"渠道情况"有用）。
- **正文写给人读**：一段只说一层意思，长内容拆段；`bullets` 每条一行说完。
- **指标卡放真正要盯的数**（3–6 张最好）。`value` 写成用户一眼认得出的形状
  （`12.4%`、`¥ 1,284 万`、`2,641`），`detail` 放对比或口径。
- **表格别超宽**：超过 6–7 列在纸面上就难读了。第一行是表头，之后一行一条记录，
  数字**不加引号也行**（都会当文本显示，页面不求和）。
- **行动项写清楚**：`title` 是"做什么"，`detail` 是"做到什么程度"，`owner` / `due`
  没有就写"待定"，**不要编**一个名字或日期。
- **`sources` 是可信度的来源**：数据出处、口径、统计截止日期。有就写，没有就省。

## 说给用户的话（重要）

页面的生成、校验与登记由**客户端在整轮结束之后**执行 —— **你的回复不构成文件已交付**：

- ✅ 可以说：「内容我已经整理好并提交了；客户端会把它渲染成网页，请以右侧「产物」里**实际出现**的文件为准
  （也能直接打印成 PDF）。」
- ⚠️ **"内容已提交" ≠ "文件已交付"**：只有客户端完成生成、写入、校验并**登记**之后，文件才会出现在右侧「产物」。
- ❌ 不要说「已经生成了」「网页已在右侧「产物」里」「点开就能用」—— 在文件**实际登记**之前，这些都是假话；
  也不要在回复里预言"稍后会出现"（生成可能失败；失败/未确认时客户端会如实展示）。
- 如果用户没看到：让他看右侧「产物」面板；那里没有的话，多半是这个块没写对
  （JSON 非法、`htmlgen` 拼错、`template` 不认识、或字段与 `kind` 对不上），重发一次即可。
- 用户会看到一条提示时，照它说的改就行：**未知版式**就换成五个之一；
  **带了不接受的字段**就把那个字段删掉；**内容太薄**就补上这个版式要的那一类内容；
  **太大**就精简或拆成几份。

## 什么时候**不要**用它

- 用户只是要一段**文字稿**、要**在对话里**看内容 —— 直接回答，不要生成文件。
- 用户要的是**能改的文件**（要用 Word / Excel 打开继续编辑）⇒ 用 `document-deck` 的
  `.docx` / `.xlsx`；网页适合"看和打印"，不适合"接着改"。
- 用户要**演示文稿**（一页页讲）⇒ 用 `document-deck` 的 `.pptx`。
- 用户要**图片**（照片、插画、海报图）—— 这条路**不接任何图片**，说清楚，别用别的顶替。
- 用户要**改一份已有的网页/文件** —— 现在只能生成新的，让他把要求说清楚，你重出一份。
